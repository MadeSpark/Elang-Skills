## 1. 怎么用（默认：什么都不用做）

```
你的程序目录\
├── 你的程序.exe
├── node.dll            ← 只放这里（或按第 6 节指定位置）
├── MbKit146.dll         ← 首次运行时从模块资源里自动释放出来（763,904 B，释放后置「隐藏」）
└── ...（模块会自动判断是否需要用新版本覆盖）
```

```易语言
.版本 2

.子程序 _启动子程序, 整数型
    ' ★ 这里就是 DllMain（加载锁内）：只能做「登记 / 投递」这类轻活。
    WKE初始化 ()                     ' 安全：只登记，不 LoadLibrary、不 wkeInitialize（0 ms）
    返回 (0)

.子程序 _AppStart, 整数型, 公开   ' 宿主调用「启用插件」时才做重活
    .局部变量 失败原因, 文本型
    ' WKE设置node路径 (“D:\我的内核\chromium_2021”, 失败原因)   ' 可选，必须在首次碰内核前
    载入 (设置窗口, , 假)
    图片框1.置大小 (...)             ' 该线程随后就成为内核属主线程
    mb.绑定 (图片框1.取窗口句柄 ())
    mb.载入 (“https://example.com/”)
    返回 (0)
```

两条时序要点：

* **`_启动子程序`（DllMain）里只能调「初始化类」**：`WKE初始化` / `WKE设置node路径` /
  `WKE载入宿主库` / `WKE卸载`。它们都只登记，不碰 node.dll。
* **第一次 `绑定` / `载入` 会做一次 350 ms 左右的初始化**（加载 `MbKit146.dll` 或 `node.dll`，再 `wkeInitialize`），必须发生在**创建窗口/有消息循环的那个线程**上（框架的启用回调就是）。
  之后就都在 50 ms 级以内，页面开始渲染。

## 2. 公开命令

| 命令 | 返回 | 说明 |
|---|---|---|
| `WKE初始化 ()` | — | **非阻塞登记**：只保证「内核会在这条业务线程上被建起来」，不 LoadLibrary、不 wkeInitialize。DllMain 里可安全调用 |
| `WKE卸载 ()` | — | `wkeFinalize`（内核没起来时是无事可做；实测标志位不清，别拿它当「能否重来」的判据） |
| `WKE设置node路径 (路径, 失败原因, 强制使用node内核)` | 逻辑型 | 目录或 `node.dll` 完整文件名；留空=默认（宿主程序根目录）。**必须在首次碰内核前调**。第三参数**可空、缺省=假**：**假**=允许走 edgewebview（WebView2 Runtime 存在时默认就是它），**真**=强制 `node.dll`。同一路径重复调返回**真**（幂等，热重载/重复启用安全）；真换内核才返回假并写原因。**内核常驻、换内核只能重启宿主** —— 设计行为，不是故障 |
| `WKE取node路径 ()` | 文本型 | 内核实际使用的完整路径（**会触发内核查找/加载**） |
| `WKE宿主自检 ()` | 文本型 | 一行式诊断：内核启动状态、内核状态/路径、**内核属主模式**、缺失导出、加载期错误、编组与回调计数。**排查先看它** |
| `WKE载入宿主库 ()` | 逻辑型 | 手工把内嵌 `MbKit146.dll` 释放+预载（一般不用调） |
| `WKE等待内核就绪 (超时毫秒)` | 逻辑型 | ★ 属主直通下「等待」= **现在就在本线程把内核建起来**（阻塞但正确，本线程从此是属主）；K 模式才是带泵等待。**别在 DllMain 里调它** |
| `WKE取内核启动状态 ()` | 整数型 | ★ `0`未启动 / `1`已登记(等首个内核调用) / `2`已完成 / `3`失败 |
| `WKE全解绑 ()` | 整数型 | ★ **热重载契约**：解绑并销毁本模块登记的全部浏览框（内核保持已初始化）。插件 DLL 被卸载前调一次 |
| `WKE取等待统计 ()` | 文本型 | ★ 诊断：编组等待期间抽掉的消息数 / 等待超时次数（属主直通下都是 0） |
| `WKE是否支持WebView2 ()` | 逻辑型 | ★ 只读探 WebView2 Runtime（查注册表 + 常见安装路径，**不加载 DLL、不起进程**）。假 = 一定走 `node.dll` |
| `WKE取内核模式 ()` | 整数型 | ★ `0` 未就绪/失败、**`1` node.dll、`2` edgewebview（WebView2）**。首次 `绑定`/`载入` 之后才有值 |
| `WKE取WebView2诊断 ()` | 文本型 | ★ 一行式 WebView2 明细：探测结果、可用的 Runtime 版本、profile 目录（含不可写回退提示）、环境/controller 创建的 HRESULT、最后错误。**edge 起不来时先看它** |

上面都是**模块级**命令。**浏览器类（`mb` 对象）**还有两组与下载相关的东西，见 §7：

* **事件**：`事件_正在下载`（逻辑型 → 真=放行 / 假=取消）、`事件_下载完成`（路径 + 结果，`0`=成功 / 非 `0`=失败/中断）、
  `事件_下载开始`（逻辑型 → **真=业务接管并取消内核这份下载** / 假=继续，返回值与 `事件_正在下载` 相反）、
  `事件_下载进度`（字节级进度，300 ms 轮询；总长未知时百分比 `-1`）、`事件_开始载入URL`（逻辑型 → 假=取消这次导航）、
  `事件_结束载入URL`（WebView2 下**未实现**）；新事件的签名与示例见 §7.7–§7.9；
* **方法**：`置下载目录 (目录)`（传空文本 = 恢复系统「下载」文件夹；**只有置过非空目录、且注册了 `事件_正在下载` 并返回真，放行时才会静默接管下载**）。
* **2026-10-20 新增事件**：`事件_下载开始`（逻辑型 → **真 = 业务接管并取消内核下载** / 假 = 不接管）、
  `事件_下载进度`（已下载 / 总大小 / 百分比）；契约与示例见 §7.7–§7.9。

## 3. 热重载

| 想要的结果 | 顺序 |
|---|---|
| 只换页面内容 | 直接 `载入`，不必卸载模块 |
| 换业务模块（改动大） | `WKE全解绑 ()`（或逐个 `销毁`）→ 卸载模块 → 载入新模块 → 重新 `绑定` |

## 4. 环境变量

| 变量 | 作用 |
|---|---|
| `MBKIT_K=1` | **逃生阀**：退回「常驻线程 K + 全调用编组」。离屏/无窗口场景可用，**窗口里渲染不出页面** |

| `MBKIT_SHOW_ERRORBOX=1` | 需要人工看错误框时才开（默认关） |

| `MBKIT_STRICT=1` | 任何缺失导出都按致命处理（排查用） |
| `MBKIT_WV2_PROFILE=目录` | **WebView2 profile 显式指定**。缺省策略是「谁可写就用谁」：先试 `%LOCALAPPDATA%\MbKitWebView2`，探针测不可写就退回 `<exe 目录>\MbKitWebView2`，再不行才用 `%TEMP%`（宿主被打了 Low 临时标签时会走回退，`WKE取WebView2诊断 ()` 里能看到提示） |

## 5. 两条硬规矩（踩过坑）

1. **不要把模块源码内联进 DLL 工程**。易语言 DLL 编译模式对「公开子程序 + 可空参数」有额外限制
   （实测报 `错误(10061) 被取地址的子程序“WkeA2W”的参数 2 不能具有“可空”标志`）。
   请与本项目现有插件一致：**导入 `miniblink.ec` 易模块**。
2. **宿主库基名是 `MbKit146.dll`，别改回 `MbKit.dll`，也别把版本号从文件名里去掉**。
   易语言 `.DLL命令` 声明的是库基名，Windows 对已载入模块**按基名命中、不看路径**：真实宿主里
   `AILI·LIFE.dll`（同一个 miniblink 模块的旧版本，内嵌 MbKit/1.2）加载顺序排在前面，
   会把 `MbKit.dll` 这个基名占掉 —— 之后本模块所有调用都走那份旧实现（表现为自检里
   「内核属主 = K 模式」、`WKE设置node路径` 返回假、页面空白）。版本化文件名让新旧模块可以同进程共存。
   **为什么版本号必须写进文件名**：Windows 对已载入模块按**基名**命中、不看路径，同名不同版本会互相抢占，
   所以基名必须随内核版本走（当前 `MbKit146.dll`）。
   早年模块靠「**尺寸一致**」判断磁盘上那份是不是本版本（早期宿主库两次构建极易同尺寸 ——
   实测 v1.4 与 v1.4.1 的宿主库就是同尺寸，于是旧的、会死锁的那份被当成「同一版本」留在盘上，修好的永远不生效）；
   **现在改成逐字节比对**（`_释放宿主库文件`：`读入文件 (路径) = #_常量28010234`，
   见构建期源码树 `miniblink_源码146\代码\程序集_全局.static.e.txt:191-217`），
   尺寸相同但内容不同的旧内核不会再被误判成同一版本。

### 7.1 为什么以前拦不到、也不知道下载成功

旧内核（2026-10-13 那版 `MbKit146.dll`）的 edgewebview 后端**只实现了「显示网页」**：
窗口、导航、JS 都有，但**从来没把 WebView2 的 `DownloadStarting` / `NavigationStarting` 挂上回调**；
更要命的是 `wkeOnDownloadFinish` / `wkeSetDownloadDir` **这两个导出在旧内核里根本不存在**。于是：

* `事件_正在下载` 里 `wkeOnDownload` **注册是成功的**（易语言代码没写错），但回调**一次都不会被调用**；
* `事件_下载完成` 需要的 `wkeOnDownloadFinish` 取不到地址（`GetProcAddress` = `00000000`），
  模块侧因此静默跳过了事件登记 —— IDE 里看不到任何报错，只是**永远不响**；
* `置下载目录` 需要的 `wkeSetDownloadDir` 同样不存在。

旧内核的铁证（插件日志 + 探针，**注册成功、命中 0**）：

```text
回调登记 : 2 个（存活 2）  命中 0
exports: OnLoadUrlBegin=… OnDownload=… OnDownloadFinish=00000000 SetDownloadDir=00000000
```

**同一支探针，只换 DLL，代码一个字没改**：

```text
exports: OnLoadUrlBegin=… OnDownload=… OnDownloadFinish=… SetDownloadDir=…
wire: DownloadStarting hooked
[797] DL http://127.0.0.1:18731/f.bin -> return 1
[3250] DONE result=0 path=C:\...\dlout\dl_e2e_test (1).bin
nav=1 dl=1 finish=1 result=0
```

结论（旧内核）：**这是宿主库（MbKit）WebView2 后端的缺陷，不是 miniblink 的 `node.dll` 问题。**

**2026-10-20 补测（用户侧真因）**：旧内核缺陷修好后，你最初那版 `模块测试源码.e`（不是现在的 r8 发布版）仍然收不到下载回调——
它只有 `mb.绑定`、新窗口事件、`mb.载入URL` 这些基础调用，**从未调用 `置下载目录`**，也**没有注册 `事件_正在下载` / `事件_下载完成`**。
内核只有在「`置下载目录` 设过**非空**目录」**且**「注册了 `事件_正在下载` 且回调返回 真」同时成立时才静默落盘接管；
缺目录或没注册开始事件时，日志是 `download allowed (WebView2 default UI)`，走 Edge 默认下载 UI
（文件进系统下载目录、弹默认下载条）；开始事件返回 假 则直接 `put_Cancel` 取消。
**走内核落盘这条路时，这两个事件都没注册，E 侧收不到任何回调**。**这不是 bug，是设计约束**；最小成对写法见 §7.3，r8 发布版 demo 则走 §7.9 B 的 `事件_下载开始` 业务接管。

下载事件之外，本轮还修掉了宿主库的另一个独立缺陷：**延迟回收队列自循环**。

`k_destroy_batch` 批量销毁时，对每个 view 调 `G.SetHandle` / `G.DestroyWebView`；这两个是导出桩，
会经编组层重新进入 `mbk_defer_destroy()`，把刚弹出队列的 view 又登记回去。待回收队列上限
`MB_DQ_CAP = 64`，于是「弹一个、回一个」，永远排不空：每次运行固定有 **64 个 WV（WebView 视图）永不 `delete`**。
这些原生视图不在 `G.views[]` 里，`MbKit_DetachAll` 也救不回来；既是有界泄漏，又让 `g_liveViews`
留下僵尸项，拖慢 `wv_of` 的线性扫描。

修复在 `mbkit.c`：新增 `g_dqb_busy`，`k_destroy_batch` 进入时置位、退出时恢复；`mbk_defer_destroy()`
在这个窗口内直接 `return 0`，销毁请求穿透到真实现，不再回队列。

实测 memreg 100 轮：修复前 `destroyed/freed = 36/36`（未通过），修复后 **100/100（PASS，rc=0）**。
测试进程退出前（RUN-END）最后 2 个仍在 400ms 延迟队列里，这是**设计行为**——延迟回收是任务 5 的「反卸载死锁」修复，
不能为了消掉这 2 个暂时项而删除；再触发两次编组入口后归零。

### 7.2 行为契约（记住这张表就不会踩坑）

> **参数类型铁律**：`事件_正在下载` 的 `URL`、`事件_下载完成` 的 `路径`、`事件_开始载入URL` 的 `URL`
> 一律声明 **文本型**——内核传的是本地代码页（中文系统即 GBK）的 NUL 结尾 `char*`，
> 只在本次回调内有效；要长期留存请在回调内立即复制（如 `到字节集` 或 `写到文件`）。
> 写成 `整数型` 再 `WKE取文本()` 只会拿到空文本；`整数型【wkeString】` 只用于 `即将创建新窗口` /
> `即将导航` / `载入完成` / `URL被改变` / `控制台消息` 这类事件。

**`事件_正在下载`** —— 逻辑型，签名 `(整数型 wkeWebView, 整数型 用户数据, 文本型 URL)`（模块注释原文）

| 情形 | 内核行为 |
|---|---|
| 没注册该事件 | 不挂下载监听/轮询；若也未调用 `置下载目录`，走 WebView2 默认 UI / 默认目录，原样进行 |
| 注册了，回调返回 **真**，**没调** `置下载目录` | 放行，仍走 WebView2 默认下载 UI（日志 `download allowed (WebView2 default UI)`） |
| 注册了，回调返回 **真**，**调过** `置下载目录`（非空，且下载前） | 内核接管：静默写入你给的目录，不弹任何 UI |
| 注册了，回调返回 **假** | 立即取消这次下载，磁盘不留文件 |
| 注册了，但回调**没写返回值** | **不能依赖**：`逻辑型` 在 cdecl thunk 里只读 EAX，未显式返回时值不确定，可能被当成假而取消；每个分支都要显式 `返回 (真/假)` |

**`事件_下载完成`** —— 无返回值，签名 `(整数型 wkeWebView, 整数型 用户数据, 文本型 路径, 整数型 结果)`（不要写返回值）

| 情形 | 内核行为 |
|---|---|
| 没注册该事件 | 本事件不回调；若也没注册 `事件_下载进度`，内核不额外挂进度轮询 |
| 注册了（该 WV 已挂 `wkeOnDownloadFinish`） | 只在**终态**回调**一次**；`结果`：`0`=成功，非 `0`=失败/中断（本版实测为 `1`） |
| 成功（`结果 = 0`） | `路径` 是**实际落盘路径**；文件已存在时 Chromium 会自动改名（如 `名字 (1).bin`），回调给的是改名后的真实路径，**别自己拼** |
| 下载已开始后取消或中断（`结果 ≠ 0`） | 回调**仍会触发一次**；此时 `路径` 是 WebView2 的**计划路径**（在你设的下载目录或系统默认「下载」文件夹下），**文件可能并不存在**（也可能只留下部分文件）。判断是否真的下到，请用 `文件是否存在 (路径)` |

**`事件_开始载入URL`** —— 逻辑型，签名 `(整数型 wkeWebView, 整数型 用户数据, 文本型 URL, 整数型 job)`

| 返回值 | 效果 |
|---|---|
| 真（每个分支显式 `返回 (真)`） | 照常导航 |
| **假** | **取消这次导航**：页面不跳转，下载也不会开始（实测 `nav=1 dl=0 finish=0`，WebView2 报 `NavDone ok=0 err=14`） |

> `err=14` 是用户/代码取消导航的实测错误码；`err=9`（`REDIRECTION_FAILED`）也会出现在「附件型顶层导航」
> （服务器返回 `Content-Disposition: attachment`）的 `载入完成` 里，**不是下载失败**——下载仍然会触发。
> 导航回调结果同样只有 `0` / `1`，不会出现 `2`。
> ⚠️ 取消发生在**导航层**：服务器侧仍记录 `sent 524288 bytes`，**请求体已经发完** —— 所以不要指望靠它省流量。

三条硬事实：

1. **内核静默接管必须成对**：只注册 `事件_下载完成`、不注册 `事件_正在下载`，不会接管到自己的目录（下载仍走 Edge 默认 UI；这里的“接管”指内核落盘，业务接管走 §7.7 的 `事件_下载开始`，两者返回值语义相反）；
   两个事件都不注册时，E 侧没有任何回调。实测 finishonly 场景 `dl=0 finish=1 result=0` 只证明能收到终态，不证明能接管。
2. `事件_下载完成` 的**视图/用户数据由模块填好**，你在 IDE 里按提示顺序接参数即可；**不要给它写返回值**。
3. `置下载目录` 是 **WebView2 专属**：只有 `事件_正在下载` 已注册、回调返回真，且在下载开始前调用过 `置下载目录`，
   才会参与**静默接管**；未注册该事件时内核直接放行给 WebView2 默认 UI（`node.dll` 后端没有对应实现，老内核本来就用系统下载目录）。
   但本版会把非空目录写进 WebView2 profile 的默认下载目录：即使没注册 `事件_正在下载`，默认下载 UI 的默认保存位置也会指向这里
   （用户仍可在 UI 里改路径；这不是静默接管）。
   传**空文本** = 恢复系统「下载」文件夹（走 WebView2 默认 UI）。
   **目录不需要用户预先创建**：模块会调用 `put_DefaultDownloadFolderPath` 写入 profile，并在落盘前尝试自动创建（多级亦可）；E 场景就是不预建目录直接下载成功的。稳妥起见你也可以先 `创建目录 ()` 并检查返回值；内核创建失败才回落到系统下载目录。

**四个常见误解**

| 写法 | 实际结果 |
|---|---|
| 只注册 `事件_下载完成`，不注册 `事件_正在下载` | 不会接管到自己的目录，下载仍走 Edge 默认 UI |
| 只写 `置下载目录`，不注册事件 | 设置成功时，目录会成为 WebView2 的默认下载目录；但不静默接管，仍弹出默认下载 UI（日志 `download allowed (WebView2 default UI)`） |
| `事件_正在下载` 返回 假 | 下载被 `put_Cancel` 取消，不会进入下载，也不会有完成事件 |
| `事件_正在下载` 回调声明成 无返回值 / 参数个数不对 | 事件静默不来（IDE 不一定报错） |

### 7.3 代码示例

> 两条注意：
> (a) `取运行目录 () ＋ “\下载”` 这种写法**不需要预先建目录**：模块会写 profile 默认下载目录并尝试自动创建（多级亦可）。稳妥起见也可以先 `创建目录 ()` 并检查返回值；内核创建失败时会回落到系统下载目录（日志 `创建下载目录失败 rc=...`）；
> (b) 如果你在 `事件_正在下载` 里返回假，下载会在 DownloadStarting 阶段被取消，**通常不会再有完成事件**；
> 若下载已开始后因其它原因取消/中断，`路径` 可能只是**计划路径**，别直接拿去读文件。

   进入即证明回调链通，再等 `事件_下载完成` 的 `结果=0` 且 `文件是否存在 (路径)` 为真即落盘成功。

### 7.4 与 `node.dll`（wke 老内核）的差异

| 能力 | `node.dll`（wke，≈Chrome 57） | edgewebview（WebView2） |
|---|---|---|
| `事件_正在下载` | 支持（`node.dll` 有 `wkeOnDownload` / `wkeOnDownload2`） | **本版起支持** |
| `事件_下载开始`（业务接管） | 无 | **本版新增**（返回真 = 业务接管、内核取消这一份下载；见 §7.7） |
| `事件_下载完成` | **不支持**（`node.dll` 里没有 `wkeOnDownloadFinish` 导出） | **本版起支持** |
| `置下载目录` | 空实现（没有 `wkeSetDownloadDir`） | 支持 |
| `事件_开始载入URL` 触发粒度 | **每个子资源都触发**（js/css/图片，很密） | **只对主框架导航触发**（一次跳转一次） |
| `事件_开始载入URL` 的 `job` | 有效句柄，可配 `WKE网络HOOK请求 ()` 改包 | **恒为 0**；`wkeNetSetData` / `wkeNetGetMIMEType` 不可用 |
| `事件_结束载入URL` | 支持（需在开始事件里调 `WKE网络HOOK请求 ()`） | **未实现**（注册了也不会响） |
| 下载进度（字节级） | 无 | **本版新增 `事件_下载进度`**（300 ms 轮询，见 §7.8；极小文件可能只有首末两帧） |

**结论**：「按 URL 特征拦下载」两种内核都能用；**改包 / 读响应体**只有 `node.dll` 能干。
要走老路：`WKE设置node路径 (路径, 失败原因, 真)`（第三个参数传 **真** 才强制 `node.dll`）——
但那样 `事件_下载完成` / `置下载目录` 就用不了。

### 7.6 排错

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `事件_正在下载` 不响 | 事件没注册 / 注册时视图句柄是 0 | 在 `_浏览器窗口_创建完毕` 里、`mb.绑定` 之后立刻注册 |
| 同上 | 跑的仍是旧内核 | 看 `<运行目录>\MbKit146.dll`：763,904 才是最终版，其它尺寸 ⇒ 按 §7.5 重编宿主 |
| 同上 | 走的是 `node.dll` | `WKE取内核模式 () = 1` ⇒ 去掉 `WKE设置node路径` 的第三个参数（或传假） |
| 回调里 `返回 假` 了、文件还是下下来了 | 你在 `事件_正在下载` 里返回假，但该次下载是 WebView2 在别处触发的（比如新窗口） | 改用 §7.3 的 ①：在 `事件_开始载入URL` 里返回假 |
| `事件_下载完成` 不响 / 迟到约 60 秒 | 旧内核只依赖 `StateChanged`；或没注册该事件 / 视图句柄是 0 | 换最终版内核；已知总长通常 0.2~1.7 秒内完成，未知总长约 4 秒（§7.8），并确认在 `mb.绑定` 后注册了 `事件_下载完成` |
| `置下载目录` 不生效 | 没调它；没注册 `事件_正在下载`（或回调返回假）；或后端是 `node.dll` | 先注册开始事件并返回真，再在下载前调用；WebView2 下传绝对路径，目录会被自动创建，失败看日志 `创建下载目录失败 rc=...` |
| 下载完成但 `结果 ≠ 0` | 下载已开始后用户/程序取消，或 WebView2 报中断（`err=14`）；`事件_正在下载` 返回假通常不会走到这里 | 看 `WKE取WebView2诊断 ()` 的最后错误 |
| `事件_下载完成` 给了路径但文件不存在 | 下载已开始后取消/中断，`路径` 是 WebView2 的**计划路径** | 用 `文件是否存在 ()` 判断；要文件就自己下（§7.3 ①） |
| 页面点了下载没反应，也没文件 | 这正是拦截生效：`事件_开始载入URL` 返回了假，导航被取消 | 正常；要文件就自己下（§7.3 ①） |

### 7.7 新增：`事件_下载开始`（业务接管钩子）

`事件_下载开始` —— 逻辑型，签名 `(整数型 wkeWebView, 整数型 用户数据, 文本型 网址, 文本型 文件名, 整数型 总字节)`。
> `.参数` 顺序是 `(整数型 wkeWebView, 整数型 用户数据, 文本型 网址, 文本型 文件名, 整数型 总字节)`；前两个参数由模块回填，**IDE 里照提示接全五个**（少写会绑不上事件）。

| 项 | 契约 |
|---|---|
| 触发时机 | WebView2 抛 `DownloadStarting` 时触发，**早于** `事件_正在下载`，也早于任何落盘动作 |
| `网址` | 真实下载 URL |
| `文件名` | 建议文件名；取不到时用 URL 末段推导 |
| `总字节` | `TotalBytesToReceive`；**未知或大于 2GB 报 `0`**（业务侧把 `0` 当“未知/不可用”） |
| 返回 **真** | **业务自己接管**：内核立刻 `Cancel` 这一份下载，不建监听、不写文件、不落 `.crdownload`；这一份下载之后**不再发任何下载事件**（没有 `事件_正在下载`、没有进度、没有完成） |
| 返回 **假** | 不接管，继续原有流程：`事件_正在下载` →（按需）静默落盘到 `置下载目录`，或走 Edge 默认下载 |

> ⚠️ **返回值语义和 `事件_正在下载` 正好相反**：
> `事件_下载开始` 返回 **真 = 接管/取消内核下载**；返回 **假 = 不接管/继续**。
> `事件_正在下载` 返回 **真 = 继续下载**；返回 **假 = 取消下载**。两个事件不要套用同一个返回值习惯。

> 这个钩子只能看到已经进入 `DownloadStarting` 的下载；如果默认下载目录不可写，导航可能在更早阶段就被静默中止，此时连 `事件_下载开始` 都不会触发。先保证 `置下载目录` 可写（机理见同目录《修复说明》§10.1）。

`网址` / `文件名` 是 **ANSI（GBK）单字节串**，业务侧直接当普通 `文本型` 用即可。
回调必须声明为逻辑型，每个分支显式 `返回 (真/假)`；不写返回值时结果不可靠。
返回真之后内核不再下载，**进度和完成事件都不会再来**，业务侧要自己下载、自己算进度、自己判断落盘结果。

**事件对照**

| 事件 | 返回 真 | 返回 假 |
|---|---|---|
| `事件_下载开始` | 业务接管，内核取消这一份下载 | 不接管，继续原有流程 |
| `事件_正在下载` | 继续下载（放行） | 取消这次下载 |

### 7.8 新增：`事件_下载进度`（300 ms 轮询）

`事件_下载进度` —— 无返回值，签名 `(整数型 wkeWebView, 整数型 用户数据, 整数型 已下载, 整数型 总大小, 整数型 百分比)`。
前两个参数由模块回填，**IDE 里照提示接全五个**（少写会绑不上事件）。

| 项 | 契约 |
|---|---|
| 登记方式 | **只关心进度时，只登记这个事件就够了**；内核会为此创建下载监听，不需要同时登记 `事件_下载完成` |
| 首帧 | 内核为本次下载建立监听后，**立刻补发一帧 `(0, 总字节, 0)`**；总字节未知时发 `(0, 0, -1)` |
| 后续帧 | 每 **300 ms** 轮询一次，**只在已下载字节数变化时才发**，不刷屏 |
| 末帧 | 下载完成前补一帧 `(总大小, 总大小, 100)`；**这一帧一定先于 `事件_下载完成`** |
| 去重（本版新增） | `(已下载, 总大小, 百分比)` 三元组完全相同只发一次；每次下载只会看到**一帧 100%**；若登记了 `事件_下载完成`，也只触发**一次** |
| 数值范围 | `已下载` / `总大小` 为 32 位整数：大于 2GB 截断为 `2147483647`；总长未知为 `0` |
| `百分比` | `已下载 × 100 ÷ 总大小` 截断取整，上限 `100`；**总长未知时为 `-1`**，业务侧务必先判 `-1`，不要按 `0` 处理 |
| 适用范围 | 只对**内核自己下载的那一份**有意义；`事件_下载开始` 返回真后内核不再下载，**没有进度事件**，业务自接管时要自己算进度 |

> 进度是 300 ms 轮询，不是 Chromium 推送；极小的文件可能只看到首帧和末帧（`0%` → `100%`），这是预期行为，不是丢帧。

**未知总长（`总大小 = 0`）的完成判据（务必先看）**

> WebView2 的 `DownloadOperation::StateChanged` 在这类下载里只会报 `st=0`，**永远不报 `COMPLETED`**；所以模块不能只等状态翻转，而要用 300 ms 轮询做兜底。
>
> 兜底必须**同时**满足两个条件才判完成：① 已下载字节数连续 **3.6 秒（12 个轮询周期）没有增长**；② 磁盘上的文件大小**严格等于**已下载字节数。两个条件缺一不可，避免“第一块刚写完就报完成”。
>
> 因此未知总长的完成时间会比最后一个字节晚约 **4 秒**（D 场景实测 **4.056 秒**），这是有意为之的取舍，不是卡住。若服务器中途停顿 ≥3.6 秒，完成可能进一步推迟，但**不会提前误报**；进度百分比固定为 **`-1`**。
>
> 已知总长仍走原判据：已收满 + 最终文件名已落地 + 没有 `.crdownload`，实测通常在 **0.2~1.7 秒**内报完成（A 场景 **0.179 秒**）。两类下载都只报**一次** `事件_下载完成`。

### 7.9 三种写法

以下只列关键语句，`mb` 的声明、绑定和窗口过程同 §7.3。

**A. 只监听进度（模块下载，不接管）**

```易语言
.版本 2

' 1) 必须先把下载目录指到可写位置，否则附件型导航可能被静默中止
mb.置下载目录 (取运行目录 () ＋ “\下载”)
mb.事件_下载进度 (&处理_下载进度)
mb.载入URL (“https://example.com/file.bin”)

.子程序 处理_下载进度
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 已下载, 整数型
    .参数 总大小, 整数型
    .参数 百分比, 整数型
    .如果 (百分比 ＝ -1)
        输出调试文本 (“进度未知，已下载 ” ＋ 到文本 (已下载) ＋ “ 字节”)
    .否则
        输出调试文本 (“进度 ” ＋ 到文本 (百分比) ＋ “%（” ＋ 到文本 (已下载) ＋ “/” ＋ 到文本 (总大小) ＋ “）”)
    .如果结束
```

> 这里只登记进度，没有 `事件_正在下载`，所以不会静默接管；`置下载目录` 只是把 WebView2 的默认下载目录指到可写位置，避免附件导航被静默中止。

**B. 业务接管 + 自己下载（发布版 demo 的真实写法）**

```易语言
.版本 2

.程序集变量 全局_接管下载, 逻辑型

' 打开门控：真 = 本程序接管；假 = 交回内核
全局_接管下载 ＝ 真
mb.置下载目录 (取运行目录 () ＋ “\下载”)   ' demo 也设了；接管时内核那份会被 Cancel，这行只保证回退路径可写
mb.事件_下载开始 (&处理_下载开始)
mb.载入URL (“https://example.com/file.bin”)

.子程序 处理_下载开始, 逻辑型
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 网址, 文本型
    .参数 文件名, 文本型
    .参数 总字节, 整数型
    .局部变量 数据, 字节集
    .局部变量 目标目录, 文本型
    .局部变量 目标文件, 文本型

    .如果真 (取反 (全局_接管下载))
        返回 (假)                 ' 假 = 不接管，继续内核原流程
    .如果真结束

    目标目录 ＝ 取运行目录 () ＋ “\用户下载”
    创建目录 (目标目录)
    数据 ＝ HTTP读文件 (网址)
    .如果真 (取字节集长度 (数据) ＞ 0)
        目标文件 ＝ 目标目录 ＋ “\” ＋ 文件名
        .如果真 (写到文件 (目标文件, 数据) ＝ 假)
            记录日志 (“写盘失败：” ＋ 目标文件)
        .如果真结束
    .否则
        记录日志 (“HTTP读文件失败：” ＋ 网址)
    .如果真结束
    返回 (真)                     ' 真 = 内核取消这一份，不再发进度/完成
```

> 上面就是发布版 demo 的核心逻辑（`处理_下载开始` 另有失败日志，省略了界面代码）。`记录日志` 同时 `输出调试文本` 并追加到 `运行目录\下载日志.txt`（GBK/ANSI、无 BOM，由程序自己创建）：冷启动、直接双击 exe 也有日志，不需要事先放一个空文件。
>
> **依赖库**：`HTTP读文件` 属于 `互联网支持库`，工程库表必须保留 `internet`。删掉它会直接编译失败：`错误(37) 找不到指定的命令／子程序／Dll命令调用名称“HTTP读文件”`。
>
> B 场景实测（发布版 demo，冷启动且事先无日志文件）：日志 **8 行 / 443 B / GBK / 无 BOM**；`用户下载\dl_e2e_test.bin` = **524,288 B**，MD5 `09cc21fef48e9ad67608d530df98cbf5`；`下载\` 目录 **0 个文件**（含 `.crdownload`）、**0 条进度**、**0 次完成**；诊断含 `download handed to user: …`。这三个“0”正是接管生效的证据。
>
> 这个示例把下载放在回调里，便于把契约写完整；实际项目建议在回调里**先返回真**，再把 `网址` / `文件名` 投递到工作线程去下载，避免在 WebView2 的 `DownloadStarting` 回调里做长时间阻塞。
> `文件名` 是服务器建议值，落盘前请自己净化路径分隔符，避免 `..\` 之类的名字逃出目标目录。
> 生产代码要判 `数据` 是否为空、`写到文件` 是否成功；失败时仍返回真并由业务提示，不要让 WebView2 继续再下一份。

**C. 按 URL 白名单拦截（`事件_正在下载`，注意返回值相反）**

```易语言
.版本 2

mb.置下载目录 (取运行目录 () ＋ “\下载”)
mb.事件_正在下载 (&处理_正在下载)
mb.载入URL (“https://example.com/”)

.子程序 处理_正在下载, 逻辑型
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 URL, 文本型

    .如果真 (寻找文本 (URL, “/allowed/”, , 假) ＝ -1)
        返回 (假)          ' 假 = 取消这次下载
    .如果真结束
    返回 (真)              ' 真 = 继续下载
```

> 这三段可以叠加：`事件_下载开始` 返回假时才会继续走 `事件_正在下载`；一旦前者返回真，后者、进度、完成都不会再触发。

**最终确认建议**：IDE 打开 `miniblink\miniblink.e` 编译一次确认无报错；再编一次宿主，起页面点一个下载链接，
`事件_开始载入URL` 应命中、拦截返回假后浏览器不再下载；再按 §7.3 成对注册下载事件并置目录，确认 `事件_下载完成` 只来一次且 `结果=0`。已知总长实测 **0.179 秒**、未知总长实测 **4.056 秒**；发布版 demo 的业务接管场景应表现为 `用户下载\` 有文件、`下载\` 0 个文件/0 进度/0 完成（见 §7 验收表 B）。


## 9. 内核自检：旧内核被复用导致宿主硬崩（2026-10-21，模块侧根治）

### 9.1 现象

多插件共用同一个宿主进程时，浏览框一创建整个宿主就消失：没有对话框、没有可捕获的异常，
`绑定` 返回的还是 **真**。转储里停在 `wkeSetDownloadDir` 这类**按槽位绑定**的调用上（模块内槽位 185/256）——
说明被调用的那份内核根本不是本模块校验过的那份，导出表/内部表布局对不上。

### 9.2 根因（两条，都在模块自己身上）

1. `_释放宿主库文件` 在「覆盖失败」时用 `文件是否存在 (路径)` 冒充成功。盘上那份旧内核被别的进程锁着、
   或落在只读目录时，删不掉也写不进，函数却返回 真 —— 于是 `LoadLibraryA` 把**旧内核**当新内核载了进来。
2. Windows 对同名 DLL 是「已载入优先」：宿主里只要已经有人载入过 `MbKit146.dll`（多插件时很常见），
   `LoadLibraryA (<运行目录>\MbKit146.dll)` 拿回来的就是**别人那份**，路径和版本都不受本模块控制。
   旧实现只比「文件存在 + 大小」和版本串，完全没有这道检查。

历史弯路一条：往 `%TEMP%\ElangMbKit` 释放内核**没用** —— 易语言的 `.DLL命令` 只按 exe 目录找
`MbKit146.dll`，换到别处用不上，只是假象。该回退分支已删除。

### 9.3 现在的行为（本目录 1.4.6 版）

`_确保宿主库已载入` 变严格了：**拿不到「逐字节就是本模块内置那份」的内核，就明确失败**。

* 盘上文件与内置资源逐字节比对（`#_常量28010234`），不一致才覆盖；覆盖后**复核一遍**，仍不一致 → 假。
* 覆盖前先清 `#只读文件` 再 `删除文件`；删不掉直接返回假（不再退 `%TEMP%`）。
* 载入前先 `GetModuleHandleA (“MbKit146.dll”)`：进程里已经有人按同名载入过 → 直接假。
* 失败时把具体原因记进 `_程序集变量1501092C`，`WKE宿主自检 ()` 会打出来（人话，含下一步该干什么）。
* 所有 WKE* 入口都先过这道门禁：`绑定` / `取浏览器指针` / `置下载目录` ……拿不到内核就停手，不半跑。

| 现场 | 旧版 | 1.4.6 |
| --- | --- | --- |
| 运行目录内核正确 | 绑定=真 | 绑定=真 |
| 运行目录是旧内核，且被别的进程锁死 | **绑定=真，静默用旧内核 → 后续硬崩** | 绑定=假，一个内核都不载入，进程活着 |
| 宿主里已有别的模块载入 `MbKit146.dll` | 绑定=真，用的是别人那份 | 绑定=假，并给出原因 |

原则是「宁可失败也不崩」：调用方拿到 假 就停手；`WKE宿主自检 ()` 给出原因。
副作用（有意为之）：宿主混用不同版本内核、或 exe 目录只读又依赖旧 `%TEMP%` 回退的程序，现在会**快速失败**而不是硬崩。

### 9.4 升级怎么做

1. 用本目录的 `miniblink.ec`（987,037 B，MD5 `9E9D0EC734944750C029951514B7C9A5`）和 `miniblink.e`（1,014,021 B）覆盖旧文件。
   **文件名必须还是 `miniblink.ec`** —— 易语言按文件名重写模块名，改名后宿主里挂在该模块下的类/公开命令会全部失联，
   IDE 编译期直接 0xc0000005（无报错）。
2. 宿主工程里重新引用一次该模块（或直接重编宿主）。产物会内嵌新内核：763,904 B / MD5 `6093014F4DD533C2B9FCBC41C629AC91`。
3. 旧版文件已放在 `backup\`（`miniblink_原版_1.4.5.ec` / `miniblink_原版_1.4.5.e`），要回退直接拷回。

### 9.5 验收（本机 A/B 实测，独立探针 exe，静态编译）

* **正常内核**：`绑定=真`，`置下载目录` / `载入URL` 全过，盘上内核原样不动。
* **旧内核 + 只读共享锁死**：旧模块 `绑定=真`，且进程里**确实**载入了旧内核（模块内存 815,104 B，路径=运行目录那份 738,304 B 文件）；
  1.4.6 `绑定=假`，进程模块列表里**没有** `MbKit146.dll`，盘上旧文件原样不动，也没有 `%TEMP%` 副本。
* **宿主先载入外来内核**：1.4.6 `绑定=假`（诊断指向「进程里已有别的代码载入了 MbKit146.dll」），进程不被带走。
