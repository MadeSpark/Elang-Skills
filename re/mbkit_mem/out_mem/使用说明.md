# miniblink 模块（**内存加载版**）—— 使用说明

> 本版取代 `out_mbkit/`（2026-09-24）那一版。旧版说明里「纯内存映射 PE 做不到」的结论
> **已被推翻** —— 本版就是真·内存映射，见下文 §3。

| 文件 | 大小 | 说明 |
|---|---|---|
| `miniblink.e` | 385,258 B | 模块源码，可在易语言 IDE 里直接打开、编译 |
| `miniblink.ec` | 362,733 B | 已编好的易模块。**文件名必须叫 `miniblink.ec`**（模块内部名 = 文件名；不一致会让类的属主断裂 → 编译期 0xc0000005） |

安装：把 `miniblink.ec` 覆盖到你工程引用的那个模块路径即可。
本机实测用的路径是 `D:\DevelopmentFolder\常用模塊\miniblink.ec`。
**覆盖前先备份原文件**（回滚见 §5）。

## 1. 这次改了什么（**只动模块，宿主工程一行都不用改**）

| # | 改动 | 效果 |
|---|---|---|
| ① | 258 条 `.DLL命令`（库名 `MbKit.dll`）**全部删掉**，换成 258 个**同名、同签名**的包装子程序，放进新程序集 `程序集_内存映射` | 调用的写法、名字、参数一个不变 ⇒ 模块内 2363 个调用点**零改动** |
| ② | 包装子程序体 = `置入代码`：压参数 → `call dword ptr [池 + 4*槽]` | 绕开「`.DLL命令` 只能按库名 `LoadLibrary` 解析」的限制 |
| ③ | `MbKit.dll` 改为**手工映射进本进程内存**（不落盘、不进加载器链表、不占模块名） | 宿主目录**不会再冒出 `MbKit.dll`**；`%TEMP%\ElangMbKit` 也不再写 |
| ④ | 映射器机器码（1840 B）以资源 `#Mapper` 内嵌；`MbKit.dll`（56,320 B）仍以资源 `#MbKit` 内嵌 | 模块自包含，不需要外带任何 dll |

`node.dll` 仍需在磁盘上（它是被 `LoadLibrary` 正常加载的真内核），规则见 §2。

## 2. `node.dll` 放哪

按顺序找，**先命中先用**：

| 顺序 | 位置 |
|---|---|
| ① | 用 `WKE设置node路径 ()` 指定的路径 |
| ② | **宿主 exe 所在目录** `\node.dll`（默认，推荐） |
| ③ | `MbKit.dll` 所在目录（本版为内存映射，此项实际不可用） |
| ④ | exe 目录上溯 ≤5 级，试 `\node.dll` 与 `\main\corn\node.dll` |
| ⑤ | 当前工作目录 |
| ⑥ | 裸名 `node.dll`（交给系统搜索） |

**最省事的用法：把 `node.dll` 和你的 exe 放同一个目录。**

## 3. 关于「内存加载」的准确说法

| | 09-24 旧版 | **本版** |
|---|---|---|
| `MbKit.dll` | 运行时**释放到磁盘**（exe 目录 或 `%TEMP%\ElangMbKit`）+ `LoadLibraryA` 预载 | **手工 PE 映射进内存**，全程不落盘 |
| 加载器链表 | 进（是正常加载的模块） | **不进** |
| 进程模块名 | 占用 `MbKit.dll` | 不占 |
| 调用方式 | 易语言按库名解析 | 按**函数地址**直接 `call` |
| 宿主目录副作用 | 多一个 56 KB 文件 | **零副作用** |

> 唯一保留的磁盘依赖是 `node.dll`（33.6 MB 的内核本体）—— 它必须由系统 `LoadLibrary`
> 正常加载，手工映射它没有意义也不可行。

## 6. 已知限制

- **只支持 32 位**（映射器与槽位表都按 32 位 PE 写）。
- `MbKit.dll` 被刻意 **PIN**：改 `src/mbkit/*.c` 后必须重跑 `re/opt/build_text.py` 才会重新内嵌，
  且已加载的进程内**不能热更新**它（业务模块可以）。
- 映射器 blob **只能由 `re/mbkit_mem/build_mapkit.py` 产出**，别手工敲 gcc ——
  同源码不同优化级别行为不同（`-O1`/`-O3` 崩，`-O0`/`-Os`/`-O2+loop` 正常）。
- 未验证：真机业务工程（AILI·LIFE）里的**交互**（JS 互调、鼠标事件、自绘离屏渲染）。
