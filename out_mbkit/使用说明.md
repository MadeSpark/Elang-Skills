# miniblink 模块（宿主层版）—— 使用说明

> 本次改造针对 `测试\miniblink.e`，**原文件未改动**（它不在版本控制里，覆盖不可恢复）。
> 新版在这里：
>
> | 文件 | 大小 | 说明 |
> |---|---|---|
> | `miniblink.e` | 293,053 B | 模块源码（可在易语言 IDE 里直接打开、编译） |
> | `miniblink.ec` | 263,957 B | 已编好的易模块。**文件名必须叫 `miniblink.ec`**（模块内部名 = 文件名，改名会让类的属主断裂 → 0xc0000005） |
>
> 确认没问题后，自己把根目录那份 `miniblink.e` 替换掉即可。

## 1. 这次改了什么

| # | 改动 | 效果 |
|---|---|---|
| ① | 252 条 `.DLL命令` 的库名 `"main\corn\node.dll"` → **`"MbKit.dll"`**（裸名） | 内核的生命周期收归 MbKit 独占持有，业务模块可随时卸载重载 |
| ② | **`MbKit.dll` 内嵌进模块**（二进制资源，56,320 B） | **你不再需要手动放 `MbKit.dll`** |
| ③ | 模块新增公开函数 **`WKE设置node路径`**（+ `WKE取node路径` / `WKE宿主自检` / `WKE载入宿主库`） | 内核可以放在任意目录，**不再局限于 `main\corn`** |
| ④ | `node.dll` 默认位置 = **宿主程序（exe）所在目录** | 只把 `node.dll` 和你的 exe 放一起就能跑 |

### 关于「内存载入」的准确说法

真正的「纯内存映射 PE」（手动加载、不落盘）在这里**做不到**：易语言的 `.DLL命令`
是通过 `LoadLibrary` 按**库名**解析的，内核式手工映射不会进进程模块表，也就无法被按名解析。

本套装的做法是**资源内嵌 + 首次运行时释放并预载**，对外效果等同于「不用再管这个 dll」：

1. 模块启动早期（首次 `MB浏览框._初始化` / `WKE初始化` / 任何公开函数）把内嵌的
   `MbKit.dll` 释放到**宿主程序目录**；
2. 紧接着用**完整路径** `LoadLibraryA` 预载它；
3. 之后易语言执行 `.DLL命令 "MbKit.dll"` 时按**基名**命中同一份，**不会再去找磁盘上的第二份**。

> 「按基名复用」已单独实测：先 `LoadLibraryA("完整路径\MbKit.dll")`，再
> `LoadLibraryA("MbKit.dll")`，返回**同一个句柄**。

### 释放位置

| 顺序 | 位置 | 条件 |
|---|---|---|
| ① | `<宿主 exe 目录>\MbKit.dll` | 默认；目录里已有同名文件且尺寸与内嵌版本一致就直接复用 |
| ② | `%TEMP%\ElangMbKit\MbKit.dll` | ① 写不进去时（只读目录 / 文件被占用） |

> **只会在你的程序目录里多出一个 `MbKit.dll`（56 KB）**，没有其它副作用。
> 想确认它到底落在哪、内核从哪儿来，调 `WKE宿主自检 ()` 看。

## 2. 怎么用

### 2.1 什么都不用做（默认）

把 `node.dll` 放到**你的 exe 旁边**，然后照原来的写法用 `MB浏览框` 就行。

```
你的程序目录\
├── 你的程序.exe
├── node.dll          ← 只要放这里
└── ...（MbKit.dll 首次运行时自动生成）
```

### 2.2 指定内核位置

```易语言
.子程序 _启动子程序, 整数型

    ' ★ 必须在「内核加载之前」调用 —— 也就是第一次 WKE初始化 / 创建浏览框之前
    ' 返回 真 = 设置成功；假 = 内核已经加载了，改不动了
    .如果真 (WKE设置node路径 (“D:\我的内核\chromium_2021”) ＝ 假)
        信息框 (“设置内核路径失败：内核可能已经加载”, 0, , )
        返回 (0)
    .如果真结束

    WKE初始化 ()
    ' ... 后面照常创建 MB浏览框
    返回 (0)
```

`WKE设置node路径` 的参数：

* 传**目录** → 自动取 `<目录>\node.dll`
* 传 **`node.dll` 的完整文件名** → 直接用它（想用别的文件名，如 `node_x64.dll`，就给完整路径）
* **留空 / 不传** → 用默认位置（宿主程序根目录）

> **设了却没找到 → 会明确报错，不会偷偷回退到别的目录。**
> 这是刻意的：否则「我明明设了路径，跑的却是另一个内核」会变成最难查的一类问题。

### 2.3 新增的四个公开函数

| 函数 | 返回 | 说明 |
|---|---|---|
| `WKE设置node路径 (路径)` | 逻辑型 | 设置内核位置。**必须在加载前调用**；留空=默认 |
| `WKE取node路径 ()` | 文本型 | 内核实际使用的完整路径（**会触发内核查找/加载**） |
| `WKE宿主自检 ()` | 文本型 | 一行式诊断：内核状态 / 实际路径 / 自定义值 / 宿主目录 / 缺失导出 / 加载期错误 |
| `WKE载入宿主库 ()` | 逻辑型 | 手工把内嵌 MbKit 释放+预载。一般不用调（会自动做） |

### 2.4 内核查找顺序（不设置时的完整链）

| # | 位置 |
|---|---|
| ① | 自定义路径（只有显式设置过才参与） |
| ② | **`<宿主 exe 目录>\node.dll`** ← 默认 |
| ③ | `<MbKit.dll 目录>\node.dll` |
| ④ | 从宿主 exe 目录逐级上溯 ≤5 级：每级试 `\node.dll` 与 `\main\corn\node.dll` |
| ⑤ | `<当前工作目录>\node.dll` 与 `<当前工作目录>\main\corn\node.dll` |
| ⑥ | 裸名 `node.dll`（交系统搜索路径） |

> ③④⑤ 保留是为了兼容老工程的目录结构（`main\corn` 仍在链里，只是不再是首选）。

## 3. 排查手册

**先调 `WKE宿主自检 ()`**，它会一次说清：内核状态、实际路径、自定义值、宿主 exe 目录、
当前工作目录、缺失导出清单、加载期错误。输出长这样：

```
MbKit 自检
  内核状态     : 已加载
  内核路径     : D:\我的内核\chromium_2021\node.dll
  内核模块     : 0x781E0000
  自定义路径   : D:\我的内核\chromium_2021
  宿主程序目录 : D:\MyApp
  当前工作目录 : D:\MyApp
  内核缺失导出 : 4（其中被真正调用过 0 次）
  缺失清单     : JsBindGetter JsBindSetter wkeGetWebView wkeNetSetURL
  加载期错误   : (无)
```

| 现象 | 原因 / 处理 |
|---|---|
| 弹框说「指定的位置里没有 node.dll」 | `WKE设置node路径` 的路径不对。留空即用默认位置 |
| 「内核缺失导出: 4」 | **正常**。这 4 条声明在原模块里同样是死的（内核本来就没导出），已填安全桩，调用只返回 0 |
| 内核加载失败但程序没崩 | 刻意设计：失败时**不 `ExitProcess`**（那会把宿主一起带走），只记录错误 + 弹一次框 + 退化成安全桩 |
| 无人值守想静音 | 环境变量 `MBKIT_SILENT=1` |
| 想让它失败就退出（CI 用） | `MBKIT_FATAL_EXIT=1` |
| 想严格校验每个导出 | `MBKIT_STRICT=1` |

**关于「可复现」的严格说法**（`re/opt/cmp_e_check.py`）：

`.e`/`.ec` 的**二进制字节不可逐字节复现** —— 易语言会往里写**时间戳 / 内部 id**。
同一份文本重新 `t2e` 出来的 `.e` 与本交付件**同尺寸（293,053 B）但有 1077 字节不同**，
三次连续编译的 `.ec` 之间也各有 700~900 字节差（尺寸恒为 263,957 B）。

⇒ **判据要用「内容」而不是 md5**：把两份 `.e` 都 `e2t` 回文本再比，实测
**18 个文件里 17 个内容文件逐字节一致**，唯一不同的 `项目.etprj` 也只是
`Source` 这个路径键（那是 e2txt 自己的配置缓存，不是工程内容）。
**结论：代码层面完全可复现，二进制层的差异纯粹是元数据。**

### 4.4 顺带修掉的一个无头编译缺陷（与本模块无关，但挡过路）

无头编译要自动填易语言的「请输入欲编译到的可执行文件名：」保存框。旧实现是
「`WM_SETTEXT` 到**枚举到的第一个 `Edit`** + 点确定」，结果在真实工程上**静默失效**：
trace 显示它连续 **1155 次**报「填充成功」（路径正确、`visible=1`），但产物从未出现。

实测取证（`ELANG_AI_DLG_ONLY=1` 只扫描不填）：

```
DLG-DUMP#1 hwnd=01141366 edits=0 combos=0 btns=4      ← 刚弹出时根本没有 Edit
  id=1  cls=Button  txt='存檔(&S)'                     ← 繁中资源
  id=0  cls=DirectUIHWND par=SearchEditBoxWrapperClass
```

这是 **Vista 风格（Explorer）公共保存框** —— 文件名编辑框在 `DirectUIHWND` 里
**延迟创建**。旧代码在它还没出现时就点「存檔」，等于**拿空文件名去存** ⇒ 易语言
退回按工程名另存 ⇒ 目标已存在 ⇒ 弹繁中「確認另存新檔」覆盖确认框 ⇒ 没人回答 ⇒
模态栈不消 ⇒ 触发线程永不返回 ⇒ 编译卡到超时。

#### 文件名框到底是哪一个（最终判据）

这个保存框**不实现 `CDM_GETFILEPATH`**（恒返回空字符串），拿不到对话框自己的答案；
而且「保存位置（目录）」框与「文件名」框的**类名、控件号完全相同**，只能靠**几何位置**区分。
用独立扫描器 `re/opt/dlg_watch.py` 每 150 ms 落盘屏幕坐标，实测（`re/opt/dlg_watch.txt`）：

| 控件 | 屏幕 `top` | 宽度 | 说明 |
|---|---|---|---|
| 地址栏 | −31956 | 52 | 太窄，被宽度闸门滤掉 |
| 保存位置（目录） | −31641 | 518 | 与文件名框同宽同号 |
| **文件名** | **−31619** | **518** | ★ **最靠下的宽编辑框** |
| 按钮行 | −31541 | — | 在文件名框之下，但不是编辑框 |

⇒ 判据 = **宽 ≥ 40 的编辑框中，屏幕 y 最靠下的那个**（回读自证通过才采用）。

已修（`src/addin/elang_addin.cpp`）：

1. 收集全部候选编辑框（含父 `ComboBox`），按屏幕 y **从下往上**排；
2. 逐个 `WM_SETTEXT` 后**立即回读**，取不到文本就**拒绝点确定**（宁可超时也不写错文件）；
3. 支持 `CDM` 的对话框才用 `CDM_GETFILEPATH` 加固，不支持就走上面的几何判据；
4. 每轮先点掉「確認另存新檔」这类覆盖确认框；
5. 确认 = `WM_COMMAND(IDOK)` + `BM_CLICK` + 向输入框投 `VK_RETURN` 三连；
6. 加 `ELANG_AI_DLG_ONLY=1` 快速取证模式（只扫描、不填充）。

## 5. 已知限制

* 只 **32 位**（与本机 `node.dll` / 易语言一致）。
* MbKit 会把自己 **PIN 在进程里** ⇒ **它自身不能热更新**（业务模块可以）。
* 内嵌的是当前 `src/mbkit/MbKit.dll`（56,320 B）。**改了 MbKit 源码要重新跑
  `python re/opt/build_text.py`** 才会把新版本内嵌进去。
* 模块首次运行时会在宿主程序目录写一个 `MbKit.dll`；不想让它出现在那儿的话，
  目前只能在只读目录里跑（自动退到 `%TEMP%\ElangMbKit\`）。
