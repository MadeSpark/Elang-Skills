## 根因（e2txt 窗口属性 bug）
成员访问编码 `1d 38 <对象ID> 39 <成员序号> <所属类型> 37`。窗口自身属性时 所属类型 = 窗口ID(0x52xxxxxx)，
e2txt 当成支持库类型拆 → 库号 20994。EProjectFile 的 AccessMemberExpression 已正确处理（LibraryId=-2 分支）。

## t2e（Model/Builder.cs + Model/Binder.cs）
- Builder：系统信息 → 载库 → 模块排序 → 预留 ID → 建实体/DEP → 子实体 → 解析声明 → 窗体 → Binder 绑代码 → 组段
- ID：全局计数器，从预留值（窗口 ID、未知本地类型、占位资源）之上连续分配；主工程先，模块按 struct→method→class→dll→const→global
- Binder 实测规则：
  - 支持库命令只有 1 个参数时 `f ()` 存 1 个省略参数；用户子程序 `f ()` 存 0 个（原件两种都有，TimeStamp 347:23，按多数）
  - 窗口程序集（0x19）的子程序可在别处直接调用；`窗口名.子程序 ()` = Call(-2, m, tgt=Var(窗口ID))
  - `窗口名.程序集变量` = AccessMember(Var(窗口ID), 窗口ID, 变量ID)
  - 本窗口自引用：原件 FormSelf 与 Var(窗口ID) 混用，文本不可区分，统一 Var(窗口ID)
  - 绑定失败（如 ?DEL 已删除项）→ 未验证代码，注释/屏蔽单独保存
- EProjectFile 补丁 5：UnexaminedStatement 增 Comment，flag = 0x40 | (Mask?0x20:0)，各流程语句未验证头带注释

## P5 旁路文件（Model/Sidecar.cs，`<文本目录>/.qaq/sidecar.json`）
- e2t 默认写出，`-nosidecar` 关闭；t2e 默认读取，缺失/损坏时退回纯文本组包（等同 e2txt 目录）
- 以实体路径为键：文本里仍存在 → 沿用原 ID 与隐藏位；新增实体分配新 ID
- 子程序代码：原始字节按新工程重渲染，与文本逐行相同才沿用，否则按文本重绑（改过的代码不会被旧字节覆盖）
- 编辑信息段/未知段仅在原实体全部保留时带回；MainMethod：无旁路按 IDE 写 0，有旁路还原原值
- e2txt 差异定论：t2e 省略空段、EOF 段名按密钥异或（EofNameXored 记录）
