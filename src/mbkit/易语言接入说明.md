# 易语言接入说明 —— MbKit.dll

> 在易语言模块里用 MbKit 代替「直接调 `node.dll` + 自己注册回调 + 自己子类化」，
> 换取**业务模块可以随时卸载、重新载入而不崩**。
>
> 内核位置**默认是宿主程序（exe）所在目录**，不再要求 `main\corn`；
> 需要放别处时用 `MbKit_SetNodePath` 指定（对应易语言模块的 `WKE设置node路径`）。
> 完整查找顺序见 §7。

---

## 0. 三条必须记住的规则

1. **`.DLL命令` 的导出名不要加 `@` 前缀。**
   `@` 在易语言里表示 `__cdecl`；MbKit 是 `__stdcall`，写**裸名**。
   （对比：现有模块里 `"@wkeInitialize"` 是对的，因为 miniblink 是 cdecl。）

2. **卸载业务模块前，必须调一次 `MbKit_DetachAll ()`。**
   这是热重载契约。忘了调也不会崩（常驻层有存活校验兜底），但会留下没人管的 view。

3. **不要再用 `wkeOnPaintUpdated` 做渲染。**
   实测（本机内核 2021 build）：view 一旦 `wkeSetHandle` 绑到窗口，
   内核**自己渲染**，该回调**从不触发**（无窗口 / 离屏 / 披斗篷 / 真正可见，四种配置全为 0）。

### 事件号（回调的「事件号」参数）

| 值 | 常量 | 含义 |
|---|---|---|
| 1 | `MB_EV_PAINT` | 绘屏更新（⚠️ 实测基本不触发，见 §0 规则 3） |
| 2 | `MB_EV_LOADED` | **载入完成**（`参数1` = 0 成功 / 1 失败 / 2 取消）|
| 9 | `MB_EV_DETACH` | 常驻层正在解绑，业务侧应停止渲染 |

> `.DLL命令` 行共 6 个槽位：`名称, 返回类型, DLL文件名, DLL入口名, 公开属性, 说明`。
> 上面的写法只用了前 4 槽（行尾未用槽位可省略）。
> 若要把这些命令**对外公开**（给模块使用者调用），在第 5 槽补 `公开` 即可：
> `.DLL命令 MbKit_初始化, 整数型, "MbKit.dll", "MbKit_Init", 公开`

## 2. 事件回调写法

```易语言
.子程序 浏览器事件, , , 注意：本子程序会被 MbKit 调用，尽量短、不要弹窗
    .参数 用户数据, 整数型
    .参数 事件号, 整数型
    .参数 参数1, 整数型
    .参数 参数2, 整数型

    .判断开始 (事件号 ＝ 2)          ' MB_EV_LOADED
        .如果真 (参数1 ＝ 0)
            输出调试文本 (“页面载入完成”)
        .如果真结束
        ' 这里可以安全地读全局变量；但不要在这里卸载本模块
    .判断结束
    ' 事件号 = 1 的绘屏回调实测不触发（见 §0 规则 3）；
    ' 若将来要用于渲染，参数1 指向 MbPaintInfo { 左边, 顶边, 宽, 高, hdc } 共 20 字节
```

> 易语言子程序的调用约定就是 `__stdcall`，与 MbKit 期望的事件回调一致，
> 所以直接传 `&浏览器事件` 即可，**不需要**像 `wkeOnPaintUpdated` 那样再做
> `_stdcall_to_cdecl` 转换。

## 3. 最小可用流程

```易语言
.版本 2

.程序集变量 浏览器, 整数型

.子程序 _启动子程序, 整数型
    .局部变量 结果, 整数型

    结果 ＝ MbKit_初始化 (“”)
    .如果真 (结果 ≠ 0)
        输出调试文本 (“MbKit 初始化失败：” ＋ MbKit_最后错误 ())
        返回 (0)
    .如果真结束
    输出调试文本 (“内核：” ＋ MbKit_内核路径 ())
    输出调试文本 (“版本：” ＋ MbKit_版本 ())

    浏览器 ＝ MbKit_创建 (_启动窗口.取窗口句柄 (), 0, 0, 800, 600, &浏览器事件, 0)
    .如果真 (浏览器 ＝ 0)
        输出调试文本 (“创建浏览器失败：” ＋ MbKit_最后错误 ())
        返回 (0)
    .如果真结束

    ' HTML 属性用单引号，避免在易语言字符串里嵌套引号
    MbKit_载入页面A (浏览器, “<html><head><meta charset='gbk'><title>你好</title></head><body><h1>测试</h1></body></html>”)
    返回 (1)
```

> ① 易语言**代码里的字符串字面量用全角引号 `“ ”`**；`.DLL命令` 行里的 DLL 名 / 入口名
> 才用半角引号。两者不能混（混了会变成语法错误）。
> ② HTML 属性尽量用单引号，免得在字符串里再嵌引号。
> ③ 页面含中文时声明 `<meta charset='gbk'>`，与「文本型」的编码一致。
> 实测 `MbKit_LoadHtmlA` + `MbKit_GetTitleA` 的 GBK 中文往返**无损**。

## 4. ★ 热重载：卸载本模块前必须做的动作

```易语言
.子程序 准备卸载本模块, , 公开
    ' 1) 解绑全部浏览器：注销回调 + 解绑窗口 + 销毁 view
    MbKit_全解绑 ()
    ' 2) 之后才可以 FreeLibrary / 重新载入本模块
    '    调试期可用 MbKit_存活数量 () 确认已归零 = 0
```

拿到新版本的业务模块后，重新 `MbKit_初始化 (“”)` → `MbKit_创建 (…)` → 载入页面即可。
**内核不会重新初始化**（`MbKit_内核初始化次数 ()` 始终是 1），所以重载很轻。

### 顺序建议

| 想要的结果 | 顺序 |
|---|---|
| 只换页面内容 | `MbKit_载入页面A` 直接重载，不必卸载模块 |
| 换业务模块（改动大） | `MbKit_全解绑` → 卸载模块 → 载入新模块 → 重新创建浏览器 |
| 连内核也要换 | 只能重启宿主 exe（内核被刻意钉住以保证稳定） |

## 6. 与现有 miniblink 模块共存

* `MbKit` 会自己 `LoadLibrary` 并**钉住** `node.dll`。
  仍按老写法声明 `"main\corn\node.dll"` 的 `.DLL命令` 依然可用（内核是同一个模块实例），
  但**两套初始化会互相干扰**（一方 `wkeIsInitialize` 为真就不 init）。
  ⇒ 建议**逐步迁移**：先把「创建/销毁/载入」改成走 MbKit，
  旧的 `.DLL命令` 只保留确实需要、MbKit 暂未封装的命令（如 Cookie、下载、资源拦截）。
* 迁移时的顺序：**先让 MbKit 初始化并创建 view，再调旧模块的其他命令**（它们拿到的是同一个内核）。

## 7. 自定义内核（`node.dll`）位置

### 默认行为

`MbKit_SetNodePath` 不调用、或传空串时，按下列顺序找 `node.dll`，**第一个命中即用**：

| # | 位置 | 说明 |
|---|---|---|
| ① | 自定义路径 | 只有显式设置过才参与，见下「显式设置即契约」 |
| ② | `<宿主 exe 目录>\node.dll` | **默认位置**（宿主程序根目录） |
| ③ | `<MbKit.dll 目录>\node.dll` | 「两个文件放一起」的老布局 |
| ④ | 从宿主 exe 目录逐级上溯 ≤5 级：每级试 `\node.dll` 与 `\main\corn\node.dll` | 兼容旧工程目录结构 |
| ⑤ | `<当前工作目录>\node.dll` 与 `<当前工作目录>\main\corn\node.dll` | 兼容「相对路径」老用法 |
| ⑥ | 裸名 `node.dll` | 交系统搜索路径 |

### 显式设置即契约

```易语言
.子程序 _启动子程序, 整数型
    ' ① 必须在「内核还没加载」时设置 —— 也就是第一次 WKE初始化 / 创建浏览框之前
    .如果真 (MbKit_置内核路径 (“D:\我的内核\chromium_2021”) ＝ 0)
        信息框 (“设置内核路径失败：内核可能已经加载了”, 0, , )
    .如果真结束
    ' ② 之后照常初始化即可
    MbKit_初始化 (“”)
```

* 参数可以是**目录**（自动补 `\node.dll`），也可以是 **`node.dll` 的完整文件名**
  （想用别的文件名，如 `node_x64.dll`，就直接给完整路径）。
* **设了却没找到 → 明确报错，不会静默回退。** 这是刻意的：否则「我明明设了路径，
  跑的却是另一个内核」会变成最难查的一类问题。此时所有转发命令都会退化成安全桩
  （返回 0、不崩），并且弹一次提示框说明。
* 内核一旦加载，`MbKit_SetNodePath` 一律返回 0（进程里只能有一份内核）。

### 排查：`MbKit_自检 ()`

```易语言
输出调试文本 (指针到文本 (MbKit_自检 ()))
```

一次说清：内核状态 / 实际路径 / 自定义值 / 宿主 exe 目录 / 当前目录 /
缺失导出 / 加载期错误。**「内核为什么没加载」先看它。**

> **注①** 返回 `char*` 的命令（`MbKit_内核路径` / `MbKit_版本` / `MbKit_最后错误` /
> `MbKit_配置内核路径` / `MbKit_自检`）在易语言侧**声明成「整数型」**，
> 调用处用 `指针到文本 (…)` 转换 —— 这是本套装的既有惯例（见 `miniblink` 模块的写法）。
> 返回的静态缓冲**不要释放、不要长期持有**。

### 相关环境变量

| 变量 | 作用 |
|---|---|
| `MBKIT_SILENT=1` | 抑制失败时的提示框（无人值守 / CI 用） |
| `MBKIT_FATAL_EXIT=1` | 让 MbKit 在致命失败时 `ExitProcess(1)`（**默认不退出**，避免把宿主一起带走） |
| `MBKIT_STRICT=1` | 任何缺失导出都按致命处理（排查用） |
