# Elang-AiTools —— 易语言 AI 工具箱

让 AI（和你）能读、能写、能查易语言（`.e` / `.ec`），还能把它**跑起来看、编译成 exe**。本包成品 —— **两个 exe、四个技能、一份规范文档（外加五份专题参考）** —— 全部收在技能包里，再加三个入口脚本把技能装进本机各个 AI 工具。

| 成品 | 位置 | 干什么 |
|---|---|---|
| ① 单文件工具 | `skills/elang-ai-coding/assets/导出支持库文档.exe` | 双击或命令行即跑，导出本机全部支持库的**函数名 / 参数 / 参数备注** |
| ② 技能 | `skills/elang-ai-coding/`、`skills/e2txt-cli/`、`skills/elang-debug/`、`skills/elang-build/` | 教 AI 怎么写对易语言代码、怎么用 e2txt、怎么查支持库、怎么**调试运行并读调试输出**、怎么用**自家宿主库无头静态编译出 exe**。**符合 Agent Skills 开放规范，任何兼容工具都能读**（见 §2） |
| ③ 规范文档 | `skills/elang-ai-coding/references/易语言文本格式规范.md` | 全部**实测**得出的格式规范（编码、缩进、声明、控制流、etprj、声明槽位总表、DLL cdecl） |

> **为什么成品藏在技能目录里？** 安装技能是**整个文件夹一起拷**的。
> 把 exe 和规范放在技能**外面**，装完之后 AI 在自己技能目录里根本找不到它们 ——
> 所以技能做成**自包含**的：脚本、查命令的工具、规范全文都在技能包内，装到哪跟到哪。

```
Elang-AiTools/
├── 使用说明.md                    ← 本文件
├── 安装技能.cmd                   ← Windows 双击安装（把 skills\ 装进本机各 AI 工具）

├── install-skills.py              ← 完整安装器（跨平台；上面两个入口会转发给它）
└── skills/
    ├── elang-ai-coding/
    │   ├── SKILL.md
    │   ├── scripts/               技能自带脚本（纯标准库，Win / macOS / Linux 通吃）
    │   │   ├── mkproj.py          生成「双击 项目.etprj 就能用 GUI 打开」的工程
    │   │   ├── rtcheck.py         格式双次往返收敛自检 + 风格 lint
    │   │   └── efix.py            清命令行 t2e 误加的数组位
    │   ├── references/
    │   │   └── 易语言文本格式规范.md     成品③（规范全文）
    │   └── assets/
    │       └── 导出支持库文档.exe        成品①（32 位 Windows，零依赖）
    ├── e2txt-cli/
    │   └── SKILL.md               只管 e2txt 命令行本身
    └── elang-debug/
        ├── SKILL.md               调试技能（宿主库 + 加壳/启动脚本）
        ├── scripts/
        │   ├── mkcage.py          给 .e 加壳（声明宿主支持库；离线）
        │   └── elaunch.py         启 IDE 调试运行 + 流式收调试框 → 结果 JSON
        ├── references/            调试协议与宿主接口说明
        └── assets/
            ├── elang_addin.fne              宿主支持库（32 位 Windows）
```

> 本包只放**成品**：没有虚拟环境、没有构建中间物、没有生成物。
> exe 的 C 源码、技能脚本的开发副本都在**开发工程**里（`src\`、`tools\`、`docs\`）。
> 技能安装后，同一套文件也会出现在 `~/.agents/skills/elang-ai-coding/` 等位置。

## 1. 导出支持库命令（单 exe）

**双击 `skills\elang-ai-coding\assets\导出支持库文档.exe` 就行**（装完技能后，各 AI 工具的技能目录里也各有一份）。
它会自动定位易语言安装目录 → 扫描 `lib\*.fne` → 把结果写到 **当前工作目录**。

```bash
"导出支持库文档.exe"                        # 全自动 → 写到【当前目录】
"导出支持库文档.exe" <输出目录>              # 位置参数：写到指定目录
"导出支持库文档.exe" -o <输出目录>           # 同上（等价写法）
"导出支持库文档.exe" -l "<易语言目录>\lib"    # 手动指定支持库目录
"导出支持库文档.exe" -q                     # 静默，不打印过程也不等待回车（供脚本/AI 调用）
"导出支持库文档.exe" --json | findstr /i 取文本   # 只吐 commands.jsonl 到标准输出，不落盘
"导出支持库文档.exe" -h                     # 看用法
```

> **不给输出目录时写「当前目录」，不是「exe 所在目录」** —— 这是为 AI / 脚本调用做的设计：
> 先 `cd` 到自己的临时目录再跑，产物就落在手边、用完即删，也不用去猜 exe 装在哪。
> 双击时当前目录就是 exe 所在目录，所以文档会直接摊在那个文件夹里 ——
> 想收进子目录、或者不想把技能目录弄脏，就手动传一个目录参数：
> `导出支持库文档.exe "%USERPROFILE%\Desktop\支持库文档"`。
>
> **`--json` 是纯查询模式**：不建目录、不写文件，只把 `commands.jsonl` 打到标准输出，
> 适合 `/findstr` `/grep` 一次性查命令。
>
> **是否等待回车会自动判断**：只有 stdin 与 stdout 都挂在控制台上才等（即真人双击时），
> 管道 / 重定向调用会直接跑完退出，不会再往输出里多塞一行「按回车退出」。

> **控制台中文不会再乱码。** Windows 控制台默认代码页是 936(GBK)，而程序内部文本是 UTF-8，
> 直接把 UTF-8 字节写进控制台就会显示成「瀹屾垚: 77/77 涓敮鎸佸簱…」这种乱码。
> 现在的 exe 在输出目标是**控制台**时，会转成 UTF-16 走 `WriteConsoleW`（与代码页无关，任何 `chcp` 下都正常）；
> 输出被**重定向到文件或管道**时，则按 UTF-8 原样写出（方便 AI 与脚本读取）。
> 回归测试源码见开发工程的 `src\test_out.c`（A/B 对照：裸写字节 → 乱码；走 `WriteConsoleW` → 正常）。

产物：

| 文件 | 内容 |
|---|---|
| `索引.md` | 库清单（标识 / 名称 / 版本 / 命令数 / 说明）+ 定位方式 + 统计 |
| `命令大全.md` | 全部命令，按库分节，一个文件看全 |
| `库/<库标识>.md` | 单库详情：命令名、英文名、返回值、**参数表**（参数名 / 类型 / 修饰 / 说明）、数据类型、常量 |
| `commands.jsonl` | 一行一条命令的 JSON，**检索最快** |

单个命令长这样：

```
### 取文本中间
> 英文名 `mid` ｜ 返回值 文本型
返回一个文本，其中包含指定文本中从指定位置算起指定数量的字符

| # | 参数名 | 类型 | 修饰 | 说明 |
| 1 | `欲取其部分的文本` | 文本型 | - |  |
| 2 | `起始取出位置` | 整数型 | - | 1为首位置，2为第2个位置，如此类推 |
| 3 | `欲取出字符的数目` | 整数型 | - |  |
```

快速检索：

```bash
grep -i "取文本中间" commands.jsonl | head -3      # 在当前目录（或你指定的输出目录）里
"导出支持库文档.exe" --json | grep -i "取文本中间"   # 不落盘，查完即走
```

导出的**库数与命令数取决于你装了哪些支持库**（易语言自带的 + 你自己加的），全流程通常几秒内跑完。
exe 是 32 位、零依赖，**不需要 Python**。不预置生成物是有意的：换台机器跑一次就有了。

> **它是 32 位 Windows 程序**，macOS / Linux 上跑不了（易语言支持库 `.fne` 本身就是 32 位 DLL）。
>
> **它查不到易模块（`.ec`）。** `*.fne` 是支持库、`*.ec` 是易模块 —— 精易模块、NB模块、HP_Socket
> 这类都是 `.ec`，不在导出的支持库清单里。所以 `编码_Utf8到Unicode`、`文本_取长度ex` 这些
> **一条也查不到**。要它们的真实签名与备注，得把模块本身转成文本：
>
> ```bash
> e2txt -mode e2t -src "<你的模块>.e" -dst "<临时目录>" -level 2 -enc UTF-8 -ns 2
> grep -rn "^.子程序 编码_" "<临时目录>/代码/"
> ```
>
> 易模块源码里 `.子程序 名, 返回类型, 公开, 备注` 的第 4 个字段**就是函数备注**，参数紧随其后。
> 技能 `elang-ai-coding` §4 有完整说明。

## 2. 技能（给 AI 用）

技能都放在 `skills/` 下，目录名就是技能名。

| 技能 | 什么时候用 | 自带资源 |
|---|---|---|
| `elang-ai-coding` | 写 / 读 / 改易语言代码，查支持库命令，产出 GUI 能打开的工程；**四份专题参考**：置入代码机器码、Win32 与 DLL 互操作、程序入口与编译验证、黑月编译与黑月界面类 | `scripts/`（3 个脚本）+ `references/`（规范全文 + 四专题）+ `assets/`（导出工具 exe） |
| `e2txt-cli` | 只用 e2txt 命令行本身（转换、参数、路径坑） | 单文件 `SKILL.md` |
| `elang-debug` | 把写好的 `.e` **跑起来并读到调试输出**：加壳 → 启 IDE 调试运行 → 收日志 → 结果 JSON。**默认无头**：IDE 窗口全程不显示（`elaunch.py --visible` 可开窗口排查） | `scripts/`（2 个脚本）+ `references/` + `assets/`（宿主支持库 `.fne`） |
| `elang-build` | **不打开 IDE 把 `.e` 静态编译成原生 exe/dll**：自家宿主库链路（ecompile.py 一条命令：加壳→触发官方静态编译功能号→自动填产物对话框→收尾自证）、成功判据、排错表、程序入口提醒；**`--check` 编译即检查**（不出产物、不运行，只让易语言编译器兜底判源码语法/语义对错——弹出保存框即通过，等于"点取消"）。**默认无头**：全程不显示任何窗口；`--visible` 供人工排查 | `scripts/`（ecompile.py） |

> **`elang-ai-coding` 的 §★ 是整份技能里优先级最高的一节**（技能里就是这么标的）。
> 它讲的是易语言最容易翻车的一件事：**原生不支持 Unicode**。
> 处理 emoji / Unicode 符号要走精易模块 `编码_Utf8到Unicode` → `编码_Unicode到usc2` 转 USC2
> （`❤️` → `\u2764\uFE0F`；emoji 输出的是**一对**代理 `\uD83D\uDD25`，不是 `\U0001F525`）；
> 而 `取文本长度` 数的是**字节**（中文算 2，「你好！HelloAbcd」＝ `3×2+9` ＝ **15**），
> 精易模块的 `文本_取长度ex` 却是**字符数**（备注原文「全角汉字字符算一个长度」）——
> **两个「取长度」能差一倍，用前必须看备注。**
> 这一节的结论全部对着真实源码核对过（自带支持库导出的命令数据 + 精易模块的 `.e` 源码）。

> **技能带脚本是正常形态，不是缺陷。** Agent Skills 规范明确规定技能可以有
> `scripts/`（可执行代码）、`references/`（按需读入的文档）、`assets/`（模板等）三类附属资源；
> 从技能市场装来的 `screen-automation` 就带 4 个脚本 + 2 份 references + 图标，
> 同样是「一键安装」装进去的。那些"纯文本"技能只是恰好不需要附属文件而已。
>
> **正文里不写本机路径。** 技能会被发给别人，别人的工具装在哪儿、装了多少支持库都不一定。
> 所以技能里一律用「`<SKILL>` 技能目录」「`<ASSETS>` 技能自带工具」「`E2TXT` 环境变量 / `PATH`」这种相对说法，
> 不出现任何具体机器的绝对路径。

### 这两个技能是「开放标准」技能，不绑定任何一家工具

`SKILL.md` 是 **Agent Skills 开放规范**（[agentskills.io](https://agentskills.io)）定义的技能格式：
一份 Markdown + 顶部 YAML frontmatter。Anthropic 在 2025 年 10 月提出，同年 12 月交给社区作为
开放标准发布，现在 **40+ 种 AI 编码工具**都能直接读同一份文件。

本包两个技能严格按规范写，所以**装到哪家都能用**：

| 规范要求 | 本包的做法 |
|---|---|
| frontmatter 只有 `name` + `description`（可选 `license`/`compatibility`/`metadata`） | ✅ 只有这两个字段，不带任何厂商私有字段 |
| `name` 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，且与目录名一致 | ✅ `elang-ai-coding`、`e2txt-cli` |
| `description` 1–1024 字符，说清"何时用" | ✅ 含触发词（易语言 / e2txt / 精易模块 / Unicode / usc2 …） |
| 正文纯 Markdown，不出现某家专有的工具名 | ✅ 不写「Bash 工具」「Read 工具」这类词 |
| 技能内路径以 `SKILL.md` 所在目录为基准 | ✅ 一律写成 `scripts/xxx.py`、`assets/xxx.exe`，装到哪都不会断 |
| 脚本不依赖私有运行时 | ✅ 只用 Python 标准库，Win / macOS / Linux 通吃 |

### 安装：一个入口，装到本机所有 AI 工具

| 入口 | 适用平台 | 说明 |
|---|---|---|
| **`安装技能.cmd`** | Windows | **双击即可**。有 Python 时转发给完整安装器；没有则用内置批处理逻辑，同样能装 |
| `install-skills.sh` | macOS / Linux / Git Bash | `./install-skills.sh`，同样自适应 |
| `install-skills.py` | 任意平台 | 完整版：`--all` / `--targets` / `--project` / `--uninstall` / `--dry-run` / `--list` |

**默认是"探测式"安装**，两步：

1. **总是**装到 `~/.agents/skills/` —— 规范定义的**共享根**。DSH、Codex CLI、OpenCode、Cursor、Amp、Gemini CLI 等都会扫描它，一份文件多处生效。
2. **检测到哪个工具的家目录存在，就顺手装到它自己的技能目录** —— Claude Code 和 Trae 不读共享根，只能装自己的，这一步不能省。

安装会覆盖共享根 + 每个检测到的工具目录，**每份都逐文件校验 md5**。

| 工具 | 全局技能目录 | 认共享根 `~/.agents/skills`？ |
|---|---|---|
| **Agent Skills 规范共享根** | `~/.agents/skills/` | —（本家） |
| DeepSeek Harness (DSH) | `~/.dsh/skills/` | 认 |
| OpenAI Codex CLI | `~/.codex/skills/` | 认 |
| OpenCode | `~/.config/opencode/skills/` | 认（也扫 `~/.claude`） |
| Cursor | `~/.cursor/skills/` | 认（有兼容目录） |
| **Claude Code** | `~/.claude/skills/` | **不认**，只读自己的 |
| **Trae**（国际 / 国内） | `~/.trae/skills/`、`~/.trae-cn/skills/` | **不认**，只读自己的 |
| Windsurf | `~/.windsurf/skills/` | 未确认 |
| WorkBuddy | `~/.workbuddy/skills/` | **不认**，只读自己的 |

> 路径按各家官方文档整理；工具迭代很快，**以各自文档为准**。
> 想增删目标，改 `install-skills.py` 顶部的 `GLOBAL_TARGETS` 表即可，其余代码不用动。

**其它用法**：

```bash
python install-skills.py --list                      # 只看会装到哪，不动文件
python install-skills.py --dry-run                   # 演练
python install-skills.py --all                       # 连没装的工具目录一起装
python install-skills.py --targets claude,trae       # 只装指定工具
python install-skills.py --project <项目目录>         # 额外装进项目级目录
python install-skills.py --uninstall                 # 从这些目录移除
```

**项目级安装**（跟着仓库走，进 git 给全组用）：`--project` 会装到该项目的 `.agents/skills/`，
以及项目里已存在的各工具目录（`.claude/`、`.trae/`、`.cursor/`、`.opencode/`、`.github/skills/` 等）。

**从市场装过的同名技能不会被覆盖**：目标目录里有 `_skillhub_meta.json` 就跳过。

### 打包发给别人 / 上架市场

### 技能自带脚本的用法

下面是**在本包里**的路径；技能装好后，同一批脚本就在对应技能目录的 `scripts/` 下
（如 `~/.agents/skills/elang-ai-coding/scripts/`），命令完全一样。

```bash
PY=python                            # 任意 Python 3.9+ 均可，脚本纯标准库
S=skills/elang-ai-coding/scripts

# 生成一个「双击 项目.etprj 就能用 e2txt GUI 打开」的完整工程（并自动生成 代码.e）
$PY $S/mkproj.py "<项目目录>"
$PY $S/mkproj.py "<项目目录>" --keep      # 已有 代码/ 时只补全配置与 etprj

# 格式自检：双次往返收敛 + 风格 lint
$PY $S/rtcheck.py <文本目录>

# 清掉命令行 t2e 给局部变量误加的数组位（GUI 没有这个问题）
$PY $S/efix.py check --e 产出.e --src 文本目录     # 只读
$PY $S/efix.py apply --e 产出.e --src 文本目录     # 带往返护栏
```

三个脚本**只用 Python 标准库**，不装任何包。
它们按 **`E2TXT` 环境变量 → `PATH`** 的顺序找 e2txt，**不假定安装路径**。

### 调试技能脚本的用法（`elang-debug`）

把写好的 `.e` **跑起来并读到调试输出**，两步：

```bash
PY=python
S=skills/elang-debug/scripts

# 1) 加壳：在工程文本里声明宿主支持库（离线，不启 IDE；不碰任何 *.e.txt）
$PY $S/mkcage.py <用户.e> <产出_ai.e>
$PY $S/mkcage.py <用户.e> --json            # 结果 JSON 到 stdout

# 2) 启 IDE 打开加壳后的 .e → 触发「调试运行」→ 流式收调试框 → 结果 JSON
$PY $S/elaunch.py <产出_ai.e> --json
$PY $S/elaunch.py <产出_ai.e> --timeout 60 --stop-after 10    # 跑满 10s 主动结束
```

`elaunch.py` 结束时打出一份机器可读 JSON：

```json
{"ok":true,"status":"ok|timeout|stopped|crashed",
 "targetExitCode":0,"eExitCode":0,"runSeconds":1.2,
 "logFile":"...","panelSeen":true,"logBytes":3123}
```

- `status` **不看面板尾行**（尾行分不出“正常结束 / 被中断”，两者都是 `ExitCode:0`）：
  `crashed` = IDE 子进程**退出码 ≠ 0**（如 `0xC0000005`）；
  `stopped` = **我们主动**发过 `FN_END_RUN` 且观测到 `enabled 1→0`；
  `ok` = 自然结束；`timeout` = 超时仍未结束。
- **定位易语言**：按 **`ELANG_HOME` 环境变量 → 注册表 `HKCU\Software\FlySky\E\Install\Path`** 的顺序，找不到才报错；**不写死安装路径**。
- 纪律：只用**精确 PID** 结束进程（绝不 `/IM`）；结束清理投放的 `.fne`、对安装目录做 `diff` 自证；日志同时给 `.utf8.txt` 视图。

> ⚠️ 被调试程序**运行期异常**可能连带打挂 IDE（第三方插件 bug）——因此每个会话用**独立进程**、
> 以**子进程退出码**判定，异常程序应隔离运行。

## 4. 运行前提

| 需要 | 说明 |
|---|---|
| **Windows** | 易语言本身、e2txt、`导出支持库文档.exe`、宿主支持库 `.fne` 都是 Windows 工具（exe / fne 是 32 位） |
| **易语言**（提供 `lib\*.fne` 支持库） | 导出工具会自己顺文件关联 / 注册表 / 常见安装路径去找；找错了用 `-l` 手动指 `lib` 目录。`elang-debug` 的 `elaunch.py` 按 **`ELANG_HOME` 环境变量 → 注册表 `HKCU\Software\FlySky\E\Install\Path`** 定位安装目录 |
| **e2txt**（`.e` ⇄ 文本，作者 JimStone / 谢栋，站点 e2eeE.com） | 命令行能跑 `e2txt` 即可；不行就把它的目录加进 `PATH`，或设环境变量 `E2TXT`。技能自带脚本优先读 `E2TXT` |
| **Python 3.9+** | 只为技能自带脚本和安装器而需要（纯标准库，不用建虚拟环境）；只跑 exe 的话**完全不需要** |
| 32 位 gcc（mingw32） | **只在你重编译时才需要**：导出工具（`src/build.sh`）与宿主支持库（`src/addin/build.sh`，`ELANG_HOME` 定位 elib SDK） |

`.etprj` 的文件关联需要指向 `e2txt-gui.exe` **且带 `-prj`**，双击才打得开。
最简单的修法：在 e2txt GUI 里点「设置 → 设置文件关联(*.etprj)」，它会自己写对。
（e2txt 出厂自带的关联不可靠，有的机器上只写了 `"%1"`。）
