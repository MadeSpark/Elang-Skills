# 黑月编译与黑月界面类

> 处理「黑月/BlackMoon 编译」「黑月界面类」「黑月类模块」「Masonry 约束布局」「.rc 资源窗口」时读这篇。
> ⚠️ **先识别 API 家族，不要混用 2.x / 3.x / 第三方改版的同名方法**；不要按网络教程补全接口。
> 改编自 aiqinxuancai/e-language-skill（MIT）同名知识。

## 0. 两个层次，别混为一谈

- **黑月编译**：编译/资源/链接**后端**（`BlackMoon.fne` 接入 IDE + `BlackMoon/bin` 的 `RC.EXE/CVTRES.EXE/LINK.EXE` + `BlackMoon/lib` 的启动对象与 `krnln.lib`）。已核实发行版链接 `/ENTRY:BMEntrypoint`、`/machine:I386`——按 **x86** 验证。
- **黑月界面类**：提供 `应用程序类`、`窗口类`、控件类、布局类的**易模块**——引入模块 ≠ 用了黑月后端。

证据优先级：当前工程依赖与可编译示例 > 模块公开接口 > 黑月安装/编译日志 > 旧教程。拿不准就解包 `.e/.ec` 读 `project/.module.json`、`header/`、`src/*.txt`。

## 2. 先识别 API 家族

| 模块家族 | 接口形态 | 兼容规则 |
|---|---|---|
| `黑月界面类` 3.x | `应用程序类`、`窗口类`、`对话框类`、控件类、布局类 | 以当前 3.x 公开接口为准 |
| `黑月类模块` 2.x | 可能是 `对话框类.载入 (父窗口, 资源ID, 回调)` | 不能套用到 3.x |
| 更早 `黑月模块` | `黑月_初始化`、`DialogBoxParam` 低层封装 | 不属于现代抽象 |
| 黑月核心库/扩展模块/第三方改版 | 具体发行版决定 | 读本地声明与示例 |

## 3. 程序入口与工程类型（★ 最容易翻车的一节）

黑月界面类程序从**普通程序集的 `_启动子程序`** 启动。搭入口四步：

1. 新建 **Windows 窗口程序**（黑月编译需要窗口程序的工程类型与子系统设置）。
2. **删除默认的 `_启动窗口` 窗口程序集**——只要它还存在，易语言就优先载入它并无视 `_启动子程序`（见《程序入口与编译验证》§1）。
3. 手动新增 `_启动子程序`。
4. 在其中初始化 `应用程序类` → 注册窗口创建事件 → 创建黑月窗口 → `应用程序类.运行` 提供唯一消息循环：

```text
.版本 2

.程序集 程序集1

.程序集变量 App, 应用程序类
.程序集变量 mainFrame, 窗口类

.子程序 _启动子程序, 整数型

    App.初始化 ()
    mainFrame.事件_创建完毕 (&mainFrame_创建完毕)
    .如果真 (mainFrame.创建 (, “黑月窗口”) ＝ 假)
        返回 (-1)
    .如果真结束
    返回 (App.运行 (mainFrame))

.子程序 mainFrame_创建完毕
    .参数 hWnd, 整数型

    ' 在这里创建/绑定子控件——此时父窗口句柄才有效
```

**禁止**：
- 在 `__启动窗口_创建完毕` 或任何易语言可视化窗口事件里初始化 `应用程序类` / 调 `运行`（嵌套消息循环）。
- 保留 `_启动窗口` 却期望 `_启动子程序` 执行。
- 整个程序出现第二个消息循环。

**生命周期**：主窗口/控件/布局声明为程序集变量（别让局部包装对象早死）；创建前注册 `事件_创建完毕`；控件创建后立刻注册控件事件并按当前模块头写回调参数；可调窗口用布局类处理缩放；销毁按所有权反序。

## 4. RC 资源方案

黑月在 `.e` 旁查找**同基本名**的 `.rc`（`Demo.e` ↔ `Demo.rc`）：

1. RC 里定义对话框/控件/图标/菜单/`RCDATA`；相对资源路径必须能从 RC 编译工作目录解析（资源放工程旁 `res\` 子目录最稳）。
2. 老 RC 工具对编码敏感：中文 RC 用 **GBK/CP936**；想用 UTF-8 必须先用当前 `RC.EXE` 实测。
3. RC 的 `#define IDD_MAIN 1000` **不会**自动变成易语言常量——在工程里另建数值一致的 `#常量`。
4. `DIALOGEX` 坐标是对话框单位，不是像素。

创建窗口（3.x 非模态主对话框）：

```text
main.事件_创建完毕 (&main_创建完毕)
.如果真 (main.创建自资源 (, #IDD_MAIN) ＝ 假)
    返回 (-1)
.如果真结束
App.运行 (main)

' 创建回调里绑定子控件：
okButton.绑定 (main, #IDC_OK)
okButton.事件_被单击 (&okButton_被单击)
```

- `创建自资源` = 非模态；`载入自资源` = 模态并返回结果。
- `绑定 (父窗口, 控件ID)` 只包装 RC 已创建的子窗口，不新建控件；必须在父窗口创建完成后调用。
- 失败排查顺序：RC 是否进了输出 → ID 数值是否一致 → 实例句柄 → 资源类型是否真是对话框。

## 5. 纯代码窗口与布局

不依赖 RC：`mainFrame.创建 (, “标题”)` 后在创建完毕回调里直接创建控件。布局类（如 `布局线性类`）示例：

```text
layout.模式 (#线性布局模式_垂直)
.计次循环首 (取数组成员数 (buttons), i)
    buttons [i].创建 (mainFrame, “按钮” ＋ 到文本 (i))
    layout.插入项目 (i － 1, buttons [i], 0, 黑月矩形 (5, 5, 5, 5), )
.计次循环尾 ()
mainFrame.置布局 (layout)
```

⚠️ 易语言数组索引从 1 起，而这个版本的布局项目位置**从 0 起**（所以示例传 `i － 1`）——差异别推广到其它集合 API。

## 6. Masonry 约束布局（仅限对应改版）

标准版 3.9.6 未确认包含这些命令，只有 `黑月界面类3.9.6-Masonry约束布局-beta.2` 一类改版可用。父窗口 `布局类型 (#布局类型_约束)` 后，在创建完毕回调里逐控件建立约束，链式调用每次把返回值赋回变量，最后 `安装 ()`；全部装完调一次 `main.布局 ()`：

```text
.局部变量 make, 约束制造器

make.制造 (按钮1)
make ＝ make.左 ().等于 (main.左 ()).偏移 (12)
make ＝ make.顶 ().等于 (main.顶 ()).偏移 (10)
make ＝ make.宽 ().等于值 (160)
make ＝ make.高 ().等于值 (32)
make.安装 ()
```

锚点：`左/右/顶/底/宽/高/中心X/中心Y`；关系 `等于/大于等于/小于等于`；固定值 `等于值`；`偏移` 有符号；`倍率` 千分比（1000 = 1.0）。已有约束用 `更新`，重建用 `重建`。

## 7. 编译与链接模型、排错

流程：易语言代码 → 黑月启动对象/核心对象 → 同名 RC 编译 `.res` → CVTRES → LINK 输出 PE（`/ENTRY:BMEntrypoint`，I386）。

编译前确认：`BlackMoon.fne` 与易语言版本匹配；`bin/lib/启动对象/krnln.lib` 完整；输出类型（EXE/DLL/资源 DLL）决定启动对象；所用支持库有黑月可链接的静态库（IDE 能识别命令 ≠ 黑月链接能成功）；跑的确实是「黑月编译」而不是普通/静态编译。

验证顺序：确认模块代际 → 确认入口（无 `_启动窗口`、初始化与运行都在 `_启动子程序`）→ 核对公开接口签名 → `.e`/`.rc` 同名同目录、编码、常量一致 → 黑月编译留全输出（分别识别易语言生成错误 / RC 错误 / CVTRES 错误 / LINK 错误）→ 检查 PE 资源 → 启动实测创建/绑定/事件/缩放/关闭。**编译成功 ≠ UI 完成。**

常见错误：混用代际方法；把黑月界面类当编译器（只装模块却用普通编译验证）；RC 不同名不同目录；以为 `#define` 会同步常量；在父窗口创建前绑定控件；忘 `应用程序类.初始化`；DLL 没把实例句柄传给初始化导致从宿主 EXE 查资源；忽略 x86 限制。

## 8. 黑月 DLL 项目

```text
.子程序 Dll入口函数, 逻辑型, 公开
    .参数 DLL实例句柄, 整数型
    .参数 调用类型, 整数型
    .参数 保留, 整数型

    .判断开始 (调用类型 ＝ 1)
        全局_实例句柄 ＝ DLL实例句柄
    .默认
    .判断结束
    返回 (真)
```

- 入口里只存句柄 + 轻量初始化；**不要在加载器锁内建窗口/等线程/重 COM**。
- 真正建 UI 时 `应用程序类.初始化 (全局_实例句柄)`，否则资源可能从宿主 EXE 找。
- DLL 内模态窗口一般不需要长期 `App.运行`；非模态窗口必须明确谁提供消息循环与对象生命周期——按实际宿主场景验证，别照抄 EXE 模板。
