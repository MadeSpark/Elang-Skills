# 无 IDE 调试易语言（elang-debug）

> 本技能符合 **Agent Skills 开放规范**（agentskills.io）：只有 `name` + `description` 两个 frontmatter 字段，正文纯 Markdown，技能内路径以 `SKILL.md` 所在目录为基准。可被 Claude Code、Codex、DSH、Trae、Cursor、OpenCode 等任何兼容该规范的工具加载。

## 1. 这个技能能干什么

给它一个 `.e` 文件的路径，它就能：

1. **不打开易语言 IDE 界面**（不需要人工点「调试运行」）地对这个 `.e` 做**调试运行**；
2. 把「**调试输出窗口**」里的内容**实时、流式**拿到手 —— 效果等同于你在易语言里正常跑源码时，看到 `输出调试文本 ()` / `调试输出 ()` 打印出来的东西；
3. 同时落**原始字节证据**与 **UTF-8 转码视图**，让 AI 能直接读、能搜中文。

底层走的是**官方宿主化**方式：技能自带一个宿主支持库（`.fne`），被 `e.exe` 以**官方插件接口**加载后，用官方功能号（`FN_COMPILE_AND_RUN` 等）**反过来驱动 IDE** 编译运行。**不依赖任何第三方命令行编译器**。

> 技能分工：只做「`.e` ⇄ 文本」互转 → 用 `e2txt-cli`；只做「把易语言代码写对 / 查支持库命令」→ 用 `elang-ai-coding`。本技能管的是「**把 `.e` 跑起来、并把调试输出抓出来**」。

## 2. 前置条件（用之前先确认）

| 条件 | 说明 | 没有会怎样 |
|---|---|---|
| 装有**易语言** | 需要它的 `e.exe` 与 `lib\` 目录 | 技能无法工作 |
| 能把技能自带的 `assets/elang_addin.fne` **投放**进易语言的 `lib\` | 运行期由脚本自动投放，**用后自动移除并 `diff` 自证还原** | 面板抓不到内容 |
| `python`（3.9+，零第三方依赖，不需要虚拟环境） | 跑 `scripts/` 下的脚本 | 脚本跑不了 |

**易语言安装目录怎么找**（技能**不写死**任何机器路径）：优先读环境变量 `ELANG_HOME`；没有就读注册表 `HKCU\Software\FlySky\E\Install\Path`。

> ⚠️ **「无需打开易语言」的准确口径**：脚本**仍然会启动 `e.exe` 进程**，只是**不需要人工打开 IDE 界面、不需要人点编译**（默认后台运行）。**这不是「完全不启动易语言」，而是「不需要人操作 IDE」** —— 别向用户承诺成前者。默认无头模式下窗口**全程不显示、画不出像素**（`SW_HIDE` 启动 + 宿主库透明斗篷）；`elaunch.py --visible` 可关闭无头、正常显示窗口，供人工排查（别忘告诉用户会看到 IDE 弹出来）。

> ⚠️ **已知风险（务必告知用户）**：被调试程序若发生**运行期异常**（例如被零除），在官方宿主化路径下**可能连带把 `e.exe` 本身搞崩**（异常会走第三方 IDE 插件链路）。因此：**每个会话用独立的 `e.exe` 进程**；**可疑的异常程序要隔离运行**，不要和用户正在编辑的 IDE 混在一起。

## 3. 三步工作流

```bash
# 1) 加壳：不改用户的 .e，产出一个「库表里登记了宿主支持库」的派生 .e
python scripts/mkcage.py  <你的.e> [<输出_ai.e>]

# 2) 运行 + 抓日志：启动 e.exe、驱动调试运行、把面板内容流式落盘，最后清理
python scripts/elaunch.py <输出_ai.e> --log <日志路径>
#     （脚本同时向标准输出打印一段机器可读的 JSON 结果，见第 5 节）

# 3) 读日志：直接读 <日志路径> 与其 .utf8.txt 视图（见第 6 节）
```

`mkcage.py` 不传输出路径时，默认产出 `<原名>_ai.e`，**绝不覆盖原 `.e`**。

## 4. 加壳原理与铁律（决定成功与否）

「加壳」= 让 `e.exe` 在打开这个 `.e` 时**按需加载**我们自带的宿主支持库 `.fne`。易语言默认**不会**把新丢进 `lib\` 的库自动加载；只有当被打开的 `.e` **声明了本库**时，才会按需去 `lib\` 加载它。做法是在 `.e` 的**库表**里登记本库 —— 而库表**不是**代码文本里的某一行：

1. **改的是库表文件，不是代码文本**：加壳要改的是文本工程里的 **`配置/支持库.config.json`**（英文命名风格下是 `config/lib.config.json`）—— 它**是 `t2e` 的输入**，`t2e` 从这里读库表。**在代码文本里写一行 `.支持库 <key>` 对 `t2e` 完全无效**（已受控实验证实：只改那一行，产物与原件**逐字节相同**；把那行的 key 换成一个已安装的库，结论相同）。
2. **顺序**：先 `e2t`（此刻还没声明库）→ 改 `config/lib.config.json` → 再 `t2e`。**加壳完成后不要再 `e2t`**：一个声明了「当前没装的支持库」的 `.e` 会让 `e2t` **失败**（报 `加载支持库失败`）且**不产出**代码文本。
3. **验收双判据（缺一即失败）**：① 产物 `.e` 的 **md5 ≠ 原件**；② 产物**二进制里能找到该库 key 的 ASCII**。只满足其一不算成功。
4. **只在副本上作业**：绝不改用户原 `.e`。

> 细节、`Key` / `Guid` 怎么取、失败样例，见 `references/加壳流程.md`。

## 5. `elaunch.py` 的输出契约（机器可读）

脚本会向标准输出打印一段 JSON，供 AI 直接消费：

```json
{"ok":true,"status":"ok|timeout|stopped|crashed",
 "targetExitCode":0,"eExitCode":0,"runSeconds":1.2,
 "logFile":"...","panelSeen":true,"logBytes":3123}
```

**`status` 的判定口径（这是产品约束，判错会误导用户）**：

- ❌ **不要用输出面板的「尾行」来判**：「正常跑完」与「被我们主动中断」的面板尾行**逐字相同**（都是 `[调试] - 调试程序[pid]退出,ExitCode:0` 加 `被调试易程序运行完毕`），靠尾行分不出这两者。
- ✅ 正确口径：
  - `crashed` = `e.exe` 的调试子进程**退出码 ≠ 0**（例如 `0xC0000005` 访问违例）；
  - `stopped` = **我们主动发过** `FN_END_RUN`，且观测到运行态标志 `enabled` 由 `1` 回落到 `0`；
  - `timeout` = 超时后运行态标志仍未回落；
  - `ok` = 目标程序**自然结束**（未被我们中断、也非异常）。

其余字段：`targetExitCode` = 被调试程序退出码；`eExitCode` = `e.exe` 进程退出码；`panelSeen` = 是否读到过输出面板内容；`logBytes` = 落盘日志字节数。

## 6. 日志与编码（读中文的关键）

- 易语言**调试输出面板的文本是 GBK**。
- 脚本会同时产出两份：**原始字节证据**（原样保留，用于证明「确实抓到了」）与 **`.utf8.txt` 转码视图**。
- ⚠️ **要搜中文，一律搜 `.utf8.txt` 视图**，别拿原始 GBK 字节去搜 —— 否则你会误以为「什么都没抓到」。

读日志用 `scripts/readlog.py`：

```bash
python scripts/readlog.py <日志>             # GBK → UTF-8，打到标准输出
python scripts/readlog.py <日志> --business  # 只取「被调试程序自身」的输出行（形如 [HH:MM:SS] * …）
python scripts/readlog.py <日志> --follow    # 增量跟随（--idle / --timeout 控制空转与超时）
python scripts/readlog.py <日志> --raw       # 原始字节（不转码）
python scripts/readlog.py <日志> --json      # 结构化输出
```

> ⚠️ **要拿「程序自己打印的内容」就用 `--business`**：它只保留被调试程序输出的那一类行（`[HH:MM:SS] * …`），把 IDE 的编译 / 链接信息滤掉 —— 这正是「调试输出」里你真正要的部分。

## 7. 排查表

| 现象 | 多半原因 | 对策 |
|---|---|---|
| `e2t` 报 `加载支持库失败！[名称]…[主键]…` | 该 `.e` 依赖了**当前没装的**支持库 | 先装齐它依赖的库；或换一个不依赖该库的 `.e` |
| 加壳产物**编译失败**（面板出现编译错误行） | 源工程依赖了本机没装的库/模块，或源码本身有错 —— 这类工程**原件在本机同样编不过**，不是加壳引入的 | 按面板里的编译错误行补齐依赖 / 修码后再跑 |
| 加壳产物比原件**小了一截**（尤其内嵌 `.ec` 模块的工程） | `t2e` 把模块区重建得更紧凑，**不是内容丢失** | 正常现象；验收只看双判据（md5 变化 + 含 key ASCII），别拿体积当判据 |
| 加壳后产物 **md5 没变** | 库表 JSON 没改对（改错文件 / 改错位置 / 没落盘） | 回到第 4 节：确认改的是 `config/lib.config.json`；确认是加壳**之后**才 `t2e` |
| `status = crashed` | 目标程序**运行期异常**，**可能已带崩 `e.exe`** | 隔离重跑；先单独排查目标程序自身的异常 |
| 面板**读不到内容**（`panelSeen=false`） | `lib\` 里没放 `.fne`、或库表没登记本库 | 确认宿主 `.fne` 已投放、且加壳成功（双判据都过） |
| 中文**搜不到**但日志看着有内容 | 搜的是 GBK 原始字节 | 改搜 `.utf8.txt` 视图（第 6 节） |
| 反复出现**上一次**的日志 | 日志文件名被复用、结果被覆盖 | 日志**按运行唯一命名**（见 `references/踩坑清单.md` 第 ⑦ 条） |
