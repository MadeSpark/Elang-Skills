# 踩坑清单（宿主支持库 `.fne` 的构建与验证）

> 构建这个技能自带的宿主支持库时，踩过并已定位的坑。**全部去掉与具体机器绑定的信息，只留可复用的通用表述。**
> 前 6 条来自 PoC-1（宿主支持库骨架打通）；后 2 条来自 PoC-2（监控调试输出）。

## 构建类

1. **官方 SDK 把头文件里的 `WINAPI` 置空** ⇒ SDK 内所有函数指针都被当成 `__cdecl`。
   兼容垫片**必须把 `WINAPI` 还原为 `__stdcall`**，否则跨 DLL 回调**栈错位 → 宿主崩溃**。
   （详见 `接口与调用约定清单.md`。这是本技能最要命的一条。）

2. **`CreateThread` 的线程体必须是 `__stdcall`**。若沿用被置空的 `WINAPI` 写线程函数，会被编成
   `__cdecl` —— 行为错，且**编译器只当 warning**（被 `-fpermissive` 降级时差点漏过），务必显式写
   `__stdcall`。

3. **`windows.h` 里没有 `INT / FLOAT / DOUBLE / DATE / INT64 / PDATE`**，SDK 依赖这些类型，
   **必须自己 `typedef` 补齐**。

4. **`lib2.h` 是 C++ 专用**（含未 typedef 的联合 / 默认参数等），**必须用 `g++` 并加
   `-fpermissive`** 才能编过。

5. **他人进程的模块枚举（ToolHelp32）可能被拒（`error 5` 拒绝访问）** ⇒ **不能作为证据来源**。
   要看「库到底被没被加载 / 被没被回调」，改用**库内自检**（在 `GetNewInf` 等入口里往一个临时文件
   追加一行记录），别去枚举别人进程的模块。

## 工具 / 编码类

6. **`windres` 的 `.rc` 注释必须用 `//`，不能用 `;` 行注释**；数值常量**不要带 `L` 后缀**
   （否则资源脚本编译报错）。

## 证据管理类

7. **证据文件必须按「每次运行」唯一命名**，否则后一次运行会**覆盖前一次的物证**。
   PoC-2 阶段就因此丢过一次核心判据 —— 面板内容、trace、退出码这些东西，一律带
   时间戳 / 唯一后缀落盘，别用固定的单名文件。

8. **调试输出面板的文本是 GBK** ⇒ 单给一份原始字节，读中文会像乱码。**要同时产出
   `.utf8.txt` 转码视图**，并提醒使用者：**搜中文一律搜 `.utf8.txt`**（否则会误判成「没抓到」）。
