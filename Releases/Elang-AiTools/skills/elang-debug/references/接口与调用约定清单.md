# 跨 DLL 函数指针约定清单

> 本文件是「宿主支持库 ⇄ `e.exe`」跨边界调用的**接口约定底稿**。给技能使用者与维护者看。
> **本文件不含任何具体机器地址 / 偏移** —— 那些随 `e.exe` 版本而变、也只对某一台机器成立，**不随技能外发**；此处只保留「判据 / 现象」，并给出自行复核的方法（第 3 节）。⟨待通用化⟩

## 1. 背景纪律

官方 SDK 头文件（`mtypes.h`）把 `WINAPI` 定义成**空**（`#define WINAPI`），于是头里所有 `(WINAPI *)` 都**展开成 `__cdecl`** —— **不可信**。**实际调用约定一律以 `e.exe` 的调用行为为准**（见第 3 节复核方法），不要照头文件抄。

## 2. 清单

| 函数指针 | 所在 / 身份 | 实测约定 | 判定依据（现象） | 现状 |
|---|---|---|---|---|
| `LIB_INFO.m_pfnNotify`（`PFN_NOTIFY_LIB`） | 本库导出、**`e.exe` 回调本库** | **`__stdcall`** | `e.exe` 调用本指针后**没有 `add esp`**（期望 callee 清栈）；多个真实支持库的 notify 入口都以 **`ret $0xc`** 返回（callee 清 3 个参数） | **已证** |
| `PFN_NOTIFY_SYS`（由 `NL_SYS_NOTIFY_FUNCTION` 下发） | IDE 提供、**本库回调 `e.exe`** | **`__stdcall`** | 其函数入口末尾为 **`ret $0xc`**（callee 清 3 个参数） | **已证** |
| `GetNewInf`（`PFN_GET_LIB_INFO` / `FUNCNAME_GET_LIB_INFO`） | 本库导出、**`e.exe` 调用** | **无参**（约定对其无影响） | 无参函数，`__cdecl` / `__stdcall` 行为一致；导出名不加修饰 | **已证（不受影响）** |
| `LIB_INFO.m_pfnRunAddInFn`（`PFN_RUN_ADDIN_FN`，签名 `INT(INT)`） | 本库导出、运行时 / IDE 回调 | **待实测**（疑似 `__stdcall`） | 真实库样本有 `ret $0x4` 迹象（→ 指向 `__stdcall`），但**未定点验证，勿当结论** | **待实测** |
| `LIB_INFO.m_pfnSuperTemplate`（`PFN_SUPER_TEMPLATE`，签名 `INT(INT)`） | 本库导出 | **待实测** | 头注释写「超级模板**暂时保留不用**」；同上疑似 `ret $0x4` | **待实测** |
| `LIB_INFO.m_pCmdsFunc[]`（`PFN_EXECUTE_CMD *`） | 本库导出、运行时**逐条回调**执行命令 | **待实测** | 头定义 `void (*PFN_EXECUTE_CMD)(...)` **不带 `WINAPI`**（头里即 `__cdecl`）；**但按第 3 节规则先按 `__stdcall` 写** | **待实测**（本宿主库 `CmdCount=0`，暂不涉及） |
| `PFN_NOTIFY_PROPERTY_CHANGED` / `PFN_GET_INTERFACE` | 其它结构（**非 `LIB_INFO`**） | **待核** | 见官方 SDK 头对应处 | **待核** |

> 备注：官方 `lib2.h` 中**未见** `m_pfnGetCmdFuncName`。若后续在其它结构 / 头文件里出现，**按第 3 节的同一规则处理**。

## 3. 可执行规则与复核方法

### 规则（写进代码注释）

> **凡由 `e.exe`（或运行时）回调、或回调 `e.exe` 的函数指针，一律显式声明为 `__stdcall`；不确定时先按 `__stdcall` 写，并在调试 trace 里打印「调用前后 ESP 差」——若不为 0 即约定不符，立即排查。**

### 怎么自己复核（不依赖具体地址）

- **看调用点**：反汇编 `e.exe` 调用某个函数指针的现场，看它后面是否补 `add esp, N`。**不补** ⇒ 由 callee 清栈 ⇒ `__stdcall`。
- **看被调用方入口末尾的 `ret $N`**：`ret`（即 `ret $0`）⇒ caller 清栈（cdecl 或无参）；`ret $0xc` ⇒ callee 清 3 个 4 字节参数 ⇒ `__stdcall`。
- **交叉验证**：拿几个**已知能在 `e.exe` 里正常工作**的真实支持库 `.fne`，看它们的 notify 入口是不是 `ret $0xc`。
- **运行时自证**：在 trace 里记录每次跨界调用前后的栈指针，差值应为 0（`__stdcall`）或等于参数总字节数（`__cdecl`）。

## 4. 为什么这条最要命

把 `__cdecl` 的指针当 `__stdcall` 用（或反过来），会在跨 DLL 返回时**栈错位**，现象是 **`e.exe` 打开引用了本库的 `.e` 时直接崩溃** —— 而且这个错**非常隐蔽**：编译期不报错、库能正常 `LoadLibrary`、`GetNewInf` 也能被调用，只有在真正的回调发生时才崩。PoC 阶段确认过：**改成 `__stdcall` 后崩溃消失**。
