# B_只取链接_彻底拦截

> 模块接口与下载事件契约见 [`miniblink\使用说明.md`](..\..\..\miniblink\使用说明.md) 的 §7.7–§7.9；交付目录 2026-10-20 由 `out_mbkit\` 改名为 `miniblink\`。

**一句话**：内嵌浏览器要下载时，回调里只记下 `网址 / 文件名 / 总字节` 并 `返回 (真)`，让内核取消这次下载 —— **一个字节都不落盘**。

## 这个模板演示什么

1. **只登记一个下载回调**：`mb.事件_下载开始 (&处理_下载开始, )`。
   参数顺序固定为 `(视图, 用户数据, 网址, 文件名, 总字节)`。
   本模板**不登记** `事件_正在下载`、`事件_下载进度`、`事件_下载完成` —— 内核不会自己下载，也不会发任何进度 / 完成回调。
2. **回调体里只有三件事**：写三行日志、把窗口标题改为 `已拦截 <文件名>（<总字节> 字节）`、`返回 (真)`。
   **不调 `HTTP读文件`**、不建目录、不写文件 —— 所以本程序自己也不会落任何下载内容。
3. **`返回 (真)` 让内核取消下载**：不建临时文件、不写 `下载\`、不发进度 / 完成事件。
4. **兜底目录照样设**：`mb.置下载目录 (取运行目录 () ＋ “\下载”)`。
   它的作用不是「存到哪」，而是**当反证** —— 目录被建出来，但始终 0 个文件，说明取消真的生效了。
5. **只登记一个日志文件** `拦截记录.txt`（ANSI / GBK，追加写，本程序自己建的），内容固定三行：

   ```text
   拦截 网址=<下载链接>
   拦截 文件名=<文件名>
   拦截 总字节=<字节数>
   ```

6. **兜住弹窗**：登记了 `事件_即将创建新窗口`，把 `window.open` 的新窗口一律在同一浏览框里打开，否则下载回调收不到。

## 界面

一个窗口 + 一个「开始下载」按钮。

- 按钮名 `按钮_开始下载`，单击事件 `_按钮_开始下载_被单击` → 调 `开始下载 ()` → `mb.载入URL (网址)`。
- **启动时不访问网络**；浏览框 `图片框1` 随窗口大小自适应。

## 下载网址从哪来

1. **命令行第一个以 `http` 开头的参数**（`取命令行` + `取数组成员数`）：
   `B_只取链接_彻底拦截.exe http://127.0.0.1:8000/f.bin`
2. 否则用 `默认网址`（`__启动窗口_创建完毕` 里第二行，默认蓝奏云分享页，可能失效 —— 换成你的直链）。

## 怎么编译

```powershell
python tools\ecompile.py "demos\下载接管\B_只取链接_彻底拦截\B_只取链接_彻底拦截.e" "demos\下载接管\B_只取链接_彻底拦截\B_只取链接_彻底拦截.exe" --kind exe --headless hide
```

退出码 `0` 即成功。本次交付的产物：`.e` = 65,811 B（md5 `c53f5bdf49165f9a2298c709fbd5c86f`），`.exe` = 840,704 B（md5 `3d2b692891807c82bc78aafe21ee53e4`）。

**模块引用是绝对路径**：`.e` 里指向 本仓库的 `…\miniblink\miniblink.ec`（编译器在临时工作目录里跑，相对路径会失效）。

### ⚠️ `记录日志` 末尾那行 4 空格空行别删

该子程序最后一行是 `.如果真结束`，紧跟其后的**只有 4 个空格**的空行是块边界标记，不是排版垃圾：
把它删掉、或让编辑器「清理行尾空白」把它变成 0 缩进的空行，这份 `.e` 在易语言 IDE 里打开就会弹
**「控制块有格式错误」**；即使不弹框，红色流程线也会从块首一路画到窗口底部（2026-10-20 就是这样
交付出去的）。而 `ecompile.py --check` 照样通过、exe 照样编得出来 —— 这条缺陷只有「用 IDE 真正
打开」或「在 IDE 编辑器里 Ctrl+A/C 取控制块模型和 `e2t` 文本比对行数」才看得见。

本目录的 `.e` 已带这行空行，`.exe` 就是用它编出来的。若你从文本改完想再组回 `.e`：`t2e` 默认
（sidecar）会把纯尾部的空行规范化掉（`[警告] … 多余的空行，已忽略`），要让空行落进产物必须加
`-nosidecar`，而它会把第 3/7/8/10/11 等元信息段按文本重建 ⇒ 得到的是「程序等价的新 `.e`」，
不是原文件上加了 15 字节的字节级补丁。

## 怎么运行

1. 把 `MbKit146.dll`、`WebView2Loader.dll`（`miniblink\` 里那两份）拷到 exe **同目录**，双击；
2. 或带网址启动：`B_只取链接_彻底拦截.exe http://127.0.0.1:8000/f.bin`。

## 怎么读结果

运行目录里**只有**这些：

| 文件 / 目录 | 含义 |
| --- | --- |
| `拦截记录.txt` | 本程序的唯一产出，GBK，恰好 3 行：`拦截 网址=` / `拦截 文件名=` / `拦截 总字节=` |
| `下载\` | 被 `置下载目录` 建出来了，但**始终 0 个文件** —— 反证取消生效 |
| `mbk_diag.log` | 内核（模块）诊断日志。有 `download handed to user: <url>` = 拦截链路生效；**不应**出现 `download -> …` / `dl watch:` / `download finish(poll)` |
| `MbKitWebView2\` | WebView2 profile 缓存，内核自动建，**不是**下载内容 |

`用户下载\` 目录**根本不会出现**（本模板没有这段代码）。

实测（本地 HTTP 服务发 524,288 B 的 `f.bin`，隐藏窗口 + 真实点击按钮）：

```text
拦截 网址=http://127.0.0.1:18740/f.bin
拦截 文件名=f.bin
拦截 总字节=524288
```

- `拦截记录.txt` = 79 B，恰好 3 行，顺序正确；
- 运行目录内（排除 `MbKitWebView2\` profile）**没有任何** 524,288 B 或与载荷同 md5 的文件，也没有 `.crdownload` / `.tmp`；
- `下载\` 0 个文件，`用户下载\` 不存在；
- `mbk_diag.log`：`download handed to user` 1 行，内核自己下载的痕迹 0 行；
- CDP：`downloadWillBegin` + `net::ERR_ABORTED`，服务端只看到 1 次请求 —— 内核那次传输被真正中止，没有「先下完再丢掉」。

## 已知限制

- 提示里说「彻底拦截」，注意内核**仍会发起**那一次网络请求（下载已被交给 E 代码，随后被取消），只是**响应体不落到任何文件**；若你的场景连这一次请求都不许发，应该在导航前就拦 URL（判断后缀 / `Content-Disposition`）。
- 文件名 / 总字节只做记录，没做校验；总字节为 0 或负数时直接原样记录。
- 只拿到「下载开始」那一次回调的信息；如需重定向后的最终 URL，得自己再请求一次。

## 与 A 的一句话区别

**B 只「拦截」**：一个字节都不落盘，只要那三个参数；
**A 只「接管」**：文件真的下下来了，只是保存位置由本程序决定。
