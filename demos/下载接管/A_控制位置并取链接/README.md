# A_控制位置并取链接

> 模块接口与下载事件契约见 [`miniblink\使用说明.md`](..\..\..\miniblink\使用说明.md) 的 §7.7–§7.9；交付目录 2026-10-20 由 `out_mbkit\` 改名为 `miniblink\`。

**一句话**：内嵌浏览器要下载时，把它「接」过来 —— 保存到哪由本程序决定，同时把 `网址 / 文件名 / 总字节` 三个参数写进日志。

## 这个模板演示什么

1. **只登记一个下载回调**：`mb.事件_下载开始 (&处理_下载开始, )`。
   回调参数顺序固定为 `(视图, 用户数据, 网址, 文件名, 总字节)`，下载链接信息全部来自这里。
   本模板**不登记** `事件_正在下载`、`事件_下载进度`、`事件_下载完成` —— 所以不会有任何进度 / 完成回调。
2. **`返回 (真)` = 让内核取消它自己那次下载**（WebView2 的 DownloadStarting 取消语义）。
   所以哪怕启动时设了兜底目录 `mb.置下载目录 (取运行目录 () ＋ “\下载”)`，`下载\` 里也**永远是空的** —— 这就是「取消生效」的证据。
3. **自己下载、自己决定位置**：回调里 `数据 ＝ HTTP读文件 (网址)`（internet 支持库），再 `创建目录` + `写到文件` 存到 `取运行目录 ()\用户下载\<文件名>`。
4. **自己写日志**：`记录日志` 子程序在运行目录建 `下载日志.txt`（ANSI / GBK，追加写，文件不存在就先建空文件）。
5. **兜住弹窗**：登记了 `事件_即将创建新窗口`，把 `window.open` 的新窗口一律在同一浏览框里打开，否则浏览器类站点会绕过下载回调。

## 界面

一个窗口 + 一个「开始下载」按钮。

- 按钮名 `按钮_开始下载`，单击事件 `_按钮_开始下载_被单击` → 调 `开始下载 ()` → `mb.载入URL (网址)`。
- **启动时不访问网络**：只有点了按钮才真正发起请求（便于自动化验证「点了才有下载」）。
- 浏览框 `图片框1` 在按钮下方，随窗口大小自适应（`__启动窗口_尺寸被改变`）。

## 下载网址从哪来

按顺序取：

1. **命令行第一个以 `http` 开头的参数**（`取命令行` + `取数组成员数`），便于脚本化验证：
   `A_控制位置并取链接.exe http://127.0.0.1:8000/f.bin`
2. 否则用 `默认网址`（`__启动窗口_创建完毕` 里第二行，默认是一个蓝奏云分享页，可能已失效 —— 换成你自己的直链即可）。

## 怎么编译

```powershell
python tools\ecompile.py "demos\下载接管\A_控制位置并取链接\A_控制位置并取链接.e" "demos\下载接管\A_控制位置并取链接\A_控制位置并取链接.exe" --kind exe --headless hide
```

退出码 `0` 即成功。本次交付的产物：`.e` = 66,941 B（md5 `c8f7a1c99d67edfc9ea00354707858b9`），`.exe` = 842,240 B（md5 `55f81ae7616fc4d30ddfeece211e7ee5`）。

**模块引用是绝对路径**：`.e` 里指向 本仓库的 `…\miniblink\miniblink.ec`。
必须是绝对路径 —— 编译器在临时工作目录里跑，相对路径会失效。整个目录搬走后，用易语言 IDE 重新指定一次该模块即可。

### ⚠️ `记录日志` 末尾那行 4 空格空行别删

该子程序最后一行是 `.如果真结束`，紧跟其后的**只有 4 个空格**的空行是块边界标记，不是排版垃圾：
把它删掉、或让编辑器「清理行尾空白」把它变成 0 缩进的空行，这份 `.e` 在易语言 IDE 里打开就会弹
**「控制块有格式错误」**；即使不弹框，红色流程线也会从块首一路画到窗口底部（2026-10-20 就是这样
交付出去的）。而 `ecompile.py --check` 照样通过、exe 照样编得出来 —— 这条缺陷只有「用 IDE 真正
打开」或「在 IDE 编辑器里 Ctrl+A/C 取控制块模型和 `e2t` 文本比对行数」才看得见。

本目录的 `.e` 已带这行空行，`.exe` 就是用它编出来的。若你从文本改完想再组回 `.e`：`t2e` 默认
（sidecar）会把纯尾部的空行规范化掉（`[警告] … 多余的空行，已忽略`），要让空行落进产物必须加
`-nosidecar`，而它会把第 3/7/8/10/11 等元信息段按文本重建 ⇒ 得到的是「程序等价的新 `.e`」，
不是原文件上加了 15 字节的字节级补丁。

## 怎么运行

1. 把 `MbKit146.dll`、`WebView2Loader.dll`（`miniblink\` 里那两份）拷到 exe **同目录**，然后双击 exe；
2. 或者带网址启动：`A_控制位置并取链接.exe http://127.0.0.1:8000/f.bin`。

## 怎么读结果

运行目录里会出现这些：

| 文件 / 目录 | 含义 |
| --- | --- |
| `下载日志.txt` | 本程序写的 GBK 日志。关键行：`请求下载 <url>`（按钮真的响了）、`网址=`、`文件名=`、`总字节=`（回调拿到的下载链接信息）、`已保存=`（最终落盘路径）、`已保存 字节=` |
| `用户下载\<文件名>` | 本程序自己下载的文件，位置由本程序决定 |
| `下载\` | **空的** —— 证明 `返回 (真)` 确实让内核取消了自己的下载 |
| `mbk_diag.log` | 内核（模块）自己的诊断日志。出现 `download handed to user: <url>` = 拦截链路生效；出现 `download -> ...` / `dl watch:` 才是内核自己往盘里写 |
| `MbKitWebView2\` | WebView2 的 profile 缓存，内核自动建，**不是**下载内容 |

实测（本地 HTTP 服务发 524,288 B 的 `f.bin`，隐藏窗口 + 真实点击按钮）：

```text
网址=http://127.0.0.1:18740/f.bin
文件名=f.bin
总字节=524288
已保存=C:\...\用户下载\f.bin
已保存 字节=524288
```

- `用户下载\f.bin` = 524,288 B，md5 `3f80ecc0a725eea94d1130b01c2a6839` 与服务端一致；
- `下载\` 0 个文件；
- `mbk_diag.log`：`download handed to user` 1 行，内核自己下载的痕迹 0 行；
- CDP：`downloadWillBegin` + `net::ERR_ABORTED` —— 内核那次下载确实被取消了。

## 已知限制

- 文件名直接用内核给的名字，没做重名 / 非法字符处理；需要的话在 `目标 ＝ …` 之后加 `文件是否存在` 改名逻辑。
- `HTTP读文件` 是同步的，大文件会卡界面；需要进度就自己分块。
- 只适用于模块提供的这一个下载回调（`事件_下载开始`）；要进度得额外登记 `事件_下载进度`。

## 与 B 的一句话区别

**A 只「接管」**：文件真的下下来了，只是保存位置由本程序决定；
**B 只「拦截」**：一个字节都不落盘，只要那三个参数。
