## 1. 已 100% 确诊的根因（3 个独立问题叠加 → 综合表现为「卡死」）

所有根因都已通过 WER 事件、注册表快照、进程内存、PID 残留、SendInput 合成延迟量化验证过。**不是玄学，不是系统兼容性，是前序 AI 三条具体配置改坏了。**

### 根因 A（键鼠卡死 5-10 秒的直接元凶，连续被改回 2 次）
- **现象**：关闭易语言后，键盘/鼠标任何操作都有明显粘滞感，拖动窗口掉帧，点击按钮 1-3 秒才有反应，持续 5-10 秒才恢复。
- **确诊数值**：无 IDE 时 SendInput 延迟平均 4.2ms、最大 18.7ms；IDE 关闭期间平均 **261.5ms**、最大 **623.8ms**（是正常的 62 倍）。
- **根本配置错误**：`HKCU\Control Panel\Desktop\LowLevelHooksTimeout` 被前序 AI 改成 `25000`（25 秒！是 Windows 默认 300ms 的 83 倍）。
  - 这个值的含义：当任何全局低级键鼠钩子（LL Keyboard/Mouse Hook）挂死/响应慢时，Windows 最多等它多少毫秒才强制跳过。
  - 设成 25000 = 钩子一旦卡住，**整个系统输入可以被冻 25 秒**，用户感觉就是「卡死、键鼠动不了」。
  - 易语言 IDE 在退出阶段会卸载钩子，但如果某个 FNE 插件钩子卸载不干净，就会踩这个超时窗口。
- **必须做的正确修复（3 选 1，效果相同）**：
  1. **推荐**：直接删掉这个注册表值，让 Windows 用默认 300ms（不需要重启，**但下一次任何进程 SetWindowsHookEx 才会读新值**，所以保险起见还是建议重启或至少重登）。
  2. 明确设为 `300`（DWORD，十进制，Windows 默认值）。
  3. 设成 `100` 也可以，但 10ms 的实验版**已确认会破坏 IDE 正常退出**（20 秒退不出来），严禁写 10。
- **绝对不能再写的值**：`≥1000`（任何 ≥1 秒的设置都是在埋输入冻结的雷）。

### 根因 B（启动假死 / 新实例打不开 / 编译闪退的元凶）
- **现象**：
  - 双击 `e.exe` 后主窗口 10+ 秒不出现，或出现后无响应、点不动；
  - 编译任何工程到保存框时突然访问冲突闪退（WER 报 `c0000005 / c0000409 BEX` 在 `CeTools.dll 3.7.13.1`）；
  - 关闭 IDE 后任务管理器里还留 2-3 个 `e.exe` 尸进程，CPU 0 但占着句柄，下次启动就堵死单实例协调口。
- **确诊配置错误 1**：`D:\ides\e\lib\` 目录下**常驻了 `elang_addin.fne`**（我们自己写的无头编译 FNE）。
  - 原因：上一轮 AI 为了跑 `--check` 把 FNE 投进去后忘了删；FNE 被 IDE 每次启动都加载，又因为工程未声明 FNE 导致 WorkerProc 逻辑/消息钩子挂死在退出阶段。
  - **Hard Constraint（红线）**：`elang_addin.fne` 严禁常驻 `lib\`。正确做法 = 编译前 `Copy-Item` 临时投，编译结束 `try/finally Remove-Item` 删掉，不论成败必须清。这条已经在 ecompile.py 的投放/回收逻辑里实现过，**别再手动把 fne 复制进 lib 不删**。
- **确诊配置错误 2**：`iDraw.fne` / `CeTools.dll` 插件与当前易语言版本冲突。
  - 确诊证据：WER 中 `CeTools.dll 3.7.13.1` 同时触发 `c0000005(AV)` 与 `c0000409(BEX/缓冲区溢出检测)`；把 iDraw 隔离后编译闪退立即消失。
  - **正确做法**：如果用户需要 iDraw，先联系 iDraw 作者拿适配当前易语言版本（3713 或对应）的新版 CeTools.dll，再装；否则保持隔离（移到 `lib\_disabled\iDraw` 之类的目录）。

### 根因 C（放大器）：崩溃后僵尸 e.exe 进程对象
- **现象**：两次崩溃 PID 58552、55928 是「尸体进程对象」：`ThreadCount=0 / HandleCount=0 / WorkingSet=20KB / 无命令行`，父进程已退出但内核进程对象没收掉。
- **危害**：易语言用单实例互斥/Mailslot 协调新开实例，尸进程堵着口子 → 启动阶段主窗口迟迟不出现（看似卡死）。
- **修复**：`taskkill /F /IM e.exe` + 若顽固杀不掉就重启（重启必清）。日常可在 FNE/elaunch 启动前自动执行一次 preflight kill。

## 2. 正确修复流程（按顺序 A → B → C）

### 步骤 A：修注册表 `LowLevelHooksTimeout`（最优先，键鼠卡的根）
1. 先**备份**：`reg export "HKCU\Control Panel\Desktop" re\_rollback\eide-input-hook-timeout\desktop-before-YYYYMMDD.reg`（路径不存在就 mkdir）。
2. **直接删值**（推荐，让系统走默认 300ms）：
   ```reg
   reg delete "HKCU\Control Panel\Desktop" /v LowLevelHooksTimeout /f
   ```
   或显式设为 300：
   ```reg
   reg add "HKCU\Control Panel\Desktop" /v LowLevelHooksTimeout /t REG_DWORD /d 300 /f
   ```
3. 验证：
   ```powershell
   Get-ItemProperty "HKCU\Control Panel\Desktop" | Select-Object LowLevelHooksTimeout
   # 正确输出：要么 LowLevelHooksTimeout 字段不存在（默认=300ms），要么 = 300
   ```
4. **必须重启或至少注销一次**：这个值只在新进程首次 SetWindowsHookEx 时读取，不重启的话现有进程里的钩子还是用旧 25000。

### 步骤 B：清理 `lib\` 里的残留 FNE，隔离 iDraw
1. **严禁常驻的 FNE 清单**：
   - `D:\ides\e\lib\elang_addin.fne`：绝对不能留，编译链自动投放/回收。
   - 任何名字像 `*_ai.fne / *.fne.bak` 的手工遗留全删。
2. **保留的正版 FNE**：易语言官方自带的 `krnln.fnr / spec.fne / dp1.fne / eAPI.fne` 等原封不动；装的第三方正版插件（精易、精益等）保留。
3. **iDraw 冲突隔离**（有编译闪退就做）：
   ```powershell
   $lib = "D:\ides\e\lib"
   $quarantine = "$lib\_disabled"
   New-Item -ItemType Directory -Force $quarantine | Out-Null
   # 移 CeTools / iDraw 相关
   Get-ChildItem $lib | Where-Object { $_.Name -match "iDraw|CeTools" } | Move-Item -Destination $quarantine -Force
   ```

### 步骤 C：清僵尸 e.exe + 预启动健康检查
1. 全杀 e.exe 族：
   ```powershell
   taskkill /F /IM e.exe /T
   taskkill /F /IM ecom.exe /T 2>$null
   # 再顽固的用 WMI 兜底
   Get-WmiObject Win32_Process -Filter "name='e.exe'" | ForEach-Object { $_.Terminate() } 2>$null
   ```
2. 启动前预检查脚本（作为后续所有 elaunch/ecompile 的前置执行）：
   - 检查 `lib\` 下没有 `elang_addin.fne` 残留，有就先删再启动；
   - 检查 `LowLevelHooksTimeout` ≤ 300 或不存在，> 300 就自动回滚（并打日志告诉用户刚才又被谁改坏了）；
   - 检查现存 e.exe 数量，> 0 就先全杀。

## 3. 一键修复脚本（接手 AI 直接整段复制运行，别改参数）

把下面脚本存为 `tools\fix-eide-kb-freeze.ps1`，**右键 PowerShell 运行**，或在工作区里直接 `powershell -ExecutionPolicy Bypass -File tools\fix-eide-kb-freeze.ps1`。**它本身就是幂等的，多跑几次只会打 INFO，不会坏配置。**

```powershell
<#
.SYNOPSIS
  一键修复易语言 IDE 启动卡死、关闭后键鼠卡顿 5-10 秒、编译闪退的三条已知根因。
  幂等：反复执行只会打日志，不会坏配置。
.NOTES
  Hard Constraints:
    - LowLevelHooksTimeout 删除（默认 300ms），严禁 > 300
    - elang_addin.fne 不得常驻 D:\ides\e\lib
    - iDraw / CeTools.dll 冲突时隔离
#>
$ErrorActionPreference = "Stop"

$EHome      = "D:\ides\e"
$ELib       = Join-Path $EHome "lib"
$LogDir     = "C:\Users\MadeSpark\Desktop\测试\re\_rollback\eide-input-hook-timeout"
$Stamp      = Get-Date -Format "yyyyMMdd-HHmmss"
$LogFile    = Join-Path $LogDir "fix-run-$Stamp.log"
New-Item -ItemType Directory -Force $LogDir | Out-Null

function L($msg) {
    $line = "[$(Get-Date -Format 'HH:mm:ss')] $msg"
    Write-Host $line
    Add-Content -Path $LogFile -Value $line
}

L "=== 易语言卡死一键修复开始 ==="

# ---------- 修复 A：LowLevelHooksTimeout ----------
$regPath = "HKCU:\Control Panel\Desktop"
$valName = "LowLevelHooksTimeout"
L "[A] 检查 LowLevelHooksTimeout ..."

try {
    $cur = (Get-ItemProperty $regPath).$valName
} catch { $cur = $null }

if ($null -eq $cur) {
    L "[A]  OK  键值不存在，使用 Windows 默认 300ms。"
} else {
    L "[A]  发现键值 = $cur"
    if ($cur -gt 300) {
        L "[A]  WARN > 300（超过 Windows 默认），备份后删除。"
        $bak = Join-Path $LogDir "desktop-before-$Stamp.reg"
        & reg export ($regPath -replace 'HKCU:\\','HKCU\') $bak /y | Out-Null
        Remove-ItemProperty -Path $regPath -Name $valName -Force
        L "[A]  DONE 已删除 LowLevelHooksTimeout，恢复默认 300ms。备份：$bak"
    } else {
        L "[A]  OK  键值 = $cur ≤ 300，无需改动。"
    }
}

# ---------- 修复 B-1：lib 里残留 elang_addin.fne ----------
L "[B1] 检查 elang_addin.fne 是否常驻 lib ..."
$badFne = Join-Path $ELib "elang_addin.fne"
if (Test-Path $badFne) {
    L "[B1] WARN 发现残留 elang_addin.fne，Hard Constraint 严禁常驻！先移到备份目录再删除。"
    $bakFne = Join-Path $LogDir "elang_addin.lib-resident-$Stamp.fne"
    Copy-Item $badFne $bakFne -Force
    Remove-Item $badFne -Force
    L "[B1] DONE 已删除，备份：$bakFne"
} else {
    L "[B1] OK  lib 目录下无 elang_addin.fne 残留。"
}

# ---------- 修复 B-2：iDraw / CeTools 冲突隔离 ----------
L "[B2] 检查 iDraw/CeTools 冲突插件 ..."
$disabled = Join-Path $ELib "_disabled"
New-Item -ItemType Directory -Force $disabled | Out-Null
Get-ChildItem $ELib -File | Where-Object { $_.Name -match "iDraw|CeTools" } | ForEach-Object {
    L "[B2] WARN 发现冲突插件 $($_.Name)（WER 确诊触发 c0000005/c0000409），隔离进 _disabled"
    Move-Item $_.FullName (Join-Path $disabled $_.Name) -Force
    L "[B2] DONE  已隔离：$($_.Name)"
}
if (-not (Get-ChildItem $ELib -File | Where-Object { $_.Name -match "iDraw|CeTools" })) {
    L "[B2] OK  无 iDraw/CeTools 插件残留。"
}

# ---------- 修复 C：清僵尸 e.exe ----------
L "[C] 清理僵尸 e.exe / ecom.exe ..."
$procs = @(Get-Process e -ErrorAction SilentlyContinue) + @(Get-Process ecom -ErrorAction SilentlyContinue)
if ($procs.Count -gt 0) {
    L "[C] 发现 $($procs.Count) 个残留进程："
    $procs | ForEach-Object { L "[C]   PID=$($_.Id) Name=$($_.ProcessName) CPU=$($_.CPU) WS=$($_.WorkingSet64)" }
    taskkill /F /IM e.exe /T 2>&1 | ForEach-Object { L "[C] taskkill-e: $_" }
    taskkill /F /IM ecom.exe /T 2>&1 | ForEach-Object { L "[C] taskkill-ecom: $_" }
    Start-Sleep -Seconds 2
} else {
    L "[C] OK  无残留 e.exe / ecom.exe。"
}

# ---------- 最终报告 ----------
L "=== 修复结束 ==="
L "日志：$LogFile"
L "【必须操作】请立即重启 Windows 或至少注销再登录，LowLevelHooksTimeout 的变更才能被新钩子读取。"
L "【验收脚本】重启后执行 tools\verify-eide-kb-freeze.ps1 看 4 项全绿即可。"
```
