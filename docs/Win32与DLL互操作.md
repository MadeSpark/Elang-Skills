# Win32 与 DLL 互操作

> 调 Win32 API、声明 DLL、映射结构、写回调、做透明窗口时读这篇。
> 改编自 aiqinxuancai/e-language-skill（MIT）同名知识。

## 1. `.DLL命令` 声明流程（一步步来）

1. 确认目标**位数**（经典易语言是 32 位进程——只调 32 位 DLL）、DLL 实际路径、导出入口名。
2. 从官方头文件/文档确认原型、调用约定、返回值、错误机制。**不要根据函数名猜 `A/W` 后缀、字符宽度或结构尺寸。**
3. 把每个 C 类型映射到易语言的确切类型：`HANDLE/HWND/指针/WPARAM/LPARAM` 在 32 位下通常是 `整数型`，但这不是跨位数保证；`BOOL` 与 `逻辑型` 的映射按实际接口验证。
4. 明确每个参数是值、指针、输入输出缓冲区、字符串、结构体还是回调。
5. 确认 ANSI/Unicode 入口与终止符：`FunctionA` 收本地代码页（中文环境 = GBK）字符串，`FunctionW` 收 UTF-16。
6. 写声明，保留固定字段空槽（见《易语言文本格式规范》槽位总表）。

## 2. ⭐ 调用约定：入口名加 `@` = cdecl

- 第 4 槽 DLL 入口名**不加 `@`** → 默认按 `stdcall`（被调方清栈）。
- 目标函数确认是 `cdecl`（调用方清栈）→ **在入口名前加 `@`，前缀写在引号内**；第 1 槽的易语言命令名不加：

```text
.DLL命令 OPENSSL_init_ssl, 整数型, "libssl-4.dll", "@OPENSSL_init_ssl", , 初始化 SSL 库
    .参数 opts, 整数型
    .参数 settings, 整数型
```

调用约定必须来自头文件/官方文档/已验证声明，不能猜。

## 3. 自定义数据类型映射 C 结构

- **保持字段顺序**，不按可读性重排；核对每字段宽度、有符号性、嵌套、固定数组长度、对齐。
- `cbSize/dwSize` 一类字段填实际字节数。
- `union`、位域、可变长尾数组：不要用普通字段列表硬映射——用成熟封装或字节集手工编解码 + 测试。
- 指针指向的内存在调用期间必须有效；保存异步指针要保证所有权与生命周期。

## 4. 回调

- `&子程序名` 取地址；需要数值时按位数转换。
- 回调的参数、返回值、调用约定必须与原生声明**完全一致**。
- 原生线程触发的回调**不能直接操作 UI/非线程安全对象**——把数据投递回主线程。
- 回调期间别让承载代码/相关对象提前销毁；捕获上下文用显式句柄或索引（没有闭包）。

### 类方法不能直接当回调

裸函数地址不会自动携带类实例，`.子程序` 类方法也不应被假定可直接写成 `&对象.方法` 并符合原生 ABI。按序选方案：

1. API 有 `user_data/context/lParam` 类上下文参数 → 传稳定句柄/索引，普通程序集查表得实例。
2. 无上下文但有窗口句柄/注册标识 → 受同步保护的显式映射，注销时删除。
3. 前两条都不通、且已固定经典 Win32/x86 ABI → 才考虑动态生成回调跳板（属于机器码工程，见《置入代码与机器码》；先注销回调、等在途调用结束再释放可执行内存）。

## 5. 分层窗口与 GDI/GDI+ 画板（逐像素透明）

需要逐像素透明/阴影/自绘时：顶层窗口设 `WS_EX_LAYERED` → 内存 DC + 32 位 DIBSection 画板 → `UpdateLayeredWindow` 提交。

- 先选更新模式：逐像素 alpha 用 `UpdateLayeredWindow`；整窗透明度/颜色键用 `SetLayeredWindowAttributes`。**同一窗口不要混用**。
- 初始化顺序：保留原扩展样式再设 `WS_EX_LAYERED`（窗口样式 API 的样式参数用指针宽度类型，别把 `LONG` 硬编码成 32 位）→ GDI+ 初始化一次并保存令牌 → 兼容内存 DC + 32bpp BGRA DIB（优先负高度 top-down；校验宽高乘积防溢出）→ DIB 选入 DC 保存旧位图 → `GdipCreateFromHDC` 建 Graphics。
- **预乘 alpha**：`UpdateLayeredWindow` 的源像素每个颜色通道必须已乘以该像素 alpha。先用全透明清空画布再画；别指望 `FillRect` 替你清零 alpha；外部图像转 32bpp ARGB 并验证边缘，避免黑边。
- 提交时 `SourceConstantAlpha` 设全局 alpha、标志带 `AC_SRC_ALPHA`；检查返回值。
- **反向清理**：停重绘/解绑回调 → 销毁 Graphics/图像/画刷/画笔/字体 → 恢复旧位图 → 删 DIB → 删内存 DC → 释放目标 DC → 全局无使用者时关 GDI+。中途失败也要回滚已完成步骤；释放后句柄清零；别在位图仍被 DC 选中时删它。
- 窗口尺寸变化：重建画板并提交一次完整更新；空图像/零尺寸/超大尺寸都要有失败路径。

## 6. 线程与生命周期

- 线程/同步/网络/异步命令都是**支持库依赖 API**，不是语言固有能力；用前查签名。
- UI 对象通常只能由创建线程访问。
- 共享全局/类实例要同步——先找项目既有的锁或消息机制。
- DLL 返回的句柄/内存/文件/网络对象必须走匹配的释放函数。
- `_销毁`/窗口销毁事件/退出路径：解除回调 → 停工作线程 → 释放资源。

## 7. 互操作检查表

- [ ] 位数与调用约定正确（`@` 只加在 cdecl 的入口名上）
- [ ] DLL 名与入口名真实存在
- [ ] 返回值、错误码、`GetLastError` 时机正确
- [ ] 参数宽度、方向（值/参考）、可空性正确
- [ ] 文本编码（A/W）、缓冲区单位（字符/字节）、终止符正确
- [ ] 结构大小、对齐、数组与嵌套布局正确
- [ ] 指针/回调/异步数据的生命周期正确
- [ ] UI 更新回到正确线程
- [ ] 成功/失败/空输入/超长输入都有测试
