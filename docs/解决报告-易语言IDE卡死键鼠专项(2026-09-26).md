## 三、根因（3 个独立叠加，非单一）

### 🔴 根因 1 —— 注册表 `LowLevelHooksTimeout` 被改坏到 **25 秒**（83× 默认值）

| 项 | 内容 |
|---|---|
| 注册表位置 | `HKCU\Control Panel\Desktop\LowLevelHooksTimeout` (DWORD) |
| Windows 默认 | **不存在该键 = 默认 300 ms**；允许显式写 `300`（十进制） |
| 修前被谁改成 | 历史 AI 反复写成 `10000` / `25000`（最后一次是 25000 ms = 25 秒） |
| 为什么会冻键鼠 | 易语言 IDE、iDraw、还有宿主框架，都会挂 `WH_KEYBOARD_LL / WH_MOUSE_LL` 低级钩子做快捷键 / 脚本类功能。若钩子所在 DLL / IDE 进程在退出瞬间卡死（比如 iDraw 的崩溃路径），**Windows 会等它响应，最长等 `LowLevelHooksTimeout` ms**。写 25 秒 = 最坏 25 秒内全系统键鼠输入被「软冻结」 |

**红线（绝对禁止）**：
- 严禁写 `10ms`（已实测：会破坏 IDE 退出路径，让 iDraw 的清理逻辑被打断）
- 严禁写 `> 300`（会把冻结拉长到秒级，用户体感就是「键鼠卡死」）
- **正确写法：删除该键 = 默认 300ms**；想显式写就写 `DWORD(十进制) = 300`

### 🔴 根因 2 —— `elang_addin.fne` 常驻 `D:\ides\e\lib\`（卡死放大器）

| 项 | 内容 |
|---|---|
| 正常机制（本套装设计） | `elang_addin.fne` 是**本套装的宿主支持库**：只在 `ecompile` / `elaunch` 启动前**临时投放**到 `lib\`，IDE 进程退出时在 finally 块里**精确回收**。只有工程 `WorkerProc` 声明了它的才加载它的钩子 |
| 修前实际状态 | 历史 AI 把 `elang_addin.fne` 直接**拷进 lib 根目录常驻**，于是**每次启动任何 `.e` 工程，不管用不用宿主库，IDE 都把它加载了** → 多装了一份 WH_GETMESSAGE / 低级钩子 → 叠加根因 1 的 25 秒超时 = 「本来卡 2s，现在卡 10s」 |

### 🔴 根因 3 —— iDraw 偶发 `c0000005 / BEX` 崩溃 → 留下僵尸 `e.exe` → 占单实例互斥锁

| 项 | 内容 |
|---|---|
| 触发条件（实测复现的那台 iDraw 版本 = `3.7.13.1`） | IDE 退出瞬间 iDraw 的背景线程还在写 `About.json` / `Config.ini` + 加载 `DIYcomponent.dll(2.5MB)`，若遇到 IDE 提前 Unload → `c0000005 访问违规` / `BEX 缓冲区溢出检查失败` → WER 接管把进程挂 20-30 秒 |
| 副作用 | ① 任务管理器里留下僵尸 `e.exe`（看起来 CPU=0，但句柄没释放）；② 易语言用了**全局单实例互斥锁**；新双击 `.e` 会等互斥 → 「IDE 完全不弹、假死 20 秒」；③ 僵尸进程还持着低级钩子句柄 → 叠加根因 1 的 `LowLevelHooksTimeout = 25000` → 「键鼠彻底卡 10-25 秒」 |
| 用户对本根因的要求 | **iDraw 不要关**。所以处置 =「保留 iDraw 的装载路径、只清理僵尸进程」，不做 DLL 改名/移走 |

**为什么不是单一根因？**（交叉验证）：
- 只修根因 1（恢复注册表）：关 IDE 还是 2-3s 卡（根因 2 + 3 还在）
- 只修根因 2（清 FNE）：重启后还是有 5s 级别偶发卡（根因 1 历史值还在注册表）
- 只清根因 3（杀僵尸）：下次关 IDE 又会卡回来（根因 1 的超时门槛没降）
→ **必须三条一起修**
