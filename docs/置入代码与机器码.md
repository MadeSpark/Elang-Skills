# `置入代码` 与内嵌机器码

> 把 x86 机器码字节直接嵌进易语言编译产物的指令流。**用之前先问一句：真的需要吗？**
> 能用已验证的核心命令、支持库、`.DLL命令` 或独立 DLL 完成的事，一律优先那些可维护接口。
> 改编自 aiqinxuancai/e-language-skill（MIT）同名知识，最小示例已经过本套装静态编译链路真机实测（见 §7）。

## 1. 命令性质：编译期字节嵌入，不是运行期函数

`置入代码 (代码数据)` 属于**核心支持库**（易语言 4.12 起；之前在特殊功能支持库 `spec`）。编译器把所给**字节**原样写进当前语句对应的代码位置，程序执行到那里就是 CPU 在执行这些字节：

- 命令本身**无返回值**；结果怎么交付（寄存器、内存）由你写的机器码与所在子程序的 ABI 决定。
- 输入必须**编译期可确定**：字节型数组常量，或（部分版本支持）指向纯平面二进制文件的文件名。**不要传运行期变量**，更不存在「运行时改机器码」。
- 编译器只复制字节：不解析导入、符号、重定位。片段里引用外部符号 = 自己负责。
- 字节写法：十六进制 `90 90` → 十进制 `{ 144, 144 }`。参数位置直接写 `{ ... }` 字面量，**不要**画蛇添足写成 `到字节集 ({ ... })`（那是普通运行期参数的规则，`置入代码` 的参数是特殊编译期输入）。

## 2. 两种片段形态（先选形态再写字节）

**落回易语言代码（推荐）**：机器码干完少量工作后顺序执行后续易语言语句。
- 不写 `ret`/`leave`/未知跳转；进出片段时 `ESP` 不变；不破坏编译器还要用的寄存器、栈帧、方向标志。
- 返回由易语言自己的 `返回 (...)` 负责。

**从机器码直接返回（高危）**：机器码自己恢复栈帧、放好返回值、执行 `ret`。它接管了控制流，源码里它后面的易语言语句在该路径上**不会执行**。只有在反汇编确认了当前编译器的函数入口/参数布局/清栈责任后才可用。社区流传的 `leave; ret N` 字节串**不是通用模板**。

## 3. 经典 Win32 x86 栈帧（需要按当前产物验证的观察）

```asm
push ebp
mov  ebp, esp
; ...
mov  esp, ebp
pop  ebp
ret  N
```

该框架下返回地址常在 `[ebp+4]`、第一个参数槽 `[ebp+8]`。但这些都是**观察，不是语言保证**：`参考`/数组/文本/字节集参数可能传地址或描述符；优化会省略 EBP 帧重排一切。**需要访问参数时，先写一个签名完全相同但不含机器码的基线子程序，编译后反汇编它的调用点和函数体，再从证据推导偏移。**

片段内的硬规则：`ESP` 每进必出；不动 `EBP`（除非整个尾声由你接管）；`EBX/ESI/EDI` 用前保存；设过方向标志退出前恢复 `DF=0`；调外部函数前满足其对齐与约定。

## 4. 分支、调用与重定位（平面片段没有链接器）

- 片段内部相对短跳：汇编器可算 → 可用。
- 指向片段外地址的跳转/调用 / `call rel32` 位移 / 外部符号引用：**统统不可靠或不可用**——别把别的构建里算出的 4 字节位移抄过来。
- 想调 Win32 API：老老实实写 `.DLL命令`。确要从机器码调 → 运行期解析地址 + 完整验证约定。
- 优先写**位置无关**、只碰显式参数/缓冲区的片段；不硬编码任何绝对地址。

## 5. 生成机器码的正确流程

1. 固定目标：`x86-32`、NASM 语法、纯 `bin` 输出。
2. 写无未解析符号的最小汇编，保留**带注释的汇编源码**作为事实来源。
3. 汇编出原始字节 → 用独立反汇编器反汇编核对 → 逐字节转十进制。
4. 易语言里先放 `{ 144, 144 }`（NOP）确认置入位置，再换成真片段。
5. 编译**最终目标模式**的产物，反汇编**最终 exe**（不是中间 `.bin`），核对字节位置、前后指令、所有控制流出口。
6. 调试器里验证进出时 `ESP/EBP/非易失寄存器/返回值`；测试成功、失败、空值、边界、重复调用。

**拿不到最终产物或不能反汇编时，不许宣称机器码正确。**

## 6. `置入代码` 最小示例

```text
.子程序 机器码占位演示

    置入代码 ({ 144, 144 })    ' 90 90 = nop; nop
```

`INT 3` 的 x86 字节是 `CC`（十进制 204）：执行时触发断点异常，只用于受控调试，**绝不进交付构建**。

## 7. 本套装真机验证记录（2026-09）

验证环境：本套装自己的无头静态编译链路（`elang-build` 技能 `ecompile.py`：加壳宿主库 → IDE 进程内触发 `FN_STATIC_COMPILE_WINDOWS_CONOLE_EXE` → 产物为易语言**真实静态编译器**输出的 x86 控制台 exe）。

| 实验 | 代码 | 结果 |
|---|---|---|
| NOP 正例 | `置入代码 ({ 144, 144 })` + `标准输出` | ✅ 编译产出 exe；运行退出码 0，`标准输出` 打印 `mc-nop-ok` |
| INT3 负例 | `标准输出` → `置入代码 ({ 204 })` → 再 `标准输出` | ✅ 编译产出 exe；运行以 `0x80000003`（断点异常）终止，**after 行未输出**——证明字节在该位置真实执行 |

两条结论：① 易语言真实静态编译后端**接受并真实执行** `置入代码`；② 上游警告「机器码与后端绑定，换后端必须重验」是对的——本文规则在不同编译模式/后端下都要按 §5 重走一遍。

> 备注：`标准输出` 在静态编译产物中工作正常（需控制台子系统 + 第一参数显式给 1/2）。

## 8. 禁止做法

- 不从论坛抄十进制字节，仅凭「能编译」判断正确。
- 不把 `置入代码` 说成「运行期执行汇编源码」。
- 不用运行期变量冒充可改写的内嵌代码。
- 不硬编码别的版本里的 `[ebp+N]`、`ret N`、函数地址、call 位移。
- 不把 `.obj`/`.exe`/任意下载文件当机器码置入。
- 不在无调试器环境执行 `INT 3`，不把断点字节留在发布版。
