## 2. 本轮缺陷：小栗子真机「node内核设置失败」（用户 14:00 提供的日志）

```
[13:58:49.661] AILI·LIFE.dll   初始化miniblink
[13:58:49.667] node内核设置失败：[内存加载] 池=0x0 映像基址=0x0 状态=2 槽0=0x6C2CA880 槽259=0x6C2C4A90 / 宿主库载入失败
```

### 2.1 根因（已用源码证据钉死，不要重新排查）

诊断串来自模块生成器拼的三段：`_内存自检文本()`（`gen_module.py` 生成的 `程序集_内存映射`）+ ` / 宿主库载入失败`（`程序集_全局` 的 `WKE宿主自检`/`WKE设置node路径` 失败分支）。

- **池 = VirtualAlloc(0x50000000, 8192, RESERVE|COMMIT, RW)，固定地址**。布局：`+0x000~0x800`=槽表（260 槽，机器码 `_内存写槽/_内存读槽` = `槽号*4 + 0x50000000`，注意机器码 imm 是**十进制字节列表** `05,0,0,0,80` → 0x50000000）、`+0x800`=映射器 blob、`+0xD00`=出参·映像基址、`+0xD04`=映射错误码。
- MbKit 映像落在 0x6C2C0000 段（日志槽值 `0x6C2CA880 = 0x6C2C0000+0xCA880` 是铁证）。
- **小栗子释放业务 DLL（AILI·LIFE.dll，内含链入的 miniblink 模块）时**：模块静态变量全部复位（`_内存池/_内存基址/_内存状态` 归 0），但**进程级残留无人释放**：池 @0x50000000、MbKit 映像 @0x6C2C0000（内含内核线程 K，还活着）、node.dll（PIN）。
- 业务 DLL 重载后新实例：`_内存状态`=0 → 置 2 → `VirtualAlloc(0x50000000)` **失败**（旧池还占着同地址）→ `_内存池`=0 → 返回假 → **状态=2 永久锁死**（状态=2 = 「记住失败，不再重试」）→ 一切 WKE 命令失败。
- **「槽0/槽259 有值但池=0」的矛盾正是判据**：槽表在旧池里，值是旧实例写的（指向旧 MbKit 映像——它还活着，可以直接复用！）。

一句话：**内核层（node.dll/K 线程）的重载问题缺陷三已解决；但 MbKit 宿主库自身的「手工映射」层还留着一个同构死结——没有「复用上一实例映射物」的恢复机制。**

### 2.2 修复（已实施，`re/mbkit_mem/gen_module.py` 模板三处改动）

1. **头部布局注释**补 `+0xD08 = 重载恢复魔数 "MBK1"(0x314B424D)`。
2. **① 段**（`init_body` 里 VirtualAlloc 失败分支）：原来直接 `返回(假)`，改为恢复探测：
   ```
   .如果真 (_内存读整数 (1342180616, 0) ≠ 827408461)   ' 0x50000D08 ≠ 魔数
       返回 (假)
   .如果真结束
   _内存基址 ＝ _内存读整数 (1342180608, 0)              ' 0x50000D00 = 旧映像基址
   .如果真 (_内存基址 ＝ 0 或 _内存读整数 (_内存基址, 0) ≠ 23117 或 _内存读槽 (0) ＝ 0)
       返回 (假)                                          ' 基址处非 'MZ' 或槽表空 → 不可信
   .如果真结束
   _内存池 ＝ 1342177280                                 ' 指回旧池
   _内存状态 ＝ 1
   返回 (真)                                              ' 槽表/映像/内核全部复用，不再重映射
   ```
   魔数字节 = `{77,66,75,49}`（'M','B','K','1'），RtlMoveMemory 按字节写、`_内存读整数` 小端读 = **827408461**（= 0x314B424D）。23117 = 0x5A4D = 'MZ'。
3. **成功路径尾部**（260 个 `_内存写槽` 之后、`_内存状态＝1` 之前）：写魔数
   ```
   魔数字节 ＝ { 77, 66, 75, 49 }
   _DLL命令0A0100C1_RtlMoveMemory (1342180616, _内存取字节集指针 (魔数字节), 4)
   ```
   （局部变量 `魔数字节, 字节集` 已加进 `init_body` 声明区。）

安全性论证：魔数只在**映射完全成功后**写（失败实例基址=0/无魔数，恢复判据过不去）；池没被任何人 VirtualFree（模块静态变量复位后地址就「失传」了）⇒ 泄漏正是复用的前提；跨版本重载（旧映像+新模块）时槽值指向旧版函数——仍能工作，属已知可接受项（文档里注明即可）。

## 4. 本机操作坑（全部实测过，照做省时间）

| 坑 | 对策 |
|---|---|
| bash 对**中文文件名/路径**不稳定（sed/grep 直接 No such file） | 一律用 Python（`os.listdir` + 按子串筛文件名）读写 |
| bash heredoc 把 `\\` 换成 `//`、中文转义被搅 | 写文件用 Write/Edit 工具或 Python 脚本；正则/Windows 路径的 Python 先落盘再跑 |
| `class/` 下任何 `*.static.e.txt` 都会被 e2txt 当程序集合并 | 备份文件放 class 目录**外**，否则出双程序集（症状：编译成功但 exe 是旧代码） |
| 连续两个 `.如果真结束`/`.如果结束` 相邻 | 中间必须插一个空行（缩进同块尾），否则 IDE 流程线串线 |
| 文本工程缺 `resource/` → IDE 弹框 → 无头编译挂死 | 保留完整工程结构（reloadtest 已含） |
| e2txt 退出码恒 0 | 解析 stdout 的 `SUCC:`/`ERROR:`（GBK 输出，用 `iconv -f GBK`） |
| 无头编译会启停 e.exe（隐藏窗口），整机可能短僵死 | 已获授权；跑之前确认用户没有开着 IDE 窗口 |
| 编译工作目录会积累 | ecompile 自带 prune（留 10 个）；残留 `_wk*` 可手删（工作区内） |
