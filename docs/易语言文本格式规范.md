# 易语言代码文本格式规范

## 1. 文件与编码

| 项 | 要求 | 实测依据 |
|---|---|---|
| 首行 | 必须是 `.版本 2` | 缺此行的文本 `t2e` 产出无法被 `e2t` 解析出程序集 |
| 编码 | **UTF-8 with BOM**（`EF BB BF`） | 输入输出均带 BOM；无 BOM 时首行 `.版本` 会被吞掉 |
| 行尾 | **CRLF**（`\r\n`） | 输入 67 个 CRLF / 0 个裸 LF，回读后仍为 67 / 0 |
| 缩进 | **每层 4 个空格**，用空格不用 Tab | 见 §3 |
| 字符串引号 | **全角** `“ ”` | 半角 `"` 会被当作语法符号 |
| 运算符 | **全角**：`＋ － × ÷ ％ ＝ ≠ ＞ ＜ ≥ ≤`，逻辑 `且 或 非` | 半角 '+' 等不被识别 |
| 注释 | `'` 开头，到行尾 | — |
| **项目文件 `项目.etprj` 的编码** | **GBK，无 BOM**（与上面所有文本文件不同！） | GUI 与命令行写出的 etprj 实测均为 GBK；见 §10 |

> ⚠️ 编码不是「一律 UTF-8+BOM」。实测（样本为 e2txt GUI 生成的参考工程）：
> **UTF-8 带 BOM** —— `代码/*.e.txt`、`常量.e.txt`、`配置/*.config.json`、`窗口/*.form.json`；
> **GBK 无 BOM** —— `项目.etprj`、`资源/长文本常量.txt`、`日志/*.log`；
> 其余（`资源/*.dat`、`*.png`、`代码.e`）是二进制。
> e2txt 读 etprj 走 ANSI，写成 UTF-8+BOM 会把 `EF BB BF` 塞在 `{` 前面导致 JSON 解析失败 → **双击 etprj 打不开项目**。

## 2. 文件与目录结构（`e2t -level 2` 产物）

```
<文本目录>/
├── class/                     程序集
│   ├── xxx.static.e.txt       标准程序集
│   ├── xxx.class.e.txt        类程序集（带 .类成员 / 公开 语义）
│   ├── xxx.form.e.txt         窗口程序集
│   ├── dirs.desc.json         程序集显示顺序描述
│   └── order.list.txt         顺序表
├── module/                    被引用的模块源码，每个模块一个子目录（内含自己的 class/）
├── config/                    lib.config.json / system.config.json / user.config.json
├── form/                      窗口资源 xxx.form.json
├── resource/                  图标等资源
├── const.e.txt                常量定义
├── dll.e.txt                  DLL 命令声明
├── struct.e.txt               自定义数据类型（结构）
├── global.e.txt               全局变量
├── project.etprj              工程描述
└── icon.ico
```

**后缀决定程序集种类，不是随便起的名字**：`static` = 标准程序集，`class` = 类程序集，`form` = 窗口程序集。

> 目录名必须严格是 `class` / `config` 等；`t2e` 只认这套结构。写文本时**至少要有 `class/` 和 `config/`**，否则 `t2e` 会报错或产出空壳。
> 想省事就从已有工程 `e2t` 一次，把 `config/`、`project.etprj` 抄过来当模板。
>
> ⚠️ 上面是**不传 `-ns` 的英文风格**。**e2txt GUI 用的是中文风格**（`代码/` `配置/` `窗口/` `资源/` `常量.e.txt` `项目.etprj`），对应 `-ns 2`。两种风格的完整对照见 **§10.1**。

## 3. 缩进规则（实测逐行确认）

以「程序集」为单位，共 4 级：

| 层级 | 缩进 | 内容 |
|---|---|---|
| 0 | `0` 空格 | `.版本`、`.支持库`、`.程序集`、`.程序集变量`、`.子程序` |
| 1 | `4` 空格 | 子程序内的 **声明**（`.参数` / `.局部变量`）与 **语句**、`.如果` 等流程标记 |
| 2 | `8` 空格 | 第一层块体（`.如果` 体内、`.计次循环首` 体内） |
| 3 | `12` 空格 | 第二层块体（块中块） |

实测往返样例（左侧为原始输入，右侧为 `e2t` 回读）：

```
.子程序 综合演示, 文本型, 公开, 覆盖各类语法      ← 0
    .参数 输入文本, 文本型, , 待处理文本            ← 4
    .局部变量 局部甲, 文本型                        ← 4
                                                    ← 4（块内空行也带缩进）
    .如果 (局部乙 ＞ 0 且 可选开关)                   ← 4
        局部乙 ＝ 局部乙 ＋ 1                        ← 8
    .否则                                           ← 4
        局部乙 ＝ 局部乙 － 1                        ← 8
    .如果结束                                       ← 4
```

**关键细节：子程序体内的空行是「4 个空格」而不是真正的空行**（见上面第 4 行）。块与块之间、子程序之间用真正的空行（0 字符）。子程序末尾会补一行 4 空格。

`.参数` / `.局部变量` 声明必须紧跟 `.子程序` 行、在第一条语句之前。**不要在 `.子程序` 行后插空行**——实测 `t2e` 会把它吃掉，虽然不报错，但会让你的文本与规范形不一致。

### e2txt 的容错（会替你纠正，但别依赖）

实测 `t2e` 会自动纠正以下写法：

| 你写的 | 被改写为 |
|---|---|
| Tab 缩进 | 4 空格 |
| `甲 = "hello"` | `甲 ＝ “hello”`（半角运算符、半角引号 → 全角） |

所以写错了不一定报错，但**规范形才是你要的样子**。用 `<SCRIPTS>/rtcheck.py` 可以一次查出这两类问题。

## 4. 声明语法

### 4.1 程序集

```
.程序集 <程序集名>
```

### 4.2 子程序

```
.子程序 <名称>, <返回类型>, <公开?>, <备注?>
```

| 位 | 必填 | 说明 |
|---|---|---|
| 名称 | 是 | — |
| 返回类型 | 是 | 留空表示无返回值；写 `整数型` / `文本型` … |
| 公开 | 否 | 写 `公开` 表示公开；不写即私有 |
| 备注 | 否 | 自由文本 |

实测往返：`.子程序 综合演示, 文本型, 公开, 覆盖各类语法` → 原样保留。

### 4.3 参数

```
.参数 <名称>, <类型>, <参考?>, <可空?>, <备注?>
```

实测往返：`.参数 输入文本, 文本型, , 待处理文本`、`.参数 结果容器, 文本型, 参考 数组`、`.参数 可选开关, 逻辑型, 可空` 全部原样保留。

> 参数在任何情况下都原样往返（GUI / 命令行都正确），可以放心写。见 §7。

### 4.4 变量（局部变量 / 程序集变量）

```
.局部变量   <名称>, <类型>, <修饰?>, <数组尺寸?>, <备注?>
.程序集变量 <名称>, <类型>, <修饰?>, <数组尺寸?>, <备注?>
```

**关键：数组不是靠 `数组` 两个字表示的，是靠第 4 位有没有尺寸数字。** 这是 IDE 的原生形态（用 IDE 亲手写的 `测试.e` 核对过）。

```
.局部变量 甲, 文本型                        ← 标量
.局部变量 乙, 整数型, 静态                   ← 静态标量
.局部变量 丙, 文本型, , "0"                  ← 数组，成员数 0（第 3 位留空）
.局部变量 丁, 文本型, , "2"                  ← 数组，成员数 2
.局部变量 戊, 文本型, 静态, , 备注内容        ← 静态标量 + 备注
```

- 第 3 位 `<修饰>` 只有一个值：`静态`（可省略，但不能写别的词）。中间的空字段**不能省**——`.局部变量 丙, 文本型, , "0"` 里那个逗号必须留着。
- 第 4 位是**数组成员数**，用**半角**引号包成 `"0"`。**声明时不写这个字段，就是标量。**
- 第 5 位是备注。

> ⚠️ **不要**给局部变量写 `, 数组` 这种形式（那是**参数**的写法，见 §4.3）。实测文本写 `.局部变量 丙, 文本型` 与写 `.局部变量 丙, 文本型, 数组`，产出的 `.e` **字节完全相同** —— `数组` 两个字对局部变量根本不生效，只是会让人误读。数组要用尺寸位 `, , "0"` 表达。

> **引号有区别**：声明里的尺寸字段用**半角**引号 `"0"`；而**代码里的字符串字面量**用**全角** `“ ”`。两者不能混。

> ⚠️ 走**命令行** `e2txt.exe` 做 `t2e` 时，局部变量/程序集变量会被加上数组位（**GUI 不会**，见 §7）。命令行产出记得跑一遍 `efix.py`。

### 4.5 常量 / 数据类型 / DLL / 全局变量

分别在 `const.e.txt` / `struct.e.txt` / `dll.e.txt` / `global.e.txt`，语法与 IDE 内一致。`.支持库 <key>` 声明写在 `class/*.e.txt` 或 `global.e.txt` 里，**`t2e` 会把它消费进 `config/lib.config.json`，回读时不再出现在文本里**（实测确认）。

## 5. 控制流语法（全部实测往返一致）

| 结构 | 写法 | 分支 |
|---|---|---|
| 条件（双分支） | `.如果 (条件)` / `.否则` / `.如果结束` | 成功 ＋ 失败都有 |
| 条件（单分支） | `.如果真 (条件)` / `.如果真结束` | **只有成功分支** |
| 多重条件 | `.判断开始 (条件)` / `.判断 (条件)` / `.默认` / `.判断结束` | 成功 ＋ 失败都有 |
| 计数循环 | `.计次循环首 (次数, 循环变量)` / `.计次循环尾 ()` | — |
| 变量循环 | `.变量循环首 (起始, 结束, 步长, 循环变量)` / `.变量循环尾 ()` | — |
| 前测循环 | `.判断循环首 (条件)` / `.判断循环尾 ()` | — |
| 后测循环 | `.循环判断首 ()` / `.循环判断尾 (条件)` | — |
| 跳出 / 继续 | `跳出循环 ()` / `到循环尾 ()` | — |
| 返回 | `返回 ()` 或 `返回 (表达式)` | — |

**注意**：
- `.计次循环尾`、`.判断循环尾`、`.变量循环尾` 后面**必须带空括号 `()`**；`.判断结束` / `.如果结束` / `.如果真结束` **不带括号**（实测：原样往返）。
- 流程标记（`.如果` 等）与普通语句**同级缩进**，块体再深一级。
- **块尾之后紧接另一条块语句时，中间必须插一个空行**（空行缩进 = 前面那个块尾的缩进），
  否则 IDE 里两条块的流程线会串在一起（`.e` 里空行只是一条 19 字节的空表达式记录，多写无害）。

### 5.1 「判断」的语义（实测，最容易被 AI 写错的点）

**「判断」是 `if / else if / else` 链，不是 switch 那种「按值分派」**：

- `.判断开始 (条件)` 的条件**必须是逻辑型**。实测给整数直接编译报错：
  `错误(10044): 不能将 "整数型" 数据转换到 "逻辑型" 数据`。
- `.判断 (条件)` 挂在中间，可以有多条；**只在前面所有分支都不成立时才求值**，语义就是 C 的 `else if`。
  它后面跟的是一条**独立的布尔条件**，**不是**「与首行表达式比较的值」——
  想按取值分派，就写若干条 `.判断 (x ＝ 1)`、`.判断 (x ＝ 2)`。
- `.默认` 是 `else`（前面全不成立时走），可省略；省略后条件不成立就什么都不做。
- 「判断」与「如果」在 IDE 里画出的流程线**一模一样**（一条「判断成功」路 ＋ 一条「判断失败」路），
  区别只是「判断」能挂多个 `else if`。
- `.计次循环首` 的循环变量从 **1** 数到 **次数**（不是 0 起）；不需要循环变量时可整体留空：
  `.计次循环首 (10, )`（实测 IDE 原生写法）。

骨架（缩进每层 4 空格；`.判断` 与 `.默认` 都与 `.判断开始` 同缩进）：

```
.判断开始 (甲 ＞ 0)              ' 判断成功分支
    ...
.判断 (甲 ＝ 0)                  ' else if：前面不成立才求值
    ...
.默认                             ' else：前面全不成立（可省略）
    ...
.判断结束
```

### 5.2 遍历目录的两个实测陷阱（`寻找文件` / `取文件属性`）

1. **`寻找文件 (路径 ＋ "\*", 16)` 不是「只要子目录」**。`16 = #子目录` 只是「把子目录也放进来」，
   实测返回的是本层**全部条目**（文件也在内）。要真目录必须再过滤：
   `位与 (取文件属性 (路径), #子目录) ≠ 0`。
   而第 2 参数**留空**才是「只列文件、不含子目录」。
2. **`取文件属性` 失败返回 -1**（典型：`hiberfil.sys` / `pagefile.sys` 这类被系统独占的文件），
   而 `位与 (-1, 16) ≠ 0` 恒成立 —— 不过滤就会把它们误判成目录。必须先判断 `属性 ≠ -1`。
3. 另外 `寻找文件` 的迭代位置记在**子程序**上，**边找边递归**会被内层调用冲掉状态（漏项 / 提前结束且不报错）。
   安全写法是「先把本层收进数组，再递归」。

## 6. 表达式与调用

```
局部甲 ＝ 子文本替换 (局部甲, “你”, “您”, , , 真)
局部乙 ＝ 局部乙 ÷ 2 ％ 7
.计次循环首 (5, 局部乙)
```

- 命令调用：`命令名 (参数1, 参数2, ...)`，**命令名与左括号之间有一个空格**。
- 参数留空表示省略：`, , ,` （连续逗号，逗号后各带一个空格）。
- 逻辑值写 `真` / `假`。
- 数组下标用**半角方括号**：`数组变量 [1]`（注意易语言此处用半角）。
- 赋值用全角 `＝`。

## 7. GUI 与命令行行为不一致：`e2txt.exe` 会给局部变量加数组位（GUI 不会）

### 一句话结论

**两个可执行文件的 `t2e` 结果不一样**，用哪个决定了要不要修：

| 工具 | 产出体积 | 局部变量 flags | `e2t` 回读 |
|---|---|---|---|
| `e2txt-gui.exe`（图形界面） | 3133 B | `0x00`，与 IDE 原生一致 | 干净 ✅ |
| `e2txt.exe`（命令行） | 2562 B | 无条件多一个 `0x08` | 每个局部变量都多出 `, 数组` ❌ |

把**同一个文本目录**（GUI 生成的参考工程）分别喂给两者，对 `i` 的声明记录逐字节对拍：

```
文本：  .局部变量 i, 整数型
GUI ：  aa 32 00 | 0a 00 00 00 | 01 03 00 80 | 00 00 00 | 69 00 ...   flags = 0x00  ✅
CLI ：  aa 32 00 | 0a 00 00 00 | 01 03 00 80 | 08 00 00 | 69 00 ...   flags = 0x08  ❌
```

### 受影响范围（仅命令行侧）

| 种类 | 是否被加 bit3 |
|---|---|
| 参数 | 否 —— `参考` / `可空` / `数组` 全部正确 |
| 局部变量 / 程序集变量 | **是，一个不漏** |

`测试.e` 实测：参数 6/6 正确；局部变量 4/4 全中（`静态变量` `0x01`→`0x09`，`数组变量_0`、`数组变量_1`、`i` `0x00`→`0x08`）。

### 为什么局部变量根本不需要 bit3

IDE 亲手写出的 `数组变量_0`（成员数 0）和 `数组变量_1`（成员数 2），flags 都是 `0x00` —— **局部变量的数组属性由尺寸块表达，bit3 只服务于参数**。所以命令行给局部变量加的 bit3 是纯噪声。

### 规避办法

1. **能用 GUI 就用 GUI** —— 产出与 IDE 原生一致，不用修。
2. 必须走命令行（自动化场景）时，`t2e` 之后跑一遍 `efix.py`：

```bash
$PY <SCRIPTS>/efix.py check --e 产出.e --src 文本目录   # 只读，先看范围
$PY <SCRIPTS>/efix.py apply --e 产出.e --src 文本目录   # 只清 bit3，带往返护栏
```

实测：对命令行产物 `g1.e` 检出 4 条污染 → 修补后 `e2t` 回读文本，**与 GUI 产物的回读文本逐字节一致**。

### 已试过但无效的命令行参数

`-level 0/1/2`、`-ns 0/2`、`-nr`、`-e`、`-async`、`-log`、`-debug-source`，以及把 `project.etprj` 的 `Source` 清空 —— **全部照样带 bit3**。没有参数开关能规避，只能事后修。

### 记录级依据（布局已用 GUI 产物与 IDE 原件双向校准）

```
u32 总长            = 9 + 4*(有尺寸块) + 名字字节数 + 备注字节数
u32 数据类型        0x8000_000n = 系统类型   n: 1 字节型 2 短整数 3 整数 4 长整数
                                            5 小数 6 双精度 7 逻辑 8 日期时间
                                            9 文本 10 字节集 11 子程序指针
u8  标志            bit0 = 静态，bit1 = 参考（参数），bit2 = 可空（参数），bit3 = 数组（参数）
u8  0
u8  有尺寸块         0/1
[u32 数组尺寸]       仅当「有尺寸块」= 1
char 名字[]         GBK，以 \0 结尾
char 备注[]         GBK，以 \0 结尾
```

`静态变量` 的记录总长 133 = 4+3+8+1+116+1，备注正好是那 58 个汉字的 116 字节。

2. **误判原因**：当时拿 **GUI 产出的 `代码.e`** 去做验证，而 GUI 恰恰是干净的一方，于是"验证通过"，反而离真相更远。
3. **第三版（本版）**：把**同一份文本目录**分别喂给 GUI 和 CLI 直接对拍，差异一眼可见。
4. 顺带钉死一个曾被写反的说法：「IDE 原件的变量声明被 `t2e` 改了 flags」。事实是 `测试.e`（IDE 原件）与 **GUI** 产出 `代码.e` 的**前 1483 字节逐字节完全相同**（全部变量声明记录都在这一段）；改 flags 的是 **CLI**。

**教训**：比对之前先确认基准是哪一侧产出的。拿 A 的产物去证明 B 的现象不存在，是最容易犯的错。

## 8. 往返保真度基线

| 指标 | 结果 |
|---|---|
| 文本层 `e2t → t2e → e2t` | **无损**。`测试.e` 两轮文本（含 `排序.list.txt`）md5 完全一致：`d37b0e83426b3bd130ab10177f093421` |
| 字节层 原始 `.e` vs 回写 `.e` | **不逐字节相同**。GUI：3137 → 3133 B，差异集中在内部索引表的排序与 4 字节校验值，变量声明区不受影响 |
| 命令行回写 | 体积明显偏小（3133 → 2562 B）且带 bit3，见 §7 |

> **永远不要用回写产物覆盖原始 `.e`**。文本往返无损，字节层不是 —— 原件永远单独留一份。

## 9. 两个 `t2e` 的路径坑（实测）

### 9.1 `-dst` 的父目录必须先存在，否则静默不产出

`t2e` 不会替你创建 `-dst` 的父目录。父目录不存在时它**既不报错也不产出**（连 `[错误]` 都没有），只在 e2txt 自身目录下留一个同名空文件夹：

```bash
# 反例：out/zztest/ 不存在
e2txt -mode t2e -src <文本目录> -dst <...>/out/zztest/p1.e
#   → 没有任何输出文件；e2txt 自己目录下会多出一个空的 zztest\

# 正例：先建目录
mkdir -p out/zztest && e2txt -mode t2e -src <文本目录> -dst <...>/out/zztest/p1.e
#   → out/zztest/p1.e ✓
```

### 9.2 `t2e` 会在 e2txt 自己目录里建同名空目录

不管成功与否，`t2e` 都会在 **e2txt 自己的目录**下建一个与「`-dst` 父目录名」同名的**空**目录。
无害，但反复跑会把工具目录弄脏（本次开发就攒了 20+ 个 `rtcheck_*`）。
`rtcheck.py` 和 `mkproj.py` 都已加自动清理（只删空目录）；手写命令行时记得自己看一眼。

### 9.3 `-src` / `-dst` 都要给绝对路径

传相对路径（例如 `-src <项目目录>/代码.e`）会直接报 `ERROR:来源文件不存在`，即使工作目录正确。
一律用绝对路径，别省事。

## 10. 项目文件 `项目.etprj` 与命名风格

### 10.1 两种命名风格由一个开关决定

`e2t` / `t2e` 都接受 `-ns`：**不传 = 英文风格；`-ns 2` = 中文风格**。两者是同一套结构的两种叫法，文件名必须成对匹配，混用会让工具以为文件全丢了。

| 英文风格（默认） | 中文风格（`-ns 2`，**e2txt GUI 用的就是这套**） |
|---|---|
| `class/` | `代码/` |
| `class/order.list.txt` | `代码/排序.list.txt` |
| `config/` | `配置/` |
| `config/lib.config.json` | `配置/支持库.config.json` |
| `config/user.config.json` | `配置/用户.config.json` |
| `config/system.config.json` | `配置/系统.config.json` |
| `form/` | `窗口/` |
| `resource/` | `资源/` |
| `const.e.txt` | `常量.e.txt` |
| `project.etprj` | `项目.etprj` |

**给 GUI 用的工程一律用中文风格**。`rtcheck.py` 会按目录里有没有 `代码/` 自动判断并补上 `-ns 2`，不用手动传。

### 10.2 `项目.etprj` 的格式（GUI 实测产物）

**GBK 编码、无 BOM、CRLF**。GUI 与命令行写出来的都是 GBK —— 这不是我能选的，e2txt 就是按 ANSI 读它。

键集固定 14 个：

```json
{
    "AsyncFile": false,
    "Dest": "",
    "E2TXT-EFile": "",
    "E2TXT-InSourceDir": true,
    "E2TXT-IsCreateE": true,
    "Encoding": "UTF-8",
    "Level": 1,
    "NameStyle": 2,
    "Password": "",
    "ResetNames": [],
    "Source": "代码.e",
    "TXT2E-CreateLog": false,
    "TXT2E-EFile": "",
    "TXT2E-InSourceDir": false
}
```

| 键 | 含义 / 取值 |
|---|---|
| `Encoding` / `Level` / `NameStyle` | 文本编码 / 转换级别 / 命名风格（`2` = 中文），对应命令行 `-enc` / `-level` / `-ns` |
| `Source` | **E转TXT** 的源 `.e`，**相对项目文件所在目录**。`.e` 在项目目录里就是 `代码.e`；在上一级就是 `../xx.e`（GUI 写的参考工程就是这种） |
| `E2TXT-InSourceDir` / `E2TXT-IsCreateE` / `E2TXT-EFile` | E转TXT 侧的输出位置/是否生成 |
| `Dest` / `TXT2E-EFile` / `TXT2E-InSourceDir` / `TXT2E-CreateLog` | TXT转E 侧的目标。GUI 写的参考工程里 `Dest` 与 `TXT2E-EFile` 都是**空** |
| `Password` / `ResetNames` / `AsyncFile` | 加密口令 / 重置名列表 / 异步写文件，默认空 |

### 10.3 用命令行生成项目时的写序（踩过）

命令行 `t2e` **会顺手重写 `<文本目录>\项目.etprj`**，而且只保留 4 个 `TXT2E-*` 键，`E2TXT-*` 那批全丢、`Dest` 被写成绝对路径。

所以：**先跑 `t2e` 生成 `.e`，再写 `项目.etprj`**；写的时候做「保留已有值 + 补齐缺失键」的合并，别无脑覆盖（用户可能在 GUI 里改过字段）。`tools/mkproj.py` 已按这个顺序实现。

### 10.4 双击 `.etprj` 能被 GUI 打开的完整条件

1. 目录是中文风格（`代码/`、`配置/`、`常量.e.txt`）。
2. `项目.etprj` 存在且是 GBK 无 BOM。
3. `.etprj` 的文件关联指向 `e2txt-gui.exe` **且命令行带 `-prj "%1"`**：

   ```
   HKCU\SOFTWARE\Classes\Applications\e2txt-gui.exe\shell\open\command
       = "<e2txt 所在目录>\e2txt-gui.exe" -prj "%1"
   ```

   并且 `HKCU\...\FileExts\.etprj\UserChoice` 的 `ProgId = Applications\e2txt-gui.exe`。
   ⚠️ e2txt **出厂自带的关联不可靠**：有的机器上 `HKCU\...\Applications\e2txt-gui.exe` 的命令只写了 `"%1"`（漏掉 `-prj`），而 `HKCR\...` 那份甚至指向打包者自己的开发机路径。所以「双击打不开」时，先查这两处。

`-prj` 的作用是**把项目文件所在目录设为「TXT转E」的源目录**（不是填「E转TXT」的源）。
