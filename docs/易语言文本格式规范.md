> 本文所有结论均为**实测**得出，非推测。验证方法：自造文本 → `t2e` 转 `.e` → `e2t` 转回文本 → 逐字节/逐行比对；并对照易语言 IDE 原生写出的 `.e`（易语言安装目录 `samples\*` 里的官方例程、以及把 IDE 里随手写的窗口程序存成 `.e`）。
> 验证脚本见 `<SCRIPTS>/rtcheck.py`（双次往返收敛自检 + 风格 lint）、`<SCRIPTS>/efix.py`（`t2e` 产物变量数组位的**只读**核对 —— 只用来 `check`，**不要 `apply`**，见 §7）。
>
> 下文 `<SCRIPTS>` 指 `elang-ai-coding` **技能自带的脚本目录** —— 即该技能目录下与 `SKILL.md` 同级的 `scripts/`（Agent Skills 规范要求技能内路径以 SKILL.md 所在目录为基准）。

# 易语言代码文本格式规范

## 1. 文件与编码

| 项 | 要求 | 实测依据 |
|---|---|---|
| 首行 | 必须是 `.版本 2` | 缺此行的文本 `t2e` 产出无法被 `e2t` 解析出程序集 |
| 编码 | **UTF-8 with BOM**（`EF BB BF`） | 输入输出均带 BOM；无 BOM 时首行 `.版本` 会被吞掉 |
| 行尾 | **CRLF**（`\r\n`） | 输入 67 个 CRLF / 0 个裸 LF，回读后仍为 67 / 0 |
| 缩进 | **每层 4 个空格**，用空格不用 Tab | 见 §3 |
| 字符串引号 | **全角** `“ ”` | 半角 `"` 会被当作语法符号 |
| 运算符 | **全角**：`＋ － × ÷ ％ ＝ ≠ ＞ ＜ ≥ ≤`，逻辑 `且 或 非` | 半角 '+' 等不被识别 |
| 注释 | `'` 开头，到行尾 | — |
| **项目文件 `项目.qtprj` 的编码** | **GBK，无 BOM**（与上面所有文本文件不同！） | QAQ-ETool `e2t` 写出的 qtprj 实测为 GBK；见 §10 |

> ⚠️ 编码不是「一律 UTF-8+BOM」。实测（QAQ-ETool `e2t -ns 2` 的产物）：
> **UTF-8 带 BOM** —— `代码/*.e.txt`、`常量.e.txt` 等 `*.e.txt`、`配置/*.config.json`、`窗口/*.form.json`、`*.desc.json`；
> **GBK 无 BOM** —— `项目.qtprj`、`资源/<常量名>.txt`（长文本常量的原始字节）；
> 其余（`资源/*.dat`、`*.png`、`图标.ico`、`代码.e`）是二进制。
> 按 ANSI 读项目文件的工具遇到 UTF-8+BOM 会把 `EF BB BF` 塞在 `{` 前面导致 JSON 解析失败，所以 qtprj 一律写 GBK 无 BOM。

## 2. 文件与目录结构（`e2t -level 2` 产物）

```
<文本目录>/
├── class/                     程序集
│   ├── xxx.static.e.txt       标准程序集
│   ├── xxx.class.e.txt        类程序集（带 .类成员 / 公开 语义）
│   ├── xxx.form.e.txt         窗口程序集
│   ├── dirs.desc.json         程序集显示顺序描述
│   └── order.list.txt         顺序表
├── module/                    被引用的模块源码，每个模块一个子目录（内含自己的 class/）
├── config/                    lib.config.json / system.config.json / user.config.json
├── form/                      窗口资源 xxx.form.json
├── resource/                  图标等资源
├── const.e.txt                常量定义
├── dll.e.txt                  DLL 命令声明
├── struct.e.txt               自定义数据类型（结构）
├── global.e.txt               全局变量
├── project.qtprj              工程描述（用 qaq-etool-gui.exe 打开）
└── icon.ico
```

**后缀决定程序集种类，不是随便起的名字**：`static` = 标准程序集，`class` = 类程序集，`form` = 窗口程序集。

> 目录名必须严格是 `class` / `config` 等；`t2e` 只认这套结构。写文本时**至少要有 `class/` 和 `config/`**，否则 `t2e` 会报错或产出空壳。
> 想省事就从已有工程 `e2t` 一次，把 `config/`、`project.qtprj` 抄过来当模板。
>
> ⚠️ 上面是**不传 `-ns` 的英文风格**。**本套技能的项目一律用中文风格**（`代码/` `配置/` `窗口/` `资源/` `常量.e.txt` `项目.qtprj`），对应 `-ns 2`。两种风格的完整对照见 **§10.1**。

## 3. 缩进规则（实测逐行确认）

以「程序集」为单位，共 4 级：

| 层级 | 缩进 | 内容 |
|---|---|---|
| 0 | `0` 空格 | `.版本`、`.支持库`、`.程序集`、`.程序集变量`、`.子程序` |
| 1 | `4` 空格 | 子程序内的 **声明**（`.参数` / `.局部变量`）与 **语句**、`.如果` 等流程标记 |
| 2 | `8` 空格 | 第一层块体（`.如果` 体内、`.计次循环首` 体内） |
| 3 | `12` 空格 | 第二层块体（块中块） |

实测往返样例（左侧为原始输入，右侧为 `e2t` 回读）：

```
.子程序 综合演示, 文本型, 公开, 覆盖各类语法      ← 0
    .参数 输入文本, 文本型, , 待处理文本            ← 4
    .局部变量 局部甲, 文本型                        ← 4
                                                    ← 4（块内空行也带缩进）
    .如果 (局部乙 ＞ 0 且 可选开关)                   ← 4
        局部乙 ＝ 局部乙 ＋ 1                        ← 8
    .否则                                           ← 4
        局部乙 ＝ 局部乙 － 1                        ← 8
    .如果结束                                       ← 4
```

**关键细节：子程序体内的空行是「4 个空格」而不是真正的空行**（见上面第 4 行）。块与块之间、子程序之间用真正的空行（0 字符）。子程序末尾会补一行 4 空格。

`.参数` / `.局部变量` 声明必须紧跟 `.子程序` 行、在第一条语句之前。**不要在 `.子程序` 行后插空行**——实测 `t2e` 会报 `[警告]`，回读的规范形也与你的原文不一致。

### `t2e` 对常见写错的反应（QAQ-ETool 实测，别依赖）

| 你写的 | 结果 |
|---|---|
| `甲 ＝ 甲 + 1`、`甲 = 1`（半角运算符） | 被纠正为全角 `＋` `＝`，不报错 |
| `甲 ＝ "hello"`（半角引号） | `[警告] 无法识别的字符 "（按未验证代码写入）`，**退出码 2** |
| Tab 缩进 | `[错误]`（后续行会被错并进上一条声明），**退出码 2** |
| 文件用 LF 换行 | 整个文件被当成一行，报「缺少 .程序集 行」 |

所以写错了不一定报错，但**规范形才是你要的样子**。退出码 2 或出现 `[错误]` 的产物一律不可交付。用 `<SCRIPTS>/rtcheck.py` 可以一次查出这几类问题。

## 4. 声明语法

### 4.1 程序集

```
.程序集 <程序集名>
```

### 4.2 子程序

```
.子程序 <名称>, <返回类型>, <公开?>, <备注?>
```

| 位 | 必填 | 说明 |
|---|---|---|
| 名称 | 是 | — |
| 返回类型 | 是 | 留空表示无返回值；写 `整数型` / `文本型` … |
| 公开 | 否 | 写 `公开` 表示公开；不写即私有 |
| 备注 | 否 | 自由文本 |

实测往返：`.子程序 综合演示, 文本型, 公开, 覆盖各类语法` → 原样保留。

### 4.3 参数

```
.参数 <名称>, <类型>, <参考?>, <可空?>, <备注?>
```

实测往返：`.参数 输入文本, 文本型, , 待处理文本`、`.参数 结果容器, 文本型, 参考 数组`、`.参数 可选开关, 逻辑型, 可空` 全部原样保留。

> 参数在任何情况下都原样往返，可以放心写。见 §7。

### 4.4 变量（局部变量 / 程序集变量）

```
.局部变量   <名称>, <类型>, <修饰?>, <数组尺寸?>, <备注?>
.程序集变量 <名称>, <类型>, <修饰?>, <数组尺寸?>, <备注?>
```

**关键：数组不是靠 `数组` 两个字表示的，是靠第 4 位有没有尺寸数字。** 这是 IDE 的原生形态（用 IDE 亲手写的 `测试.e` 核对过）。

```
.局部变量 甲, 文本型                        ← 标量
.局部变量 乙, 整数型, 静态                   ← 静态标量
.局部变量 丙, 文本型, , "0"                  ← 数组，成员数 0（第 3 位留空）
.局部变量 丁, 文本型, , "2"                  ← 数组，成员数 2
.局部变量 戊, 文本型, 静态, , 备注内容        ← 静态标量 + 备注
```

- 第 3 位 `<修饰>` 只有一个值：`静态`（可省略，但不能写别的词）。中间的空字段**不能省**——`.局部变量 丙, 文本型, , "0"` 里那个逗号必须留着。
- 第 4 位是**数组成员数**，用**半角**引号包成 `"0"`。**声明时不写这个字段，就是标量。**
- 第 5 位是备注。

> ⚠️ **不要**给局部变量写 `, 数组` 这种形式（那是**参数**的写法，见 §4.3）。实测文本写 `.局部变量 丙, 文本型` 与写 `.局部变量 丙, 文本型, 数组`，产出的 `.e` **字节完全相同** —— `数组` 两个字对局部变量根本不生效，只是会让人误读。数组要用尺寸位 `, , "0"` 表达。

> **引号有区别**：声明里的尺寸字段用**半角**引号 `"0"`；而**代码里的字符串字面量**用**全角** `“ ”`。两者不能混。

> ⚠️ 变量记录的数组位（bit3 = `0x08`）：QAQ-ETool `t2e` 按文本绑定的局部变量 / 程序集变量**不带** bit3（`efix.py check` 实测 0 条）。拿到的 `.e` 若带 bit3，**原样交付、不要去清** —— 用 `efix.py apply` 清掉后**易语言 IDE 打不开该 `.e`**（详见 §7）。唯一可靠判据是「用户能否在 IDE 里打开并编译运行」。

### 4.5 常量 / 数据类型 / DLL / 全局变量

分别在 `const.e.txt` / `struct.e.txt` / `dll.e.txt` / `global.e.txt`，语法与 IDE 内一致。

**支持库清单只走 `配置/支持库.config.json`（英文布局 `config/lib.config.json`），不要写 `.支持库` 行**（2026-09-21 受控实验：四组对照，同源文本只改一处）：

| 只改这一处 | `t2e` 产物 `.e` | 结论 |
|---|---|---|
| `配置/支持库.config.json` 里追加一项 | 6747 B → **6818 B**，二进制含该 key 的 ASCII（md5 `ff549e9c…`） | ✅ **这才是输入** |
| `代码/*.e.txt` 的 `.版本 2` 后加一行顶格 `.支持库 <key>` | 与基线**逐字节相同**（6747 B / md5 `d0d47062…`），key 未进 `.e` | ❌ 无效 |
| 同上，但换成**已安装**的库 `cncnv` | 同基线，同样**逐字节相同** | ❌ 与「库是否安装」无关，通道就是不通 |

> QAQ-ETool 复测（`-nosidecar`，只加一行 `.支持库 cncnv`）：产物 md5 与基线相同，二进制里没有 `cncnv`，结论一致。

- **别手写，用 `<SCRIPTS>/elibs.py <文本目录> --fix`**（按源码用到的命令/类型/常量自动补；`--add <key>` 手动指定；`--which <名字>` 查所属库），见 SKILL.md §4.1。
- 追加项的结构（`Key` = `.fne` 文件名主干；`Guid` = 该库 `.fne` 自带的 GUID **原字符串**，大小写 / 花括号 / 连字符都照抄 —— IDE 保存的库表里 `A512548E76954B6E92C21055517615B0`、`{A068799B-7551-46b9-8CA8-EEF8357AFEA4}`、`d09f2340818511d396f6aaf844c7e325` 三种写法并存；`elibs.py` 从导出文档 `库/<key>.md` 的 GUID 行取）：

  ```json
  {"Key":"<key>","Guid":"<.fne 里的 GUID 原文>","Name":"<库名>",
   "Version":{"Major":<主版本>,"Minor":<次版本>},
   "CmdCount":0,"MaxRefConstPos":0,"MaxRefObjectPos":0}
  ```

  `CmdCount` / `MaxRef*` 是「最少需要」计数（IDE 按实际引用写，未引用的可以是 0），新加的库写 0 即可。

- **验收闸门 = 产物 `.e` 的 md5 必须变化**（更硬的判据：二进制里能找到该 key 的 ASCII）。md5 没变＝白改，不得进入下一步。
- `e2t` 把库表写成 `配置/支持库.config.json`（英文布局 `config/lib.config.json`），并在程序集文件头为非核心支持库写 `.支持库 <key>` 行（核心库 krnln 不写） —— **那几行只是展示**，改它们对 `t2e` 不生效，要改库表就改 json。
- 本机**没装**的支持库：`e2t` 只报 `[警告] 支持库未能加载: <key> <库名>`，文本照常产出；`t2e` 同样只警告，但引用该库命令的语句无法绑定（会变成 `[错误]` / 未验证代码）。所以库表里写没装的库不会让工具罢工，却一定过不了交付红线（实测）。

## 5. 控制流语法（全部实测往返一致）

| 结构 | 写法 | 分支 |
|---|---|---|
| 条件（双分支） | `.如果 (条件)` / `.否则` / `.如果结束` | 成功 ＋ 失败都有 |
| 条件（单分支） | `.如果真 (条件)` / `.如果真结束` | **只有成功分支** |
| 多重条件 | `.判断开始 (条件)` / `.判断 (条件)` / `.默认` / `.判断结束` | 成功 ＋ 失败都有 |
| 计数循环 | `.计次循环首 (次数, 循环变量)` / `.计次循环尾 ()` | — |
| 变量循环 | `.变量循环首 (起始, 结束, 步长, 循环变量)` / `.变量循环尾 ()` | — |
| 前测循环 | `.判断循环首 (条件)` / `.判断循环尾 ()` | — |
| 后测循环 | `.循环判断首 ()` / `.循环判断尾 (条件)` | — |
| 跳出 / 继续 | `跳出循环 ()` / `到循环尾 ()` | — |
| 返回 | `返回 ()` 或 `返回 (表达式)` | — |

**注意**：
- `.计次循环尾`、`.判断循环尾`、`.变量循环尾` 后面**必须带空括号 `()`**；`.判断结束` / `.如果结束` / `.如果真结束` **不带括号**（实测：原样往返）。
- 流程标记（`.如果` 等）与普通语句**同级缩进**，块体再深一级。
- **块尾之后紧接另一条块语句时，中间必须插一个空行**（空行缩进 = 前面那个块尾的缩进），
  否则 IDE 里两条块的流程线会串在一起（`.e` 里空行只是一条 19 字节的空表达式记录，多写无害）。

### 5.1 「判断」的语义（实测，最容易被 AI 写错的点）

**「判断」是 `if / else if / else` 链，不是 switch 那种「按值分派」**：

- `.判断开始 (条件)` 的条件**必须是逻辑型**。实测给整数直接编译报错：
  `错误(10044): 不能将 "整数型" 数据转换到 "逻辑型" 数据`。
- `.判断 (条件)` 挂在中间，可以有多条；**只在前面所有分支都不成立时才求值**，语义就是 C 的 `else if`。
  它后面跟的是一条**独立的布尔条件**，**不是**「与首行表达式比较的值」——
  想按取值分派，就写若干条 `.判断 (x ＝ 1)`、`.判断 (x ＝ 2)`。
- `.默认` 是 `else`（前面全不成立时走），可省略；省略后条件不成立就什么都不做。
- 「判断」与「如果」在 IDE 里画出的流程线**一模一样**（一条「判断成功」路 ＋ 一条「判断失败」路），
  区别只是「判断」能挂多个 `else if`。
- `.计次循环首` 的循环变量从 **1** 数到 **次数**（不是 0 起）；不需要循环变量时可整体留空：
  `.计次循环首 (10, )`（实测 IDE 原生写法）。

骨架（缩进每层 4 空格；`.判断` 与 `.默认` 都与 `.判断开始` 同缩进）：

```
.判断开始 (甲 ＞ 0)              ' 判断成功分支
    ...
.判断 (甲 ＝ 0)                  ' else if：前面不成立才求值
    ...
.默认                             ' else：前面全不成立（可省略）
    ...
.判断结束
```

### 5.2 遍历目录的两个实测陷阱（`寻找文件` / `取文件属性`）

1. **`寻找文件 (路径 ＋ "\*", 16)` 不是「只要子目录」**。`16 = #子目录` 只是「把子目录也放进来」，
   实测返回的是本层**全部条目**（文件也在内）。要真目录必须再过滤：
   `位与 (取文件属性 (路径), #子目录) ≠ 0`。
   而第 2 参数**留空**才是「只列文件、不含子目录」。
2. **`取文件属性` 失败返回 -1**（典型：`hiberfil.sys` / `pagefile.sys` 这类被系统独占的文件），
   而 `位与 (-1, 16) ≠ 0` 恒成立 —— 不过滤就会把它们误判成目录。必须先判断 `属性 ≠ -1`。
3. 另外 `寻找文件` 的迭代位置记在**子程序**上，**边找边递归**会被内层调用冲掉状态（漏项 / 提前结束且不报错）。
   安全写法是「先把本层收进数组，再递归」。

## 6. 表达式与调用

```
局部甲 ＝ 子文本替换 (局部甲, “你”, “您”, , , 真)
局部乙 ＝ 局部乙 ÷ 2 ％ 7
.计次循环首 (5, 局部乙)
```

- 命令调用：`命令名 (参数1, 参数2, ...)`，**命令名与左括号之间有一个空格**。
- 参数留空表示省略：`, , ,` （连续逗号，逗号后各带一个空格）。
- 逻辑值写 `真` / `假`。
- 数组下标用**半角方括号**：`数组变量 [1]`（注意易语言此处用半角）。
- 赋值用全角 `＝`。

## 7. 变量记录的「数组位」（bit3）—— 见到了也原样交付，不要去清

### 一句话结论

**变量记录带 bit3（`0x08`）的 `.e`，直接交付，不要清。** QAQ-ETool `t2e` 按文本绑定的局部变量 / 程序集变量本身不带 bit3（实测）；带 bit3 的通常来自别的工具的产物。

用 `efix.py apply` 清掉 bit3 之后，**易语言 IDE 直接打不开该 `.e`**；未清的原样产物能打开、能成功编译运行（用户实测）。所以本节的**唯一可靠判据是「用户能否在 IDE 里打开并编译运行」**，不是「`e2t` 回读文本是否干净」。

> 背景：`e2t` 回读时若把 bit3 显示成 `, 数组`，那只是回读的解读口径 —— **IDE 并不把该变量当数组**。

### 只读复核

```bash
$PY <SCRIPTS>/efix.py check --e 产出.e --src 文本目录
# 例：候选名字 7 个 → 判定带 bit3 的 0 个名字 / 0 条记录（QAQ-ETool 产物）
```

### 记录级依据（布局已用工具产物与 IDE 原件双向校准）

```
u32 总长            = 9 + 4*(有尺寸块) + 名字字节数 + 备注字节数
u32 数据类型        0x8000_000n = 系统类型   n: 1 字节型 2 短整数 3 整数 4 长整数
                                            5 小数 6 双精度 7 逻辑 8 日期时间
                                            9 文本 10 字节集 11 子程序指针
u8  标志            bit0 = 静态，bit1 = 参考（参数），bit2 = 可空（参数），bit3 = 数组（参数）
u8  0
u8  有尺寸块         0/1
[u32 数组尺寸]       仅当「有尺寸块」= 1
char 名字[]         GBK，以 \0 结尾
char 备注[]         GBK，以 \0 结尾
```

`静态变量` 的记录总长 133 = 4+3+8+1+116+1，备注正好是那 58 个汉字的 116 字节。

### 更正记录（这条结论改过多次，留个档 —— 教训比结论值钱）

1. 最早把「`t2e` 产物带 bit3」写成转换工具的通用缺陷，并按不同可执行文件做了归因 —— 归因错误：同一文本目录、同一时刻分别喂给两个可执行文件，产物**逐字节完全相同**。
2. 据错误归因落地了 `efix.py apply` 去「清理」—— **结果清过 bit3 的 `.e` 在 IDE 里直接打不开**（用户实测），「清理」建议是**有害的**。
3. 现行结论：保留记录布局与 `check`，`apply` 不再建议；事实是 **IDE 原生 `.e` 的变量 flags 是 `0x00`，旧产物是 `0x08`** —— 这是**产物 vs 原件**的差异；无论产自哪里，做法都是**原样交付**。

**教训**：① 比对之前先确认「基准是哪一侧产出的」—— 拿 A 的产物去证明 B 的现象不存在，是最容易犯的错。② **只看文本回读、不看 IDE 能否打开**，会把无害噪声当成缺陷去「修」，结果把文件修坏 —— 判据必须落在「用户能否真的用起来」上。

## 8. 往返保真度基线

| 指标 | 结果 |
|---|---|
| 文本层 `e2t → t2e → e2t`（`-nosidecar`） | **无损**。两轮代码文本（含 `排序.list.txt`）逐字节一致；只有 `项目.qtprj` 的 `Source` 随 `.e` 位置变化 |
| 字节层 原始 `.e` vs `t2e` 回写 `.e`（带 `.qaq/` 旁路、未改动） | **逐字节一致**（含多个易模块、1496 个子程序的工程实测 md5 相同）；改过的子程序按文本重新绑定，其余沿用原字节 |
| 字节层 原始 `.e` vs `t2e` 回写 `.e`（`-nosidecar`） | 全部按文本重新绑定，**不保证**与 IDE 原件逐字节相同 |
| `t2e` 回写的变量 flags | 不带 bit3（见 §7） |

> **永远不要用回写产物覆盖原始 `.e`**。文本往返无损，字节层不是 —— 原件永远单独留一份。

## 9. 命令行要点（QAQ-ETool 实测）

- `-dst` 的父目录不存在时会自动创建；`-src` / `-dst` 用相对路径也可以（按当前工作目录解析）。
- 不在工具自己的目录里留任何东西（`assets/` 里只有那 3 个 exe）。
- `e2t` 的 `-dst` 若是**非空且不是文本工程**的目录，直接拒绝，不会覆盖你的文件。
- 退出码：`0` 成功；`1` 失败（无产物，stderr 有 `ERROR:`）；`2` 已产出但有无法解析 / 未验证的内容 —— **2 也不可交付**。
- 不认识的参数会被**静默忽略**（例如 `-enc`），别以为传了就生效。
- `.qaq/sidecar.json` 旁路：`e2t` 默认写出，`t2e` 用它把未改动的子程序逐字节还原；做格式自检（`rtcheck.py`）时要加 `-nosidecar`，否则第二遍往返必然收敛、检验失去意义。

## 10. 项目文件 `项目.qtprj` 与命名风格

### 10.1 两种命名风格由一个开关决定

`e2t` / `t2e` 都接受 `-ns`：**不传 = 英文风格；`-ns 2` = 中文风格**。两者是同一套结构的两种叫法，文件名必须成对匹配，混用会让工具以为文件全丢了。

| 英文风格（默认） | 中文风格（`-ns 2`） |
|---|---|
| `class/` | `代码/` |
| `class/order.list.txt` | `代码/排序.list.txt` |
| `config/` | `配置/` |
| `config/lib.config.json` | `配置/支持库.config.json` |
| `config/user.config.json` | `配置/用户.config.json` |
| `config/system.config.json` | `配置/系统.config.json` |
| `form/` | `窗口/` |
| `resource/` | `资源/` |
| `const.e.txt` | `常量.e.txt` |
| `dll.e.txt` | `DLL.e.txt` |
| `struct.e.txt` | `自定义类型.e.txt` |
| `global.e.txt` | `全局变量.e.txt` |
| `class/dirs.desc.json` | `代码/目录.desc.json` |
| `icon.ico` | `图标.ico` |
| `project.qtprj` | `项目.qtprj` |

**本套技能的工程一律用中文风格**（`项目.qtprj` 就是中文布局的标志文件）。`rtcheck.py` 会按目录里有没有 `代码/` 自动判断并补上 `-ns 2`，不用手动传。

> 项目文件扩展名是 **`.qtprj`**（关联到 `qaq-etool-gui.exe` 打开）。`.etprj` 已不再使用，`t2e`、GUI 和 `e2t` 的覆盖闸门都不认它。

### 10.2 `项目.qtprj` 的格式

**GBK 编码、无 BOM、CRLF**（QAQ-ETool `e2t` 实测产物）。`t2e` 只把它当「中文布局」的标志，**不读其中的值**；这些键是给人看、给别的工具留的元信息。

`mkproj.py` 写的基本键：

```json
{
    "AsyncFile": false,
    "Encoding": "UTF-8",
    "Level": 1,
    "NameStyle": 2,
    "Password": "",
    "ResetNames": [],
    "Source": "代码.e"
}
```

| 键 | 含义 / 取值 |
|---|---|
| `Encoding` / `Level` / `NameStyle` | 文本编码 / 导出级别 / 命名风格（`2` = 中文） |
| `Source` | 源 `.e`，**相对项目文件所在目录**。`.e` 在项目目录里就是 `代码.e`；在上一级就是 `../xx.e` |
| `Password` / `ResetNames` / `AsyncFile` | 加密口令 / 重置名列表 / 异步写文件，默认空 |

`e2t` 写出的 qtprj 还会带几个工具自用的键，原样保留即可。

### 10.3 写 qtprj 的顺序

**先跑 `t2e` 生成 `.e`，再写 `项目.qtprj`**；写的时候做「保留已有键值（含不认识的）+ 补齐缺失键」的合并，别无脑覆盖（用户可能改过字段）。QAQ-ETool 的 `t2e` 不改写 qtprj，但 `<SCRIPTS>/mkproj.py` 仍按这个顺序实现。

### 10.4 用图形界面打开项目

`qaq-etool-cli` 技能的 `assets/qaq-etool-gui.exe` 接受一个路径参数：

```bat
qaq-etool-gui.exe "<项目目录>\项目.qtprj"   :: 或项目目录本身 → 预选「组包（文本 → .e）」
qaq-etool-gui.exe "<某个>.e"                 :: .e / .ec → 预选「拆包（.e → 文本）」
```

把 `.qtprj` / 目录 / `.e` 拖到 exe 上，或在资源管理器里对 `.qtprj` 用「打开方式 → qaq-etool-gui.exe」，效果相同。安装器**不写文件关联**，要双击 `.qtprj` 打开就自己在「打开方式」里选 `qaq-etool-gui.exe` 并勾「始终使用此应用」。

## 11. 声明槽位总表与 DLL 调用约定（上游技能搬运）

### 11.1 各声明的固定槽位数（改编自 aiqinxuancai/e-language-skill，MIT）

逗号分隔的是**固定字段槽位**，不是可随意压缩的 CSV：**行尾未用槽位可省略，中间空槽必须用逗号保留**。最后一个结构逗号之后的内容全部属于「说明」，说明里可以再包含逗号；带引号的常量值 / DLL 名 / 数组维数（`"2,3"`）内部的逗号不是结构逗号。

| 指令 | 槽位 / 结构逗号 | 固定字段顺序 | 关键约束 |
|---|---|---|---|
| `.程序集` | 4 / 3 | 名称, 基类, 公开属性, 说明 | 公开属性仅空或 `公开`；`<对象>` 是 IDE 对「省略基类」的等价导出，别为统一改写 |
| `.子程序` | 4 / 3 | 名称, 返回类型, 公开属性, 说明 | 第 3 槽仅空或 `公开`，**说明放第 3 槽是经典错误**（要写 `, , 说明`） |
| `.参数` | 4 / 3 | 名称, 类型, 参数属性, 说明 | 普通子程序用 `参考`/`可空`/`数组`；DLL 参数导出属性用 `传址`/`数组` |
| `.局部变量` | 5 / 4 | 名称, 类型, 静态属性, 数组维数, 说明 | 第 3 槽仅空或 `静态` |
| `.程序集变量` | 5 / 4 | 名称, 类型, 保留空槽, 数组维数, 说明 | **第 3 槽必须为空**（不是静态属性），写内容 = 错 |
| `.全局变量` | 5 / 4 | 名称, 类型, 公开属性, 数组维数, 说明 | 第 3 槽仅空或 `公开` |
| `.数据类型` | 3 / 2 | 名称, 公开属性, 说明 | 后接 `.成员`；成员顺序 = 结构内存布局 |
| `.成员` | 5 / 4 | 名称, 类型, 传址属性, 数组维数, 说明 | 第 3 槽仅空或 `传址` |
| `.DLL命令` | 6 / 5 | 名称, 返回类型, DLL文件名, DLL入口名, 公开属性, 说明 | DLL 名/入口名带引号；第 5 槽仅空或 `公开`；省略入口名但填后面的字段时中间逗号要留 |
| `.常量` | 4 / 3 | 名称, 值, 公开属性, 说明 | 旧工程可能有兼容的 5 槽行——读的时候保留原状，新增用 4 槽 |
| `.支持库` | 不适用 | 库名/版本（项目指令） | 只在明确改依赖时动；名称必须来自实际安装的库 |

声明顺序硬规则：每个 `.子程序` 内先**连续**写完全部 `.参数`，再**连续**写完全部 `.局部变量`，最后才是执行语句；执行语句开始后不能再声明。类公开方法在第 3 槽写 `公开`；类通常带 `_初始化`/`_销毁` 生命周期子程序，保留 IDE 生成的结构与顺序。

### 11.2 DLL 入口名的 `@` 前缀 = cdecl

- 第 4 槽入口名**不加 `@`** → 默认 `stdcall`。
- 目标函数确认是 `cdecl` → 入口名前加 `@`（引号内）；第 1 槽易语言命令名不变：

```text
.DLL命令 Foo, 整数型, "foo.dll", "@Foo", , cdecl 示例（若后续槽位要填，中间逗号照留）
```

调用约定从头文件/官方文档/已验证声明来，不猜。详见《Win32与DLL互操作》。
