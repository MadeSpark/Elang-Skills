# 易语言 AI 工具链（开发工程）

让 AI（和你）能读、能写、能查易语言（`.e` / `.ec`）。

**本目录是工程本体**；可直接拷走给别人用的**成品发布区**是 `Releases\Elang-AiTools\`。

## 三件直接可用的事

| 要做什么 | 用什么 |
|---|---|
| **查支持库函数**（函数名 / 参数 / 参数备注） | 双击 `Releases\Elang-AiTools\skills\elang-ai-coding\assets\导出支持库文档.exe`，产物落在**当前目录**（77 库 / 5951 条命令）；AI 调用时传个输出目录即可 |

`mkproj.py` 产出的工程与 GUI 生成的参考工程结构逐项对齐（14 键 etprj、GBK 编码、中文命名风格），`rtcheck.py` 实测**双次往返收敛 ✓**。

## 工具一：导出支持库文档（单 exe）

**双击 `Releases\Elang-AiTools\skills\elang-ai-coding\assets\导出支持库文档.exe` 即可**（装完技能后，各 AI 工具的技能目录里也各有一份）。它会：

1. 顺着 `.e` 的文件关联找 `e.exe`，推出 `lib` 目录（多路注册表回退 + 常见路径兜底）
2. 扫描该目录下所有 `.fne`，逐个 `LoadLibrary` + `GetNewInf`
3. 把结果写到 **当前工作目录**（不给输出目录参数时）

命令行：

```bash
"导出支持库文档.exe"                     # 全自动，输出到【当前目录】
"导出支持库文档.exe" D:\out              # 位置参数：输出到指定目录
"导出支持库文档.exe" -o D:\out           # 同上（等价写法）
"导出支持库文档.exe" -l D:\ides\e\lib     # 手动指定支持库目录
"导出支持库文档.exe" -q                  # 静默（不打印过程、不等待回车）
"导出支持库文档.exe" --json | findstr /i 取文本   # 只吐 commands.jsonl 到 stdout，不落盘
```

> **默认输出目录是「当前工作目录」而不是「exe 所在目录」**，这是为 AI / 脚本调用设计的：
> 先 `cd` 到自己的临时目录再跑，产物就落在手边，用完即删，也不必去猜 exe 装在哪。
> 双击时当前目录就是 exe 所在目录，行为与从前一致。
> `--json` 是纯查询模式：不建目录、不写文件，只把 JSONL 打到标准输出（管道接走时是 UTF-8）。
> 另外，「是否等待回车」会**自动判断**：只在 stdin 与 stdout 都挂在控制台上时才等，
> 所以管道/重定向调用不会被一行「按回车退出」污染输出。

输出内容：

| 文件 | 内容 |
|---|---|
| `索引.md` | 库清单（标识/名称/版本/命令数/说明）+ 定位方式 + 统计 |
| `命令大全.md` | 全部命令，按库分节，一个文件看全 |
| `库/<库标识>.md` | 单库详情：命令名、英文名、返回值、参数表（参数名/类型/修饰/备注）、数据类型、常量 |
| `commands.jsonl` | 一行一条命令的 JSON，便于程序或 AI 直接检索 |

本机实测：**77 个支持库、5951 条可用命令**，全流程约 2 秒。

> **它查不到易模块（`.ec`）。** `*.fne` 是支持库、`*.ec` 是易模块，精易模块 / NB模块 / HP_Socket
> 这类都是 `.ec`，不在那 77 个库里 —— 所以 `编码_Utf8到Unicode`、`文本_取长度ex` 一条也查不到。
> 要它们的真实签名和备注，把模块本身 `e2txt -mode e2t` 转成文本再 `grep "^.子程序 "` 即可
> （易模块源码里 `.子程序 名, 返回类型, 公开, 备注` 的第 4 个字段就是函数备注）。做法写在技能 §4。

> 若改了 `src/elibdoc.c`，用 `bash src/build.sh` 重编译（需要 32 位 gcc，支持库是 32 位 DLL）。
> ⚠️ 编译脚本里**必须把 gcc 所在目录加进 `PATH`**：只写 gcc 全路径而不加 PATH，gcc 找不到自己的
> `cc1`/`as`/`ld` 子程序，会以 **exit 1 静默失败**（一行错误都不打印，表现为「脚本跑完但 exe 没更新」）。`build.sh` 已处理。

## 工具二：写出一份「双击就能在 GUI 里打开」的项目

e2txt GUI 双击 `.etprj` 时执行的是 `e2txt-gui.exe -prj "<项目文件>"`，
它会把**项目文件所在目录**当作「TXT转E」的文本目录。所以项目目录必须是这个形状：

```
<项目目录>/
├── 项目.etprj              项目描述（GUI 靠它定位）
├── 代码/                   ← 目录名必须是这个（NameStyle=2 中文命名风格）
│   ├── xxx.static.e.txt    标准程序集
│   ├── xxx.class.e.txt     类程序集
│   ├── xxx.form.e.txt      窗口程序集
│   └── 排序.list.txt        程序集顺序
├── 常量.e.txt
├── 配置/{支持库,用户,系统}.config.json
└── 代码.e                  生成好的 .e（t2e 产物）
```

用 `mkproj.py` 一键生成（默认写一份示例源码）：

```bash
PY=python                            # 任意 Python 3.9+ 均可
$PY tools/mkproj.py "C:\path\to\我的项目"
```

它会依次：写示例源码 → 写 `配置/` → 调 `t2e` 生成 `代码.e` → 自动跑 `efix` 清数组位 → **最后**才写 `项目.etprj`。

生成后**双击 `<项目>\项目.etprj`** 就能在 e2txt GUI 里打开，切到「TXT转E」页点「生成」即可重新出 `.e`。

三个容易踩的点（都已内置处理）：

| 点 | 说明 |
|---|---|
| **etprj 写序** | 命令行 `t2e` 会顺手把 `<项目>\项目.etprj` 重写成只剩 4 个 `TXT2E-*` 键，所以 etprj 必须**在 `t2e` 之后**写，并做「保留已有值 + 补齐缺失键」的合并。 |
| **etprj 编码** | **GBK、无 BOM、CRLF** —— 和 `*.e.txt`（UTF-8 带 BOM）不一样。e2txt 按 ANSI 读它，写成 UTF-8+BOM 会让 JSON 解析失败、双击打不开。 |
| **数组位** | 命令行 `t2e` 会给局部变量加 bit3，不清的话用户在 IDE 里会看到变量被误勾「数组」。`mkproj.py` 自动调 `efix.py` 修掉（`--no-fix` 可关）。 |

> 双击要能用，需要 `.etprj` 的文件关联指向 `e2txt-gui.exe` 且带 `-prj`。
> GUI 的「设置 → 设置文件关联(*.etprj)」按钮会自己写对这份关联。

## 工具四：技能 —— 跨 AI 工具通用

`Releases/Elang-AiTools/skills/` 下两个技能按 **Agent Skills 开放规范**
（[agentskills.io](https://agentskills.io)，Anthropic 提出、现为社区标准，40+ 种工具支持）编写：

- frontmatter 只有 `name` + `description`，不带任何厂商私有字段
- `name` 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$` 且与目录名一致
- 技能内路径以 `SKILL.md` 所在目录为基准（写 `scripts/xxx.py`，不写死绝对路径）
- 正文不出现「Bash 工具」「Read 工具」这类某家专有的工具名
- 脚本只用 Python 标准库

**所以同一份技能文件夹在 Claude Code、Codex CLI、DSH、Trae、Cursor、OpenCode、
WorkBuddy 等任何兼容工具里都能直接加载**，不需要为每家转换格式。

两个技能的分工：

| 技能 | 内容 |
|---|---|
| `elang-ai-coding` | **§★ 最高优先级：Unicode 与「文本长度」** → §1 格式铁律 → §2 双次往返验证 → §3 命令行 t2e 数组位修补 → §4 查支持库命令 → §5 产出 GUI 能打开的项目 → §6 标准工作流 → §7 其它坑 |
| `e2txt-cli` | 只管 e2txt 命令行本身：两种模式、参数、路径坑、退出码恒为 0 |

> **`elang-ai-coding` 的 §★ 是整份技能里优先级最高的一节**，因为它是「写出来的代码能不能跑」的分水岭。
> 内容全部来自对**本机真实源码**的核对（易语言自带 77 库 5951 条命令 + 精易模块 v11.1.7 的 `.e` 源码）：
> 易语言原生**不支持 Unicode**（文本型就是 GBK 字节流），处理 emoji / Unicode 符号要走精易模块
> `编码_Utf8到Unicode` → `编码_Unicode到usc2` 转成 USC2（`❤️` → `\u2764\uFE0F`，且 emoji 是**一对**代理
> `\uD83D\uDD25` 而不是 `\U0001F525`）；而 `取文本长度` 数的是**字节**（中文算 2，「你好！MadeSpark」＝ 15），
> 精易模块的 `文本_取长度ex` 却是**字符数**（备注原文「全角汉字字符算一个长度」）—— **两个「取长度」差一倍，
> 用前必须看备注。**

安装策略是**探测式**（`Releases/Elang-AiTools/install-skills.py`）：

1. **总是**装到 `~/.agents/skills/` —— 规范共享根，DSH / Codex / OpenCode / Cursor / Amp / Gemini CLI 等都扫它
2. 检测到哪个工具的家目录存在，就装到它自己的技能目录（**Claude Code 与 Trae 不读共享根**，必须单独装）

本机实测：一次装 **9 个位置 × 2 技能 = 18 份**，全部逐文件 md5 一致。

```bash
python Releases/Elang-AiTools/install-skills.py --list        # 看会装到哪
python Releases/Elang-AiTools/install-skills.py               # 装
bash   Releases/Elang-AiTools/install-skills.sh               # macOS/Linux 等价入口
python Releases/Elang-AiTools/install-skills.py --all         # 连没装的工具目录一起装
python Releases/Elang-AiTools/install-skills.py --project .   # 项目级安装
```

## 关键结论（详见 docs）

1. **缩进每层 4 空格**，UTF-8 **带 BOM**、**CRLF**；字符串引号全角 `“ ”`，运算符全角 `＋ － × ÷ ＝`。
2. **声明里的尺寸用半角引号** `"8"`，与代码里的全角字符串不同。
3. **局部变量/程序集变量表达数组要写尺寸位、不要写 `数组`**：`.局部变量 丙, 文本型, , "0"`。
   `, 数组` 是**参数**的写法（`.参数 结果, 文本型, 参考 数组`）。
4. **判定格式正确的办法是「双次往返收敛」**：文本 → `t2e` → `e2t` 得到规范形，规范形再走一遍应逐字节不变。一次往返必然不一致，因为 e2txt 会规范化空白。
5. **GUI 与命令行的 `t2e` 结果不同**：`e2txt-gui.exe` 产出的 `.e` 与 IDE 原生逐字节一致；`e2txt.exe`（命令行）会给**每个**局部变量/程序集变量多置一个 `flags` bit3(`0x08`)，导致 `e2t` 回读时普遍多出 `, 数组`（参数不受影响）。命令行走 `efix.py` 修补后，回读文本与 GUI 产物**完全一致**。
6. **文本往返无损，字节层有损**。**永远不要用回写产物覆盖原始 `.e`**。
7. **`t2e` 的两个路径坑**：`-dst` 的父目录必须先存在（否则静默不产出）；`t2e` 会在 e2txt 自身目录下留一个与 `-dst` 父目录同名的空目录。另外 **`-src` / `-dst` 都要给绝对路径**，相对路径直接报「来源文件不存在」。
8. **`-ns 2` 是中文命名风格**（`代码/` `配置/` `常量.e.txt`），不传则输出英文风格（`class/` `config/` `const.e.txt`）。GUI 用中文风格；工具有时要用 `-ns 2` 才能对齐。
9. **编码不是「一律 UTF-8+BOM」**：`代码/*.e.txt`、`配置/*.config.json`、`窗口/*.form.json` 是 **UTF-8 带 BOM**；而 **`项目.etprj` 是 GBK 无 BOM**（GUI 和命令行都这么写）。e2txt 按 ANSI 读 etprj，写错编码双击就打不开项目。
10. **命令行 `t2e` 会重写 `<文本目录>\项目.etprj`**，只剩 4 个 `TXT2E-*` 键。要用 etprj 的话必须**在 `t2e` 之后**写。
11. **双击 `.etprj` 的机制**是 `e2txt-gui.exe -prj "%1"`，即把**项目文件所在目录**当作「TXT转E」的源目录。本机出厂关联漏了 `-prj`、HKCR 那份还指向作者开发机路径，已修正为 `HKCU\SOFTWARE\Classes\Applications\e2txt-gui.exe\shell\open\command`。
12. **写控制台要防乱码**：程序内部文本是 UTF-8，而 Windows 控制台默认代码页是 936(GBK)，把 UTF-8 字节直接 `printf`/`WriteFile` 进控制台，中文会变成「瀹屾垚」这类乱码（`导出支持库文档.exe` 曾这样）。正确做法是**输出目标是控制台时转 UTF-16 走 `WriteConsoleW`**（与代码页无关，任何 `chcp` 下都正常）；被**重定向到文件/管道**时按 UTF-8 原样写出（AI/脚本要的就是 UTF-8）。回归测试：`src/test_out.c`（A/B 对照，实测乱码与正常两路）。
13. **技能是「开放标准」格式，一份文件跨工具通用**：`SKILL.md` = Agent Skills 开放规范（agentskills.io）。守住四条即可跨 40+ 种工具：① frontmatter 只留 `name` + `description`（厂商私有的 `agent_created` 之类，部分工具在打包/上传时会**直接报错**）；② `name` 必须匹配 `^[a-z0-9]+(-[a-z0-9]+)*$` 且与目录名同名；③ 技能内路径以 `SKILL.md` 所在目录为基准（写 `scripts/x.py`，别写死绝对路径）；④ 正文别出现「Bash 工具」这类某家专有的工具名。**安装位置**另有讲究：`~/.agents/skills/` 覆盖最广，但 **Claude Code 与 Trae 只读自己的目录**，所以必须按工具分别装 —— 见 `install-skills.py`。
14. **`安装技能.cmd` 必须 GBK + CRLF**：Windows 批处理里的中文若存成 UTF-8，cmd 按 ANSI 解释必乱码；带 UTF-8 BOM 更会让 cmd 直接报错。所以源模板（UTF-8）放在 `tools/mk-cmd.py`，产物按 GBK 落盘。
