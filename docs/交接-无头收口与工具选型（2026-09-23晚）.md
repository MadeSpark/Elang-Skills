## 2. ⭐ 本轮修的回归：`off`/`park` 档窗口不显示

**现象**：`--visible`（= `--headless off`）本应显示窗口供人工排查，实测全程 0 像素。

**根因**：elaunch 对 off/park 档传 `startupinfo=None` → 全零 `STARTUPINFO` 里
`wShowWindow=0` → GUI 程序的 `SW_SHOWDEFAULT` 回读这个 0 ⇒ 主窗口按 `SW_HIDE` 创建
（Windows 经典坑；宿主库 off 档不干预，就没人再显示它）。

**修法**：`tools/elaunch.py` 新增 `make_visible_startupinfo()`（显式
`STARTF_USESHOWWINDOW + wShowWindow=SW_SHOW`），park/off 档都用它。

**复测**：修后 off 档 `ENewFrame` 主窗口全屏可见（0,0,1707,1019）+ 向导 + 保存框全部正常显示 ✅
（用 `probe_enum.py` 枚举法验证；当时桌面有挂起窗口，`probe_wfp` 像素法不可用——见 §0 铁律 8）。
这份 off=可见 的数据**同时补上了像素判据的方向对照**（前文 89.4% 对照的复现）。

## 9. ⭐ 补充（2048 实战暴露的链路坑，2026-09-24 凌晨）

用本套装 skill 写「2048（GUI 游戏）」（`demo/2048/`）实测，**发现并修复一条致命链路坑**：

### 9.1 症状与定位（物证 `re/epk_q/2048_workspace_dump/`）

- 文本工程（窗口 JSON + 双程序集）t2e 零错误、echeck/rtcheck 全绿；
  但 `ecompile --check` 一律 `failed`，**IDE 打开工程后触发编译即静默退出（e_self_exit=0）**，面板无任何错误。
- 排除项：启动方式（etprj/配置字段无差异）、路径中文（Temp 纯 ASCII 复现同样失败）、
  AutoLinker 干扰（无请求文件残留）、t2e level、窗口 Id。
- **控件二分 + 代码二分**（mk_min.py / mk_code.py / D1~D8 系列）最终钉死：

### 9.2 根因（**务必写进 skill 规范意识**）

**`.如果` 不带 `.否则`（单分支使用）会让 t2e 产物在 IDE 编译期静默崩溃**——
面板无错误、IDE 进程 exit 0。规范 §5 的表格虽写了「.如果=双分支 / .如果真=单分支」，
但 echeck 与 t2e 都**不报错**（比「流程线串」更危险的静默坑）。
修法：`.如果` 一律配 `.否则`（哪怕空体/赋值占位），单分支一律用 `.如果真`。

### 9.3 其他确认有效的经验

- **窗口 UI 可全文本化**：`窗口/_启动窗口.form.json`（Controls 数组，19 键模板）+ `xxx.form.e.txt`
  事件程序集；事件名 `_窗口名_控件名_事件名`、启动窗口 `__启动窗口_创建完毕`。
- **t2e 产物默认「子程序启动」**：GUI 工程必须有 `_启动子程序`（`载入 (_启动窗口, , 假)`）。
- **`.e.txt` 三件套 = UTF-8 BOM + CRLF + 全角运算符**；缺 BOM 或 LF 行尾 → t2e 静默丢整个程序集。
- **echeck/rtcheck 绿 ≠ 编译绿**；反向亦然（悬空调用会让 IDE 假绿）。二分定位时必须让每次变体
  的调用链真实闭合。
- **弹窗取证**：`re/win_probe/probe_dlg.py`（EnumWindows + GetWindowTextA 抓 #32770 标题与子控件）。
