> 适用版本：MbKit 模块 `MbKit/1.4.5`（2026-10-20 最终发布，`.ec` **985,592 字节** / MD5 `8f963d0f265281c9ee514ca0fb970adf`）
> 结论先行：**A–F 六条验收（含“发布版 B”业务接管）全部实测通过** —— A 已知总长 8 MiB 进度 38 行、末字节后 **0.179 秒**完成；B 接管后 `用户下载\` 落盘 **524,288 B**，`下载\` **0 文件/0 进度/0 完成**；C 门控开/关分别为“正常完成”与“0 文件/0 完成”；D 未知总长 **262,144 B**、**17 行 `-1%`**、末字节后 **4.056 秒**完成；E 全新 profile 不预建目录也能落盘；F 中文文件名正常。实测口径与数据见第四节。

## 一、你遇到的三个问题，其实是三层原因

| 现象 | 真正的原因 | 本次处理 |
| --- | --- | --- |
| 下载自顾自下、程序收不到任何回调（文件跑到 `C:\Users\你\Downloads`） | `置下载目录` 没生效 ⇒ 内核认为“没人要接”，于是用 Edge 默认下载 UI | 修好 `置下载目录` 方法体（见第二节） |
| 偶尔能收到 `事件_正在下载`，但 `事件_下载完成` 要等 60 秒甚至根本不来 | WebView2 的 `DownloadOperation::State` 在文件落地后长时间仍是 `IN_PROGRESS`；未知总长时甚至永远不翻 `COMPLETED` | 已知总长改用“收满 + 最终文件落地 + 无 `.crdownload`”判定（实测 0.2~1.7 秒）；未知总长加 300 ms 轮询兜底（3.6 秒无增长且磁盘大小相等，实测约 4 秒，见第三节） |
| 以上都配好了，仍然拦不到 | 你原来的工程里只有 `绑定` / `事件_即将创建新窗口` / `载入URL` 这几个调用，既没有 `置下载目录`，也没有注册下载事件 | 给出可直接用的最小三件套（见第五节），业务接管另见 `事件_下载开始`（`使用说明` §7.7） |

而“修好源码还不行”的最后一环是**模块打包**的问题：

## 二、最关键的根因：`置下载目录` 在所有已发布 `.ec` 里都是空壳

把任意一份**本次修复前**的 `miniblink.ec` 拆包，`C:MB浏览框/M:置下载目录` 的字节码只有 **19 字节**——
这正好是“终止记录”的长度，意味着方法体里**一条语句都没有**。也就是说：

```
你调用  mb.置下载目录 (某目录)      ' 方法存在、参数正常、不报错
实际执行  什么也不做                ' 目录永远是空串
结果      内核走默认下载 UI，模块一个回调都收不到
```

为什么空？在模块源码文本树里，`.参数 目录, 文本型, 可空, ` 这一行行尾有一个**裸 LF**（只有 `\n`，没有 `\r`）——
这是整棵源码树里唯一的一处。`e2t` 拆包时它看起来只是一行普通空行，但 `t2e` 组包解析时会把紧跟其后的唯一语句吞进上一条记录，
于是方法体变成 0 条语句。更麻烦的是：`t2e` 有“旁路”优化——方法文本没变就沿用旧字节码，所以这个空壳会被**原样带进每一次重新组包**，
永远不会自愈。

本次修复做了两件事：

1. 把该处规范成标准 `CRLF`，重建文本树，方法体恢复为 124 字节的 3 条语句；
2. 构建期源码树里**裸 LF 数量已清零**（活动 `.txt` 源码 0 处；`资源\资源.desc.json` 这类配置文件里的换行不参与解析；该源码树不随 5 文件交付目录提供），以后用 `miniblink.e` 或 `miniblink_源码146` 重新组包不会再退化。

```易语言
    .如果真 (m_WebView ≠ 0)
        wkeSetDownloadDir (m_WebView, 目录)
    .如果真结束
```

> 字节码对照：旧版 **19 B（空壳）** → 修复版 **124 B（3 条语句）**。这是判断“到底有没有修好”最硬的指标，
> 以后你自己重新组包，也可以用这个数字自检（`Code` 各槽 base64 解码后求和）。

## 三、内核侧：`事件_下载完成` 为什么以前要等 60 秒，本版怎么判

WebView2 的下载状态机有个坑：文件已经落盘完成，`ICoreWebView2DownloadOperation::get_State()` 却长时间停在 `IN_PROGRESS`；**未知总长（chunked、无 `Content-Length`）时它更是只报 `st=0`，永远不报 `COMPLETED`**。旧实现只等状态翻成 `COMPLETED`，于是出现“文件早下完了、`事件_下载完成` 迟迟不来”（实测约 60 秒，甚至彻底不来）。

本版保留 `StateChanged` 终止态优先，同时用 300 ms 轮询兜底，并把两类下载分开判定：

- **已知总长**：已接收字节 ≥ 总大小，最终文件名已落地（不是 `.crdownload`），且没有 `.crdownload` 残留；满足即上报。实测通常在 **0.2~1.7 秒**内报完成（A 场景末字节后 **0.179 秒**）。
- **未知总长**：已接收字节 > 0，且**连续 12 个轮询周期（3.6 秒）字节数不再增长**，且**磁盘文件大小严格等于已接收字节数**；两个条件必须同时满足才上报。D 场景实测末字节后 **4.056 秒**完成，这是有意留出的安全窗，宁可延迟、不提前误报。
- 进度百分比在未知总长时固定为 **`-1`**；完成事件按下载对象去重，每次下载只报一次（日志里可见 `dl watch` 的完成上报记录）。服务器中途停顿 ≥3.6 秒时完成会顺延，但仍不会提前误报。

六条验收全部在最终发布件上跑完，旧版日志不再作为结论引用。验收口径如下：

| 场景 | 实测结果 |
| --- | --- |

B 场景的三个“0”不是失败，而是接管生效的证据：内核那份下载已被 `Cancel`，文件由业务代码写到 `用户下载\`，所以 `下载\` 里既没有文件，也没有进度/完成事件。D 场景的 **4.056 秒**也不是卡顿，而是未知总长判据必须等满 3.6 秒无增长后再确认；它换来的是“绝不把第一块刚写完误报成完成”。

## 五、修好后的正确写法（最小三件套，照抄即可）

```e
.子程序 __启动窗口_创建完毕
    mb.绑定 (图片框1.取窗口句柄 ())

    ' ① 目录建议非空（传空串等于交回 Edge 默认下载 UI）；目录不需要预先创建，模块会写 profile 并自动建
    mb.置下载目录 (取运行目录 () ＋ “\下载”)
    ' ② 注册“即将开始下载”：回调返回 真 = 放行；配合上面的目录才静默落盘
    mb.事件_正在下载 (&处理_正在下载, )
    ' ③ 注册“下载完成”：拿到最终路径和结果码
    mb.事件_下载完成 (&处理_下载完成, )

    mb.事件_即将创建新窗口 (&即将创建新窗口, )
    mb.载入URL (“你的页面地址”)

.子程序 处理_正在下载, 逻辑型
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 Url, 文本型

    返回 (真)      ' 返回 假 = 放弃这次下载，文件不会落盘

.子程序 处理_下载完成
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 路径, 文本型
    .参数 结果, 整数型

    ' 结果 = 0 表示成功；路径是最终真实文件名（可能带 “(1)” “(2)” 后缀）
```

要点：

- `事件_正在下载` 的回调**必须返回 真**，否则等于主动取消这次下载；
- 目录参数建议**非空**；用 `取运行目录 () ＋ “\下载”` 便于把文件收在程序旁边。**不需要预先建目录**：模块会调用 `put_DefaultDownloadFolderPath` 并自动创建，E 场景已实测；
- `路径` 以内核回报为准，不要自己拼文件名（重名会自动变成 `xxx (1).bin`）；
- 参数名按上表写即可；`视图` / `用户数据` 声明成整数型（内核传的是指针，需要文本时用 `WKE取文本`）。

> **只想看进度**：再注册 `mb.事件_下载进度 (&处理_下载进度, )` 即可，不需要额外注册完成事件；未知总长时百分比是 `-1`。
> **想让业务自己下载**：改用 `mb.事件_下载开始 (&处理_下载开始, )`，回调里返回 **真** 表示业务接管，内核会 `Cancel` 这一份，之后**没有** `事件_正在下载` / 进度 / 完成。注意它的返回值语义与 `事件_正在下载` **相反**（详见 `使用说明` §7.7–§7.9）。

## 六、怎么用发布版 demo 自证

1. 用易语言 IDE 打开 `模块测试源码.e`，确认工程已引入 **`互联网支持库`**（`HTTP读文件` 需要它），编译运行；
2. 把 demo 里的 `载入URL (...)` 换成你的下载直链，`全局_接管下载 = 真`，点下载；
3. 预期结果：
   - 运行目录自动生成 `下载日志.txt`（GBK/ANSI、无 BOM，程序自建），其中可见 `下载开始 …` 与 `download handed to user: …`；
   - `运行目录\用户下载\` 出现文件，大小与源文件一致；
   - `运行目录\下载\` 里 **0 个文件**（含 `.crdownload`），**没有进度、没有完成事件**——因为这一份已被业务接管；
4. 再把 `全局_接管下载` 改成 `假` 重跑：这次由内核接管，`下载\` 里应出现文件，`下载日志.txt` 应出现 `下载进度 …` 和 **一次** `下载完成 … 结果=0`。

B 场景的发布版实测就是第 3 步：日志 **8 行 / 443 B / GBK / 无 BOM**，`用户下载\dl_e2e_test.bin` **524,288 B**（MD5 `09cc21fef48e9ad67608d530df98cbf5`），`下载\` **0 文件 / 0 进度 / 0 完成**。如果你的结果不是这样，把 `下载日志.txt` 和 `mbk_diag.log` 一起发回。

## 八、注意事项与已知问题

1. **目录参数建议非空**：`置下载目录 (“”)` 等于没设置，会退回 Edge 默认下载 UI；目录本身**不需要预先创建**，模块会写 profile 并自动建。
2. **`事件_正在下载` 必须返回 真**：返回假就是主动取消这次下载。
3. **多个插件各带一份 MbKit 时，只有先载入的那份生效**（内核会在日志里警告，版本串不一致时要统一）。
4. **内核会把内置的 `MbKit146.dll` 释放到宿主 exe 所在目录**（逐字节比对，不一致就覆盖），所以重新编译产物后不需要你手动换 DLL。
5. 内核日志里中文路径可能显示成 GBK 乱码（如 `涓嬭浇`），**只是日志编码问题，功能与落盘路径都正常**。
6. 模块内版本串仍是 `MbKit/1.4.5`；原有接口签名未变，另新增 `事件_下载开始` / `事件_下载进度` 两个下载事件。最终交付只认 **985,592 B / MD5 `8f963d0f265281c9ee514ca0fb970adf`** 这一版，旧尺寸不再作为判断依据。
7. 如果你在**别的宿主程序**（如框架插件）里用这个模块，需要那个宿主也用新模块重新编译，它才会带上新内核；
   你直接用易语言编译自己的程序时，替换 `.ec` 后必须**重新编译**，新内核才会进产物。

## 十、下载接管与实时进度回调（2026-10-20 追加）

### 10.1 主因一：默认下载目录不可写，导航被静默中止

`DownloadStarting` 是 WebView2 下载链路的第一道口。旧实现只在 `事件_正在下载` 之后才处理目录和落盘；如果 profile 的默认下载目录不存在或不可写，`Content-Disposition: attachment` / 二进制主框架导航会在进入 `DownloadStarting` 之前被静默 abort，表现就是“点了没反应”，有时连 `事件_下载开始` 都不触发。本版在 view 初始化（挂下载事件之前）对非空的 `置下载目录` 显式调用 `put_DefaultDownloadFolderPath(置下载目录)`，目录由模块自动创建、**用户不需要预先建**（E 场景全新 profile 实测通过）；为空时不动 profile，创建/设置失败只记日志并保持原有放行与默认下载行为。

### 10.2 主因二：完成态只等 `StateChanged`

`事件_下载完成` 原先只依赖 `DownloadOperation::StateChanged`；某些场景状态长时间不翻，未知总长时更是只报 `st=0`、永远不报 `COMPLETED`，且会与 300 ms 轮询的兜底判定竞争。本版保留终止态优先：已知总长要求“已收满 + 最终文件名已落地 + 无 `.crdownload`”；未知总长要求“连续 12 个周期（3.6 秒）字节不增长 + 磁盘大小严格等于已接收字节”。两种路径都按下载对象去重，保证每个下载只报一次完成；进度由轮询按已接收字节变化上报，不依赖状态翻转。

### 10.3 已知取舍

进度是 300 ms 轮询，不是 Chromium 推送。极小的文件可能在首帧之后直接到末帧（`0%` → `100%`），这是预期行为，不是丢帧。

**要点**
- 目录兜底发生在 view 级；`置下载目录` 为空或创建/设置失败时只记日志，保持原有行为。
- 完成按下载对象去重；进度按 `(已下载, 总大小, 百分比)` 三元组去重，100% 只报一次。未知总长必须等连续 **3.6 秒**无增长且磁盘大小严格相等才上报，所以完成通常晚约 **4 秒**（D 实测 **4.056 秒**）；这是为了避免“第一块刚写完就误报”，服务器停顿会顺延、不会提前，进度百分比固定为 **`-1`**。

## 十一、易模块记录段校验和修复（2026-10-20 收尾，必读）

**现象**：A、B 两个 demo 的 `.e`，以及 `miniblink\模块测试源码.e`，改指 `…\miniblink\miniblink.ec` 之后，用易语言 IDE 打开任一都弹：
`文件中的重要数据段[易模块记录段]校验失败！`

**根因**：`.e` 的「易模块记录段」（`ECDependenciesSection`，段 key `0x0C007319`）里，每条依赖记录除 `Name` / `Path` 外还带 `FileSize`、`FileLastModifiedDate`；而**该段 92 字节段头的 `dataChecksum`（offset 44）与段头校验和（offset 4）都覆盖段数据**。首版“改路径”只替换了等长的路径串（`…\out_mbkit\miniblink.ec` → `…\miniblink\miniblink.ec`，同为 54 字节），没有重算这两个校验和，IDE 打开即判该段损坏。

**修法**（文件尺寸不变，每份只改 8 字节）：
1. 段数据校验和：对段数据做 4 路 XOR（`c[i & 3] ^= byte`），拼成 `c[3] << 24 | c[2] << 16 | c[1] << 8 | c[0]`，写回段头 offset 44；
2. 段头校验和：对 92 字节段头同样算一遍，写回 offset 4；
3. 其余段（含文件末尾 key `0x07007319` 的结束段）不动；段内 `FileSize` / FILETIME 与现行 `miniblink.ec`（985,592 B）本就一致，无需改。

### 11.1 「控制块有格式错误」：`--check` 全绿 ≠ IDE 能打开（2026-10-20 事故，必读）

**现象**：用户把 `demos\下载接管\B_只取链接_彻底拦截\B_只取链接_彻底拦截.e` 拖进易语言 IDE，弹

**根因**：A/B 两份 `.e` 的最后一个子程序 `记录日志`，末行是 `.如果真结束`，紧跟其后的只有

- IDE 解析出的控制块模型比文件里的代码少最后一行 —— 在 IDE 编辑器里 `Ctrl+A` / `Ctrl+C` 取剪贴板
