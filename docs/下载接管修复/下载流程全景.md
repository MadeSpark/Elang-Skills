# 下载流程全景

> 本文是[《使用说明.md》](..\..\miniblink\使用说明.md) §7.7–§7.9 的流程级展开：把“点一下下载”到“文件落盘”的每一步拆开，再把五种常见用法并排放在一起。接口契约以模块 `.ec` 的公开声明为准，《使用说明.md》§7.7–§7.9 是配套说明；本文负责回答“这一步谁在动、我能拿到什么、下一步该返回真还是假”。
>
> 实测环境：Windows 10/11 x64；WebView2 Runtime 155.0.4283.62；MbKit/1.4.5（`MbKit146.dll` 763,904 B）；32 位宿主。文中的字节数、MD5、耗时都来自最终验收；A/B 模板的身份与实测数据见 §6。

## 30 秒速查

### 用法一：当前 demo 的方案，能够控制下载位置和获取下载链接

```易语言
mb.置下载目录 (取运行目录 () ＋ “\下载”)
mb.事件_下载开始 (&处理_下载开始)
mb.载入URL (“https://example.com/download”)
' 回调内：记录 网址；数据 = HTTP读文件 (网址)；写到文件 (用户下载\文件名)
' 回调末尾：返回 (真)   ' 真 = 内核取消这一份，业务自己接管
```

**一句注意**：`事件_下载开始` 返回真后，内核不再写盘、不再发进度/完成；`用户下载\<文件名>` 是你自己 `HTTP读文件` + `写到文件` 写出来的，`下载\` 为空是正常现象。

### 用法二：彻底拦截下载，只直接取出下载链接

```易语言
mb.置下载目录 (取运行目录 () ＋ “\下载”)
mb.事件_下载开始 (&处理_下载开始)
mb.载入URL (“https://example.com/download”)
' 回调内：记录 网址/文件名/总字节；不调用 HTTP读文件，不写文件
' 回调末尾：返回 (真)   ' 真 = 内核取消这一份，只留链接
```

**一句注意**：返回真取消的是 WebView2 这一份下载操作（后续不再写盘），但撤不回已经发出的那次 HTTP 请求；它不是网络防火墙，鉴权链接/防盗链链接拿给外部下载器也可能打不开。

## 1. 总览：一条主线，两个分叉

### 1.1 阶段表

| 序 | 阶段 | 谁触发 | 模块做什么 | 你能拿到/看到 |
|---|---|---|---|---|
| 1 | 点击/导航 | 用户点击 `<a download>`，或主框架导航到附件 URL | 尚未介入 | 页面开始一次下载请求 |
| 2 | `DownloadStarting` | WebView2 收到响应、准备落盘时 | 读取 URI、建议文件名、总字节 | 下载还没写盘；事件参数已可用 |
| 3 | 派发 `事件_下载开始` | 模块在 `DownloadStarting` 内回调 | 把 `网址`、`文件名`、`总字节` 交给业务；等待逻辑型返回值 | 业务第一次拿到链接和文件名 |
| 4 | 内核 Cancel 或 Continue | 模块按返回值决定 | 真 = `Cancel` 这一份；假 = 继续 | 真：后面没有内核下载事件；假：进入下一阶段 |
| 5 | 写盘 | 内核，或业务代码 | 假：内核写到 `置下载目录`；真：模块不写，业务自己写（流程 3）或干脆不写（流程 4） | `下载\` 出现文件，或你自己的目录出现文件，或两边都没有 |
| 6 | 300 ms 轮询进度 | 内核下载监听 | 字节数变化时派发 `事件_下载进度` | `已下载`、`总字节`、`百分比`；未知总长时百分比为 `-1` |
| 7 | 完成判定 | 模块 | 已知总长看 `COMPLETED` + 最终文件 + 无 `.crdownload`；未知总长看 3.6 秒静默 + 磁盘大小严格相等 | 文件已经可读，或还在等最后一块 |
| 8 | 派发 `事件_下载完成` | 模块 | 给出 `路径`、`结果` | `结果=0` 且 `文件是否存在 (路径)` 为真，才算真正成功 |

### 1.2 时间线

下面按“触发 → 模块动作 → 你能看到的数据”展开；每一步括号里的内容，就是这一步新出现的数据。

```text
导航/点击
  → WebView2 DownloadStarting（网址、建议文件名、总字节已知）
  → 模块派发 事件_下载开始（仅当已登记）
      ├─ 返回 真：内核 Cancel
      │     ├─ 流程 3：业务 HTTP读文件 → 写到文件 → 自己判断成败
      │     └─ 流程 4：只记录网址/文件名/总字节，不写任何文件
      │     结果：没有内核写盘、没有内核进度、没有内核完成
      └─ 返回 假 / 未登记：内核 Continue
            → 写盘到 置下载目录
            → 每 300 ms 轮询，字节变化才发 事件_下载进度（已下载/总字节/百分比）
            → 完成判定（已知总长 / 未知总长 3.6 秒静默）
            → 事件_下载完成（路径 + 结果）
```

### 1.3 三个“一句话”

- `事件_下载开始` 决定的是“**内核还下不下**”：真 = 取消内核这一份，假 = 继续。
- `事件_正在下载` 决定的是“**这一份放不放**”：真 = 放行，假 = 取消；它和 `事件_下载开始` 的返回值正好相反。
- `事件_下载进度` / `事件_下载完成` 只描述“**内核自己下的那一份**”。`事件_下载开始` 返回真之后，这两个事件不会再来。

## 2. 参数从哪里来，能拿到什么，拿不到什么

### 2.1 三个业务参数

| 参数 | 来源 | 形态与边界 |
|---|---|---|
| `网址` | `DownloadStarting` 的 URI | 通常是最终 URL，可能带查询串、重定向后的地址，也可能是 `blob:` / `data:`；离开当前页面后不一定还能访问 |
| `文件名` | 服务器 `Content-Disposition` 的建议名，取不到时由 URL 末段推导 | 可能为空、没有扩展名、带 `\` 或 `/`、带百分号编码；**拼路径前必须自己净化** |
| `总字节` | `TotalBytesToReceive` | `0` 表示“未知或大于 2GB”，不能当成 0 字节文件；大于 2GB 时进度侧会截断到 `2147483647` |

`事件_下载进度` 还有两个派生值：

- `已下载`：32 位整数，接近或超过 2GB 时可能停在 `2147483647`。
- `百分比`：`已下载 × 100 ÷ 总字节` 截断取整，最大 `100`；**总长未知时固定为 `-1`**，业务侧必须先判 `-1`，不能按 `0%` 处理。

### 2.2 拿不到的东西

`DownloadStarting` 只给 URI、建议文件名、总字节这三样业务数据。以下内容**不会**出现在事件参数里：

- 请求头、响应头；
- `Cookie`、`Authorization`；
- `Referer`；
- POST 请求体；
- 服务端最终的 `Content-Type` / `Content-Disposition` 原文。

这带来两个直接后果：

1. **外置下载器可能失败。** 把 `网址` 交给 IDM、aria2 或自己的下载队列时，如果原站点依赖登录 Cookie、一次性签名、`Referer` 防盗链，外置下载器拿到的就是 403/404/空文件。要么你自己补 `Cookie` / `Referer`（需要另外的 HTTP 组件），要么改用“同会话内核下载”（流程 1 或流程 2），让 WebView2 带着原会话去取。
2. **`HTTP读文件` 更适合公开 URL。** 它没有自定义 `Cookie` / `Referer` 的参数；能下公开文件，不等于能下登录后的文件。流程 3 的示例因此把“下载失败”也记进日志，而不是假设一定成功。

### 2.3 下载目录：`置下载目录` 到底改了什么

`mb.置下载目录 (路径)` 改的是 WebView2 profile 的 `DefaultDownloadFolderPath`（模块内部调用 `put_DefaultDownloadFolderPath`）。它有三个容易混淆的点：

- **不需要预先建目录。** 模块会写 profile 并尝试自动创建，多级目录也可以；创建失败会记录 `创建下载目录失败 rc=...`，此时先检查路径是否可写，不要假设下载一定成功。
- **空文本 = 恢复系统默认。** 传 `“”` 不是“当前目录”，而是把默认下载位置还原。
- **改目录不等于静默接管。** 只调 `置下载目录`、不登记 `事件_正在下载` 时，目录会变，但仍可能弹 Edge 默认下载 UI；要静默落盘，必须登记 `事件_正在下载` 并返回真（流程 2），或者用 `事件_下载开始` 返回真由业务自己写（流程 3/4）。

业务接管时，**写盘的是你的代码，不是模块**。所以流程 3 的 `下载\` 可以是 0 个文件，流程 4 可以不产生任何下载文件；判断成功与否要看你自己写出的目标文件，不能等 `事件_下载完成`。

> 还有一个前置条件：默认下载目录必须可写。目录不可写时，附件型导航可能在更早阶段就被静默中止，连 `事件_下载开始` 都不会触发。先保证 `置下载目录` 指向一个可写位置。

### 2.4 回调签名要对上

1.4.5 的模块 `.ec` 公开声明里，下载回调都带 `视图`、`用户数据` 两个前置参数：

| 事件 | 实际回调参数 |
|---|---|
| `事件_下载开始` | `(视图, 用户数据, 网址, 文件名, 总字节)`，返回逻辑型 |
| `事件_下载进度` | `(视图, 用户数据, 已下载, 总字节, 百分比)`，无返回值 |
| `事件_下载完成` | `(视图, 用户数据, 路径, 结果)`，无返回值 |
| `事件_正在下载` | `(视图, 用户数据, Url)`，返回逻辑型 |

本文代码按这个签名写，不提供三参数兼容写法。若回调参数个数与 `.ec` 声明不一致，运行时就可能不触发或参数错位；排查“回调不来”时，先数参数个数。

## 3. 五种流程

### 3.1 流程 1：完全不管，让内核下载

**适合**：只想显示进度、下载完提示一下；不要求静默，不要求改文件名，不要求自己接管。

```易语言
.版本 2

.程序集 窗口程序集_启动窗口

.程序集变量 mb, MB浏览框

.子程序 __启动窗口_创建完毕
    mb.绑定 (图片框1.取窗口句柄 ())
    mb.置下载目录 (取运行目录 () ＋ “\下载”)
    mb.事件_下载进度 (&处理_下载进度)
    mb.事件_下载完成 (&处理_下载完成)
    mb.载入URL (“https://example.com/file.bin”)

.子程序 处理_下载进度
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 已下载, 整数型
    .参数 总字节, 整数型
    .参数 百分比, 整数型

    .如果 (百分比 ＝ -1)
        输出调试文本 (“总长未知，已下载 ” ＋ 到文本 (已下载) ＋ “ 字节”)
    .否则
        输出调试文本 (“进度 ” ＋ 到文本 (百分比) ＋ “%（” ＋ 到文本 (已下载) ＋ “/” ＋ 到文本 (总字节) ＋ “）”)
    .如果结束

.子程序 处理_下载完成
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 路径, 文本型
    .参数 结果, 整数型

    .如果 (结果 ＝ 0)
        .如果 (文件是否存在 (路径))
            输出调试文本 (“下载成功：” ＋ 路径)
        .否则
            输出调试文本 (“结果=0 但文件不在：” ＋ 路径)
        .如果结束
    .否则
        输出调试文本 (“下载结束（结果=” ＋ 到文本 (结果) ＋ “）：” ＋ 路径)
    .如果结束
```

**实测（A 场景）**：已知总长 8 MiB，落盘 **8,388,608 B**，MD5 `dfa86a862c2c722cd6076b6e4df220e9`；38 行单调递增进度，最后一行 `8388608/8388608（100%）`；1 次完成、`结果=0`；末字节后 **0.179 秒**报完成。

**副作用**：

- 文件落在 `置下载目录` 下，文件名由服务器建议名决定；重名时由内核处理，业务侧不能改名。
- 本流程不登记 `事件_正在下载`，**不承诺静默**：仍可能出现 Edge 默认下载 UI。要静默，改用流程 2。
- 进度是 300 ms 轮询；极小文件可能只有 `0%` 和 `100%` 两帧，不是丢帧。

> A 场景的测试壳还登记了 `事件_正在下载` 并恒返回真；它只是放行，不改变“内核写盘”的结论。

### 3.2 流程 2：白名单放行 / 取消

**适合**：仍然让 WebView2 下载，但只想允许某些站点或后缀；或者要静默落到自己的目录，不想自己处理字节。

```易语言
.版本 2

.程序集 窗口程序集_启动窗口

.程序集变量 mb, MB浏览框
.程序集变量 全局_允许下载, 逻辑型

.子程序 __启动窗口_创建完毕
    mb.绑定 (图片框1.取窗口句柄 ())
    全局_允许下载 ＝ 真
    mb.置下载目录 (取运行目录 () ＋ “\下载”)
    mb.事件_正在下载 (&处理_正在下载)
    mb.事件_下载完成 (&处理_下载完成)
    mb.载入URL (“https://example.com/”)

.子程序 处理_正在下载, 逻辑型
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 Url, 文本型

    输出调试文本 (“正在下载：” ＋ Url)
    .如果 (全局_允许下载 ＝ 假)
        返回 (假)
    .如果结束
    .如果 (寻找文本 (Url, “/allowed/”, , 假) ＝ -1)
        返回 (假)
    .如果结束
    返回 (真)

.子程序 处理_下载完成
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 路径, 文本型
    .参数 结果, 整数型

    输出调试文本 (“下载完成：” ＋ 路径 ＋ “ 结果=” ＋ 到文本 (结果))
```

**返回值必须记牢**：

> **`事件_正在下载`：返回真 = 继续下载，返回假 = 取消下载。**
> 这和 `事件_下载开始` 正好相反：后者返回真 = 取消内核下载、业务接管。
> 两个事件不要套用同一个返回值习惯。

**实测**：

- 放行（`allow=1`）：同一份 512 KiB 文件落盘 **524,288 B**，进度出现 `0%` 和 `100%` 两帧，完成 1 次、`结果=0`。
- 取消（`allow=0`）：`下载\` 下 0 个文件，0 条进度，0 次完成；诊断日志写 `download cancelled by user`，下载日志停在“正在下载”这一行。
- 取消测试用的是 demo 的 `取消下载.txt` 开关，不是模块 API；真实业务把返回值接到自己的白名单/黑名单即可。

**副作用**：

- 返回假会取消这一份下载，**通常不会再有完成事件**；不要等完成来收尾。
- 页面/导航可能以 `net::ERR_ABORTED` 结束，这是取消的正常表现，不是模块崩溃。
- `置下载目录` 是全局的，不能按单次下载改目录；要单次改名/改目录，用流程 3。

### 3.3 流程 3：业务接管（重点用法一：控制位置 + 获取链接）

**适合**：要把文件放到自己的目录、按业务规则改名、自己决定是否落盘；当前交付的 A 模板就是这一种，实测见 §6.1。

```易语言
.版本 2

.程序集 窗口程序集_启动窗口

.程序集变量 mb, MB浏览框
.程序集变量 日志内容, 文本型

.子程序 __启动窗口_创建完毕
    mb.绑定 (图片框1.取窗口句柄 ())
    日志内容 ＝ “”
    记录日志 (“==== 启动（WebView2 内核，未加载 node.dll）====”)
    记录日志 (“运行目录=” ＋ 取运行目录 ())
    mb.置下载目录 (取运行目录 () ＋ “\下载”)
    mb.事件_下载开始 (&处理_下载开始)
    mb.载入URL (“https://example.com/download”)

.子程序 处理_下载开始, 逻辑型
    .参数 视图, 整数型
    .参数 用户数据, 整数型
    .参数 网址, 文本型
    .参数 文件名, 文本型
    .参数 总字节, 整数型
    .局部变量 数据, 字节集
    .局部变量 目标文件, 文本型

    记录日志 (“下载开始 ” ＋ 网址 ＋ “ → ” ＋ 文件名 ＋ “ 总字节=” ＋ 到文本 (总字节))
    记录日志 (“接管 网址=” ＋ 网址)
    记录日志 (“接管 文件名=” ＋ 文件名)
    记录日志 (“接管 总字节=” ＋ 到文本 (总字节))
    创建目录 (取运行目录 () ＋ “\用户下载”)
    数据 ＝ HTTP读文件 (网址)
    .如果 (取字节集长度 (数据) ＞ 0)
        记录日志 (“接管 用户下载 字节=” ＋ 到文本 (取字节集长度 (数据)))
        目标文件 ＝ 取运行目录 () ＋ “\用户下载\” ＋ 文件名
        .如果 (写到文件 (目标文件, 数据))
            记录日志 (“接管 已保存=” ＋ 目标文件)
        .否则
            记录日志 (“接管 写盘失败=” ＋ 目标文件)
        .如果结束
    .否则
        记录日志 (“接管 下载失败：” ＋ 网址)
    .如果结束
    返回 (真)

.子程序 记录日志
    .参数 内容, 文本型

    日志内容 ＝ 日志内容 ＋ 内容 ＋ #换行符
    写到文件 (取运行目录 () ＋ “\下载日志.txt”, 到字节集 (日志内容))
    输出调试文本 (内容)
```

**实测（早前发布版 B 场景，会写盘）**：

| 观测点 | 结果 |
|---|---|
| 业务写出的文件 | `用户下载\dl_e2e_test.bin`，**524,288 B** |
| MD5 | `09cc21fef48e9ad67608d530df98cbf5` |
| 内核目录 `下载\` | **0 个文件**（目录本身可能已被模块创建） |
| 内核进度 | **0 条** |
| 内核完成 | **0 次** |
| 诊断日志 | `download handed to user: …` |
| demo 下载日志 | 发布版 demo 在该运行目录下 8 行 / 443 B；含 `下载开始 http://127.0.0.1:18733/f.bin → dl_e2e_test.bin 总字节=524288` 和 `接管 已保存=…\用户下载\dl_e2e_test.bin`；换路径后字节数会变，行数仍是 8 |
| WebView2 导航 | `net::ERR_ABORTED`，表示内核这份下载被取消，属预期 |

**副作用与坑**：

- **同步阻塞**：上面的 `HTTP读文件` 写在 `DownloadStarting` 回调里，大文件会卡住 WebView2。生产代码应先在回调里复制 `网址`/`文件名` 到全局变量，立刻 `返回 (真)`，再把实际下载投递到线程池或自己的队列。推荐顺序是“复制参数 → 返回真 → 异步下载”，不要反过来。
- **文本指针只在回调内有效**：`网址`、`文件名` 是 GBK 编码、`NUL` 结尾的窄字符串（`char*`），回调返回后不要保存指针；要保存就当场复制成 `文本型`。
- **文件名不可信**：`文件名` 可能为空、带 `\`/`/`、是 `..`、或含非法字符。上面为了贴近 demo 直接拼接；生产代码必须净化，至少拒绝空名、`.`、`..` 和路径分隔符，再补一个默认扩展名。
- **鉴权会丢**：`HTTP读文件` 不带原页面的 Cookie/Referer，登录后的链接可能 403 或返回登录页；这时改用流程 2，让内核带会话下载。
- **没有内核进度/完成**：返回真后这两类事件不会再来；进度要自己算，成功要自己用 `文件是否存在`/字节数判断。
- **页面表现**：直接导航到附件的场景可能留下 `net::ERR_ABORTED`；这是取消内核下载的正常回报，不等于业务写盘失败。

### 3.4 流程 4：彻底拦截（重点用法二：只取链接，不落盘）

**副作用与边界**：

- **拦的是下载操作，不是网络层。** `DownloadStarting` 触发时，这次 HTTP 请求已经发出；返回真能取消 WebView2 后续的下载与落盘，但撤不回已经发出的请求。要阻止请求本身，得在更早的导航/页面层做，或者用网络拦截能力，这不是本事件的范围。
- **页面会看到失败。** 依赖下载成功回调的网页可能报错、重试或弹提示；如果页面逻辑不能接受，改用流程 3 静默写盘。
- **链接可能离开上下文就失效。** 一次性签名、Cookie、Referer、`blob:` URL 都可能让外置下载器失败；先小样本验证，再批量接。
- **没有完成事件。** 不要等 `事件_下载完成` 来判断“链接取到了”；链接在 `事件_下载开始` 返回前就已经在手里。
- **总字节可能是 0。** 这表示未知或大于 2GB，不是“空文件”；日志里要原样记录，不要用 0 做除数。

**实测（D 场景）**：

| 观测点 | 结果 |
|---|---|
| 事件里的总字节 | `总字节=0` |
| 进度行 | 17 行，全部是 `x/0（-1%）`，从 `0` 到 `262144` |
| 落盘 | **262,144 B**，MD5 `602e6d438037879b64adf74156fe3449` |

| 末字节到完成 | **4.056 秒** |

**完成判定为什么慢**：

- WebView2 对这类下载只报 `st=0`，**永远不会报 `COMPLETED`**；模块不能只等状态翻转。
- 模块用 300 ms 轮询兜底，必须同时满足：① 已下载字节连续 **3.6 秒（12 个轮询周期）**没有增长；② 磁盘文件大小**严格等于**已下载字节数。
- 所以完成时间比最后一个字节晚约 **4 秒**，D 场景实测 **4.056 秒**；这是有意为之，不是卡住。
- 服务器中途停顿 ≥3.6 秒，完成会进一步推迟，但**不会提前误报**。

**副作用**：

- 进度条只能做“不确定态”（滚动/转圈），不要按 `0%` 画，也不要用 `已下载 ÷ 总字节`（除数为 0）。
- UI 上不要显示“预计剩余时间”；总长根本不知道。
- 已知总长的下载仍走正常判据，通常在 **0.18–1.7 秒**内完成，不要把所有下载都按 4 秒等。

## 4. 决策表：先问“要不要内核写盘”

| 你的目标 | 登记哪个事件 | 返回值 | 谁写盘 | 内核进度/完成 |
|---|---|---|---|---|
| 只看进度，文件让内核下 | `事件_下载进度` + `事件_下载完成` | 无返回值 | 内核，落到 `置下载目录` | 有 |
| 白名单放行/取消，文件仍让内核下 | `事件_正在下载` | 真 = 放行；假 = 取消 | 内核（放行时） | 放行时有；取消时无 |
| 控制位置/改名，业务自己取文件 | `事件_下载开始` | **真 = 接管** | 业务 `HTTP读文件` + `写到文件` | **无** |
| 只取链接，不留下载文件 | `事件_下载开始` | **真 = 接管** | 没人写盘（也不让内核写） | **无** |
| 总长未知，仍让内核下 | `事件_下载进度` + `事件_下载完成` | 无返回值 | 内核 | 有，但完成晚约 4 秒 |

一条判断链：

```text
要不要内核把文件写下来？
  ├─ 要 → 用 事件_正在下载：真放行 / 假取消
  │        └─ 想改目录 → 先 置下载目录
  └─ 不要 → 用 事件_下载开始：返回真
           ├─ 自己写文件 → 流程 3
           └─ 只留链接   → 流程 4
```

## 5. 排错表

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 点击后没有文件 | `事件_下载开始` 返回了真，但回调里没写文件 / `HTTP读文件` 返回空 / 写盘失败 | 看 `下载日志.txt` 里的 `接管 已保存`、`接管 下载失败`、`接管 写盘失败`；`下载\` 为空在接管模式下是正常的 |
| 没有进度 | `事件_下载开始` 返回真，内核这份被取消；或只登记了完成；或文件极小只有首末帧 | 接管模式自己算进度；内核模式补登记 `事件_下载进度`；极小文件看 `0%`/`100%` 两帧 |
| 没有完成 | `事件_正在下载` 返回假取消了；目标目录不可写；未知总长还没到 3.6 秒静默；页面提前关闭 | 先确认走的是哪条分支；未知总长等约 4 秒；用 `文件是否存在 (路径)` 复核 |
| 完成来了两次 | 同一回调注册了两次；宿主/旧 DLL 重复派发；用了旧模块 | 本版实测只报一次；检查 `事件_下载完成` 是否只登记一次，确认 `MbKit146.dll` 是 763,904 B 的最终版 |
| 中文文件名乱码 | 把 GBK 文本又按 UTF-8 转了一次；或用了只接受 Unicode 的 API | 事件文本直接当普通 `文本型` 用；`写到文件` 走 ANSI；不要在中间做 `Ansi → UTF-8` |
| 编译报错“找不到 `HTTP读文件`” | 没引用“互联网支持库”（internet） | IDE → 支持库配置 → 勾选“互联网支持库”；或改用其他 HTTP 组件 |
| 日志里 `NavDone ... err=9 url=about:blank` | 附件型顶层导航结束在 `about:blank`，是导航噪声 | 不是下载失败；以 `下载开始`/`下载完成` 和磁盘文件为准 |
| `mbk_diag.log` 里中文路径是乱码 | 诊断日志的编码与查看器不一致；路径本身可能仍可用 | 不要据此判断文件没落盘；用资源管理器/`文件是否存在` 复核；这是日志显示问题，不是下载失败 |
| `事件_下载开始` 根本不触发 | 默认下载目录不可写，导航在更早阶段被中止；或回调参数个数不对，事件没挂上 | 先把 `置下载目录` 指到可写目录；再按 §2.4 核对 5 个参数 |
| 链接给外部下载器后 403/空文件 | 站点要 Cookie/Referer/一次性签名，事件里拿不到这些 | 自己补请求头；或改用流程 2，让 WebView2 带会话下载 |

## 7. 与 [`使用说明.md`](..\..\miniblink\使用说明.md) 的关系
