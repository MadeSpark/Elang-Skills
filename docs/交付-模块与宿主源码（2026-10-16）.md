## 3. 怎么用（你随便写个 dll 给宿主载入）

### 3.1 最省事的接法

在易语言里把你的工程**引用本模块**（模块路径指向 `D:\DevelopmentFolder\常用模塊\miniblink.ec`），然后：

```
.版本 2

.程序集 窗口程序集_你的窗口
.程序集变量 mb, MB浏览框

.子程序 启动你的网页界面
.参数 宿主窗口句柄, 整数型

    ' ① 先选内核 —— 必须在「碰内核之前」调，且全进程只认第一次
    '    第三参缺省=假 → 本机有 WebView2 Runtime 就走 edgewebview（推荐）
    .如果真 (WKE设置node路径 (取运行目录 () ＋ “\main\corn\node.dll”, , 假) ＝ 假)
        输出调试文本 (“内核设置失败：” ＋ WKE宿主自检 ())
        返回 ()
    .如果真结束

    ' ② 绑到宿主的承载窗口（图片框句柄）
    .如果真 (mb.绑定 (宿主窗口句柄, 假) ＝ 假)
        输出调试文本 (“绑定失败”)
        返回 ()
    .如果真结束

    ' ③ JS → 易语言 回调
    mb.JS绑定函数 (“e_notify”, &_网页回调, 3)

    ' ④ 载入页面
    mb.载入文件 (你的html全路径)
    ' 或者： mb.载入URL (“https://example.com”)
    ' 或者： mb.载入HTML (“<h1>hi</h1>”)

.子程序 _网页回调, 整数型
.参数 wkeWebView, 整数型
.参数 参数1, 文本型
.参数 参数2, 文本型
    输出调试文本 (“网页来的：” ＋ 参数1)
    返回 (0)
```

网页侧：
```html
<script>
  window.e_notify('你好', '42');     // 会进到 _网页回调
</script>
```

### 3.2 三条必须遵守的规则

1. **`WKE设置node路径` 只能在碰内核之前调一次。** 内核一旦加载就常驻进程，之后改不了（换内核只能重启宿主 exe）。这是设计行为，不是故障。
2. **业务 DLL 卸载/重载前必须调 `WKE全解绑 ()`**（或至少 `mb.销毁 ()`）。这是热重载契约：不解绑，内核手里会攥着已卸载 DLL 的函数指针。
3. **`.ec` 文件名必须是 `miniblink.ec`**，不能改名（内部模块名 = 文件名）。

### 3.3 想要「强制 node 内核」？

第三参传 `真`。但**本机那份 `main\corn\node.dll`（2021-03-29、33,600,512 B）在 `wkeCreateWebView` 里会同步死循环，把宿主 UI 线程彻底堵死**（实测 415/417 个窗口 `responsive=False`）。所以：
- 不要为了「用上 node」去传 `真`；
- 真要用 node，得先换一份新的 `node.dll`。

## 5. 排障：页面空白 / 灰屏时按这个顺序看

1. **`WKE宿主自检 ()`** —— 九成问题这一行就看出来了（内核没加载？路径不对？缺导出？）。
2. **`%TEMP%\mbkit-webview-<宿主pid>.log`** —— edgewebview 后端的一行一条诊断。正常的冷启动应该能看到这条链：
   ```
   detected WebView2 Runtime 155.x
   enable edgewebview kernel: ... slots bound 181/252
   CreateWebView view=…
   SetHandle view=… valid=1
   hidden host created on tid=…        ← 必须和下面几行同一个 tid
   EnvDone async tid=…
   ensure_ctl async tid=…              ← 缺这一行 = controller 没建，必然灰屏
   CreateCoreWebView2Controller returned hr=0x00000000
   CtlDone::Invoke hr=0x00000000 tid=…
   NavDone ok=1 err=0 url=…
   ```
3. **`WKE取内核模式 ()`** —— 期望 `2`（edgewebview）；`0` 说明内核没起来。
4. 宿主目录里 `mb_veh_<pid>.log` —— 热重载期的异常取证（VEH 探针写的）。

## 6. 两个已知坑（都会让你以为「交付坏了」，其实不是）

### 6.1 改了内核源码、也重编了模块，宿主却还在跑旧内核

`MbKit146.dll` 会被钉在旧版本上。模块虽然内嵌了内核 blob、也会比对内容后释放，
但实测有走不到那条分支的情况。**构建链跑完后必须显式覆盖两处**：
```powershell
Copy-Item src\mbkit\MbKit.dll 'D:\DevelopmentFolder\插件开发目录\E\插件\框架-爱丽\MbKit146.dll' -Force
Copy-Item src\mbkit\MbKit.dll 'out_mbkit\miniblink_源码146\资源\_常量28010234.image.dat' -Force
```
**怎么判断宿主到底加载了哪份内核**：看 `%TEMP%\mbkit-webview-<pid>.log` 里有没有
`hidden host created on tid=` / `controller released [view=…]` 这种新格式的字段；没有就是旧内核。

### 6.2 用 `ecompile` 编模块/插件时会卡在「確認另存新檔」

IDE 的 `ComDlg32\LastVisitedPidlMRU` 记住了 e.exe 的保存路径。清掉 e.exe 条目即可
（脚本：`out_mbkit\ab_test\clear_mru.py`），表现为 `status=timeout` 或 `status=failed`。

## 8. 本次交付**没有**解决的问题（别误以为已修）

1. **热重载 5 次不崩溃**：本轮实测**不稳定**（三次里两次 5/5 过、一次崩在第 3 轮后）。
   崩溃签名：`win32u.dll + 0x11cc`（新）与 `unknown + 0x7133c8b4`（昨天就有）。
   根因方向已写在 `docs\交接-WebView2黑屏与宿主置顶根因（2026-10-16）.md` 第 3.3 节：
   `WM_DESTROY` 里的 `Close()/Release()` 是**异步**投递的，宿主窗口随后就被销毁，
   Chromium 还没拆完。
2. **webui 挂久了黑屏**：已消除一个确证成因（释放不幂等，每视图 ~10 次 → 1 次），
   但没抓到黑屏瞬间现场，不排除还有别的路径。
3. **强制 node 内核**：本机 `node.dll` 在 `wkeCreateWebView` 同步死循环，不可用。
